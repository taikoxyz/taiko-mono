# 8.4 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). This file states only what the text states: each vector either follows from an enumerated condition, or reports that a requirement was violated. Where the text states a requirement but **not the consequence of violating it**, the vector says "violates <ID>" and does not name an outcome. Anything undetermined has no vector; it is listed under "Not covered" and raised in [review/8.4.md](../review/8.4.md).

`accept` means the described genesis, first block or joining-node behaviour satisfies the rules cited. Where the text names a rejection (a missing record), it is stated as such.

| Vector | Setup | Expected |
|---|---|---|
| 1.a accept | recovery uses stock CometBFT v0.40.0 with no additional authorizer and no trusted snapshot service | conforms |
