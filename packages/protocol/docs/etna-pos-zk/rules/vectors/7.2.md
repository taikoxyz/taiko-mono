# 7.2 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). This file states only what the text states: each vector either follows directly from an enumerated condition, or reports that a requirement was violated. Where the text states a requirement but **not the consequence of violating it**, the vector says "violates <ID>" and does not name an outcome — inventing one would lock in an interpretation nobody decided. Anything you cannot determine has no vector; it is listed under "Not covered" and raised in [review/7.2.md](../review/7.2.md).

`accept` means the described block or landing satisfies the rules cited. `reject` means a stated requirement is violated (the enforcement consequence is a separate question — see review Q11).

## FI-7.2-1

| Vector              | Setup                                                                                                                        | Expected                                                                                           |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 1.a accept          | `c=5`; entry 5 appears as transaction 0 of the execution block                                                               | included; `c` becomes 6                                                                            |
| 1.b reject          | `c=5`; entry 5 is due and neither included nor legally skipped, yet entry 6 is treated as the forced inclusion at position 0 | violates FI-7.2-1 ("only entry c") and FI-7.2-10; consequence - [Q7.2-11](../review/7.2.md#q72-11) |
| 1.f accept          | `c=5`; entry 5 is not due, entry 6 executes as an ordinary transaction at position 0, and entry 5's witness is supplied      | permitted: `c` stays 5, and entry 6 is not an inclusion                                            |
| 1.c reject          | `c=5`; the execution block carries two forced entries (5 and 6)                                                              | violates FI-7.2-1 ("at most one entry"); consequence — [Q7.2-11](../review/7.2.md#q72-11)          |
| 1.d accept boundary | `c=0`; no entry submitted (tail = 0)                                                                                         | block requires no forced witness; `c` stays 0                                                      |
| 1.e accept          | landing at height `h` with `c=9`                                                                                             | the Inbox head at the checkpoint equals 9                                                          |

_Landing with head ≠ `c`: no vector — [Q7.2-12](../review/7.2.md#q72-12)._
