# 5.3 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). Each vector follows from a stated reconstruction dependency, input or check, or reports that a requirement was violated. Where the text states a requirement but not the consequence of violating it, the vector says "violates <ID>". Gaps are in [review/5.3.md](../review/5.3.md).

`accept` means the described reconstruction satisfies the rule cited. `reject` means a stated input or check is contradicted.

## DATA-5.3-1

| Vector     | Setup                                                                                                            | Expected                   |
| ---------- | ---------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 1.a accept | reconstruction uses the starting state, canonical L1 transactions/events/headers and corresponding blobs         | conforms to DATA-5.3-1     |
| 1.b reject | reconstruction needs a validator-private database, complete envelopes, witnesses, signatures or a running L2 RPC | violates "depends only on" |

## DATA-5.3-2

| Vector     | Setup                                                                                  | Expected                |
| ---------- | -------------------------------------------------------------------------------------- | ----------------------- |
| 2.a accept | a source-available reconstruction program and the listed public inputs are provided    | conforms to DATA-5.3-2  |
| 2.b reject | reconstruction requires a closed-source program, or the public inputs are not provided | violates "are required" |

_Which program, version and licence satisfy "source-available": no vector — [Q5.3-1](../review/5.3.md#q53-1)._

## DATA-5.3-3

| Vector     | Setup                                                                                                                                                                                      | Expected                            |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------- |
| 3.a accept | starting material contains complete downloadable genesis allocation/state and code, content hashes, EL rule version, L1/L2 chain ids, contract addresses, L1_0, genesis hash and stateRoot | conforms to DATA-5.3-3              |
| 3.b reject | the genesis state or code is incomplete, or a listed item is missing                                                                                                                       | violates the starting-material list |
| 3.c reject | the material is downloadable but not complete                                                                                                                                              | violates "complete"                 |

_What "content hashes" hash and where each item is published: no vector — [Q5.3-2](../review/5.3.md#q53-2)._

## DATA-5.3-4

| Vector     | Setup                                                                                       | Expected               |
| ---------- | ------------------------------------------------------------------------------------------- | ---------------------- |
| 4.a accept | the program recomputes the starting point and matches it against the L1-authenticated value | conforms to DATA-5.3-4 |
| 4.b reject | the program trusts an unchecked snapshot without recomputing or matching                    | violates DATA-5.3-4    |

## DATA-5.3-5

| Vector     | Setup                                                                                                                                                                    | Expected                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| 5.a accept | in canonical L1 landing order, versioned hashes and complete `(p, h]` blobs are verified; `p` comes from proof input and actual `c` from authenticated events or records | conforms to DATA-5.3-5                                        |
| 5.b reject | `p` is taken from an unchecked source, or actual `c` from an RPC                                                                                                         | violates DATA-5.3-5                                           |
| 5.c reject | a blob is missing, or the landing order is not canonical                                                                                                                 | violates "complete ... blobs" or "canonical L1 landing order" |

## DATA-5.3-6

| Vector     | Setup                                                                                                                                                                   | Expected                                                    |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 6.a accept | the overlapping prefix is checked for EL hashes and links; only `(c, h]` is executed from authenticated `c`'s EL state; `h`'s hash, stateRoot and FI cursor are checked | conforms to DATA-5.3-6                                      |
| 6.b reject | the prefix is executed twice                                                                                                                                            | violates "do not execute the prefix twice"                  |
| 6.c reject | `h`'s hash, stateRoot or FI cursor is not checked                                                                                                                       | violates DATA-5.3-6                                         |
| 6.d reject | authentication is replaced by RPC state                                                                                                                                 | violates "do not ... replace authentication with RPC state" |

## DATA-5.3-7

| Vector     | Setup                                                                          | Expected               |
| ---------- | ------------------------------------------------------------------------------ | ---------------------- |
| 7.a accept | history is selected using authenticated generations and fixed recovery origins | conforms to DATA-5.3-7 |
| 7.b reject | history is selected from an unauthenticated L2 height or a running RPC         | violates DATA-5.3-7    |

## DATA-5.3-8

| Vector     | Setup                                                          | Expected                                                                        |
| ---------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 8.a reject | original material is missing                                   | reject (stated)                                                                 |
| 8.b reject | a version is unsupported                                       | reject (stated)                                                                 |
| 8.c reject | a hash mismatch is found                                       | reject (stated)                                                                 |
| 8.d reject | the program silently skips the prefix or substitutes RPC state | violates "do not ... silently skip it or replace authentication with RPC state" |

_This rule is a rejection list; a reconstruction that satisfies DATA-5.3-3 through DATA-5.3-7 is the accept case._

_Which versions are "unsupported", and how the program learns the supported set: no vector — [Q5.3-4](../review/5.3.md#q53-4)._

## DATA-5.3-9

| Vector     | Setup                                                                                           | Expected                                                      |
| ---------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 9.a accept | historical blobs remain retrievable; archive contents are authenticated against L1 commitments  | conforms to DATA-5.3-9                                        |
| 9.b reject | archive contents are unauthenticated, or historical blobs are unavailable                       | violates "must remain retrievable" or "must be authenticated" |
