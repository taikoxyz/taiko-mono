# 10 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). This file states only what the text states. Where the text states a requirement but **not the consequence of violating it**, the vector says "violates <ID>" and does not name an outcome. Anything undetermined has no vector; it is listed under "Not covered" and raised in [review/10.md](../review/10.md).

`accept` means the described deployment satisfies the rule cited. `reject` means a stated requirement is violated.

## START-10-1

| Vector     | Setup                                                                                                                                                                                                                                             | Expected                                                                  |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 1.a accept | Inbox proxy deployed uninitialized; its owner initializes it; the registry is deployed with that proxy address fixed; validators sign the appendix A registration digest with their consensus keys, register and wait for activation and finality | each step satisfied                                                       |
| 1.b reject | a non-owner initializes the Inbox proxy                                                                                                                                                                                                           | violates START-10-1 ("only its owner can initialize it")                  |
| 1.c reject | the registry is deployed with a different Inbox proxy address                                                                                                                                                                                     | violates START-10-1 ("deploy the registry with that proxy address fixed") |
| 1.d reject | registration is treated as final without the consensus-key signature over the appendix A digest                                                                                                                                                   | violates START-10-1                                                       |
| 1.e reject | a validator is treated as active before activation and finality                                                                                                                                                                                   | violates START-10-1 ("wait for activation and finality")                  |

_The owner identity and the ordering guarantees between the two deployments: no vector — [Q10-1](../review/10.md#q10-1)._
