# 8.3 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). This file states only what the text states: each vector either follows from an enumerated condition, or reports that a requirement was violated together with the outcome the text gives for it. Where the text states a requirement but **not the consequence of violating it**, the vector says "violates <ID>" and does not name an outcome. Anything undetermined has no vector; it is listed under "Not covered" and raised in [review/8.3.md](../review/8.3.md).

`accept` means the described call, retry or state satisfies the rules cited. `reject` means a stated requirement is violated. Section 8 says "Validate all lists and state before applying" recover's transition (RECOV-8-39), and RECOV-8.3-16 puts everything recover does "inside one recover call, and any failure reverts everything"; so a `recover` call that fails a stated condition reads `violates <ID>; recover reverts (RECOV-8.3-16)`. `invalidateRecoveryNonce` is a separate call: its conditions ("Only the Inbox owner may call", "require Inbox initialization", "require a match") are preconditions of that named call, and in Solidity terms a failed precondition reverts it, written `violates <ID>; the call reverts`. A reject that describes an implementation or storage layout departing from the rules has no call to reject and reads only "violates <ID>".

## RECOV-8.3-1

| Vector     | Setup                                     | Expected                                                                                                 |
| ---------- | ----------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 1.a accept | the Inbox owner (the DAO) calls `recover` | conforms                                                                                                 |
| 1.b reject | a non-owner calls `recover`               | violates RECOV-8.3-1 ("only the Inbox owner (the DAO) may call recover"); recover reverts (RECOV-8.3-16) |
