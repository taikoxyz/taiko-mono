# 8.3 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). This file states only what the text states: each vector either follows from an enumerated condition, or reports that a requirement was violated. Where the text states a requirement but **not the consequence of violating it**, the vector says "violates <ID>" and does not name an outcome. Anything undetermined has no vector; it is listed under "Not covered" and raised in [review/8.3.md](../review/8.3.md).

`accept` means the described call, retry or state satisfies the rules cited. Where a precondition is stated but its failure is not, the vector says "does not satisfy <ID>" rather than naming a revert.

## RECOV-8.3-1

| Vector | Setup | Expected |
|---|---|---|
| 1.a accept | the Inbox owner (the DAO) calls `recover` | conforms |
| 1.b reject | a non-owner calls `recover` | does not satisfy RECOV-8.3-1; the bullet names no failure — [Q8.3-7](../review/8.3.md#q83-7) |
