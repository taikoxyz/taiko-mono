# 6.4 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). This file states only what the text states: each vector either follows directly from an enumerated condition, or reports that a requirement was violated. Where the text states a requirement but **not the consequence of violating it**, the vector says "violates <ID>" and does not name an outcome. Anything you cannot determine has no vector; it is listed under "Not covered" and raised in [review/6.4.md](../review/6.4.md).

6.4 couples a height bound to a settlement parameter `U`. `U` is an integer committed in the config hash; `K` is the grid interval. The bound is quoted as `anchor.lastCheckpoint.height + U` below.

## BACKP-6.4-1

What enforcement exists for the bound is [Q6.4-1](../review/6.4.md#q64-1); these vectors state only the bound.

| Vector     | Setup                                                                                                                        | Expected                                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 1.a accept | anchor checkpoint height 1000, `U=3600`, L2 height 4600                                                                      | at the bound; within the rule                                                                            |
| 1.b accept | L2 height 4599                                                                                                               | within the rule                                                                                          |
| 1.c reject | L2 height 4601                                                                                                               | violates BACKP-6.4-1 ("cannot exceed"); the text's stated response is a pause, not a block-validity rule |
| 1.d reject | an L1-finality lag leaves the node's anchor checkpoint at 999 while the real checkpoint is 1000, and height 4601 is produced | violates BACKP-6.4-1 (and BACKP-6.4-12)                                                                  |

## BACKP-6.4-2

| Vector              | Setup                                                                                           | Expected                                     |
| ------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------- |
| 2.a accept          | `U=3600`, `K=3`, `U` is a multiple of `K` and inside `[K, 65536]`, committed in the config hash | conforms                                     |
| 2.b accept boundary | `U=K`                                                                                           | conforms                                     |
| 2.c accept boundary | `U=65536` and a multiple of `K`                                                                 | conforms                                     |
| 2.d reject          | `U=3601` with `K=3`                                                                             | violates BACKP-6.4-2 (not a multiple of `K`) |
| 2.e reject          | `U=65537`                                                                                       | violates BACKP-6.4-2 (above the maximum)     |
| 2.f reject          | `U=2` with `K=3`                                                                                | violates BACKP-6.4-2 (`U` below `K`)         |
| 2.g reject          | `U` is read from local node configuration instead of the config hash                            | violates BACKP-6.4-2                         |

## BACKP-6.4-3

| Vector     | Setup                                                                                                 | Expected                                                                                                                                        |
| ---------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 3.a accept | proving or landing stalls for a long time; the height reaches checkpoint+`U` and L2 pauses            | conforms (the breaker trips)                                                                                                                    |
| 3.b accept | normal operation with the unsettled count below `U`                                                   | no pause; `U` is not used as a pacing target                                                                                                    |
| 3.c reject | a deployment sizes `U` to the expected per-batch block count and treats the pause as normal operation | violates BACKP-6.4-3 ("not the pace of normal settlement")                                                                                      |
| 3.d reject | L2 pauses while proving and landing are healthy and every decided block can be proven                 | violates BACKP-6.4-3 (pause trigger is a long stall or an unprovable decided block) — the force of "should" is [Q6.4-1](../review/6.4.md#q64-1) |

## BACKP-6.4-4

| Vector     | Setup                                                           | Expected                                            |
| ---------- | --------------------------------------------------------------- | --------------------------------------------------- |
| 4.a accept | the target deployment configures `U = 3600`                     | conforms                                            |
| 4.b        | a valid deployment chooses another value allowed by BACKP-6.4-2 | conforms to 6.4 but is not the target configuration |

There is no reject case for this rule: it fixes the target value rather than prohibiting another. A deployment that chooses a different value allowed by BACKP-6.4-2 is not violating BACKP-6.4-4; it is simply not the target deployment.

| 6.a accept | `U=3600`, `L=900`                                                          | conforms                              |

## BACKP-6.4-7

| Vector     | Setup                                                                                      | Expected                                                   |
| ---------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| 7.a accept | a landing stall begins at checkpoint height `C`; blocks `C+1` through `C+U` are produced   | within the allowance                                       |
| 7.b reject | the stall produces block `C+U+1`                                                           | violates BACKP-6.4-7 ("at most U further blocks")          |
| 7.c reject | the allowance is counted from the stall's detection rather than from the anchor checkpoint | violates BACKP-6.4-7 (the allowance is `U` further blocks) |

## BACKP-6.4-8

| Vector     | Setup                                                                                   | Expected                                  |
| ---------- | --------------------------------------------------------------------------------------- | ----------------------------------------- |
| 8.a accept | the landing transaction is included on L1 but not yet finalized/adopted by a new anchor | the pause is not released                 |
| 8.b accept | the landing state finalizes and a new anchor adopts it                                  | the pause is released; the bound advances |
| 8.c reject | a node releases the pause as soon as the landing transaction is included on L1          | violates BACKP-6.4-8                      |

## BACKP-6.4-10

| Vector      | Setup                                                                                                                            | Expected                                                                     |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 10.a accept | the unsettled count is `height - anchor.lastCheckpoint.height`, the anchor is a finalized L1 block, and checkpoints only advance | conforms                                                                     |
| 10.b reject | the count uses an anchor that is not finalized                                                                                   | violates BACKP-6.4-10                                                        |
| 10.c reject | the count is computed from a checkpoint lower than one previously adopted                                                        | violates BACKP-6.4-10 ("checkpoints only advance")                           |
| 10.d reject | the count averages block intervals instead of using actual heights                                                               | violates BACKP-6.4-10 (the count is `height - anchor.lastCheckpoint.height`) |

## BACKP-6.4-11

| Vector      | Setup                                                                                               | Expected                                                                     |
| ----------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 11.a accept | after a section 8 verifier-failure rollback, accounting follows the rules shipped with that upgrade | conforms (the sole exception)                                                |
| 11.b        | the rollback's own accounting when its shipped rules are absent                                     | not determinable from 6.4; the exception is defined by the section 8 upgrade |

There is no independent reject case: the exception's content is defined by the section 8 upgrade, so 6.4 can neither confirm nor violate it.

## BACKP-6.4-13

The sentence covers both the effect of raising `U` and the pre-recovery settlement bound; the sub-labels separate them.

| Vector               | Setup                                                                                                      | Expected                                                           |
| -------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 13.a accept          | `U` is raised from 3600 to 7200; the maximum recoverable discard rises from 3600 to 7200                   | conforms                                                           |
| 13.b accept          | before recovery the DAO settles to the last provable grid point, so only unsettleable blocks are discarded | conforms                                                           |
| 13.c accept boundary | discard is unsettleable blocks plus exactly `K-1` provable blocks short of a full grid segment             | conforms                                                           |
| 13.d reject          | recovery discards `K` provable blocks beyond a full grid segment                                           | violates BACKP-6.4-13 ("at most K − 1")                            |
| 13.e reject          | recovery discards blocks that could have been settled to the last provable grid point                      | violates BACKP-6.4-13 ("only blocks that truly cannot be settled") |
