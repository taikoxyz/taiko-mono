# 3.2 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). This file asserts only what the text says: each vector follows from the cited header rule, or reports that it is contradicted. Where the text states a requirement but **not the consequence of violating it**, the row says "violates <ID>" and names no outcome. Undetermined items are under "Not covered" and in [review/3.2.md](../review/3.2.md).

`accept` means the described header satisfies the cited rule. `reject` means it does not; this file does not assume that a node necessarily rejects the block, because most rows state no consequence.

## CONS-3.2-1

| Vector     | Setup                                                                                                                                                | Expected                                                                     |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 1.a accept | every non-beneficiary field recomputed from the committed parent, the block's anchor, BFT time and chain constants matches the header field by field | conforms                                                                     |
| 1.b accept | the beneficiary differs from any value a recomputation would produce, and the header is accepted                                                     | conforms: beneficiary is the stated exception                                |
| 1.c reject | a node accepts a header whose gasLimit was chosen arbitrarily rather than derived from a chain constant                                              | violates CONS-3.2-1                                                          |
| 1.d reject | the proposer builds a header using values other than those listed, and no node recomputes them                                                       | violates "The proposer builds with these values; other nodes recompute them" |

## CONS-3.2-2

| Vector     | Setup                                                                  | Expected            |
| ---------- | ---------------------------------------------------------------------- | ------------------- |
| 2.a accept | `number = parent.number + 1` and `parentHash = parent.hash`            | conforms            |
| 2.b reject | `number = parent.number + 2`                                           | violates CONS-3.2-2 |
| 2.c reject | `number = parent.number + 1` but `parentHash` is not the parent's hash | violates CONS-3.2-2 |

## CONS-3.2-3

| Vector              | Setup                                                    | Expected                                      |
| ------------------- | -------------------------------------------------------- | --------------------------------------------- |
| 3.a accept          | `parent.timestamp + 1` is the maximum of the three terms | header timestamp equals it                    |
| 3.b accept          | `⌊BFT time⌋` is the maximum                              | header timestamp equals it                    |
| 3.c accept          | `anchor.timestamp` is the maximum                        | header timestamp equals it                    |
| 3.d accept boundary | two or three terms are equal and are the maximum         | the header uses that value (max, not max + 1) |
| 3.e reject          | header timestamp is one greater than the maximum         | violates CONS-3.2-3                           |
| 3.f reject          | header timestamp equals `parent.timestamp`               | violates the `parent.timestamp + 1` term      |

_What unit `BFT time` is floored in, and how a fractional value is obtained: no vector — [Q3.2-1](../review/3.2.md#q32-1)._

## CONS-3.2-4

| Vector     | Setup                                                                                            | Expected               |

## CONS-3.2-8

| Vector     | Setup                                                                                                  | Expected                                   |

| 8.a accept | block 1 has `baseFeePerGas = 0.025 gwei`                                                               | conforms                                   |

| 8.c reject | block 1 has `baseFeePerGas = 0.01 gwei`                                                                | violates "fixed at 0.025 gwei for block 1" |
