# 4.3 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). Each vector follows from the stated selection rule, or reports that a requirement was violated. Where the text states a requirement but not the consequence of violating it, the vector says "violates <ID>"; the consequence is a separate question. Gaps are in [review/4.3.md](../review/4.3.md).

`accept` means the described derivation satisfies the rule cited. `reject` means a stated condition is violated; where the text says "reject the derivation", the vector says so.

## COMM-4.3-1

| Vector     | Setup                                                                                                                                               | Expected                                                                      |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 1.a accept | committee 0, an ordinary rotation and a recovery each derive from their own authenticated snapshot using the same eligibility, sort and power rules | conforms to COMM-4.3-1                                                        |
| 1.b reject | recovery carries over an earlier committee's members or powers instead of applying the rule to R                                                    | violates COMM-4.3-1                                                           |
| 1.c accept | an entry with high past voting power but low current `effStake` is not favored                                                                      | conforms ("independently of previous voting powers or participation history") |
