The five distinctions, in one place

Almost every confused argument about rollups comes from collapsing these five questions into one. The course keeps them apart at every step.

QuestionWho answers itWhat it does NOT tell you
Is this block execution-valid?Anyone who re-executes itWhether anyone else agrees, or whether you can still get the data tomorrow
Is it agreed by consensus?The L2 validator set (PoS)Whether the state transition was computed correctly by everyone
Is the data available?Whoever holds and serves it, until it lands on L1Whether the block is final, or whether a proof exists
Is anyone economically accountable?Stake and slashing rulesWhether you personally will be compensated
Is it settled on Ethereum?An L1 transaction containing data and a valid proofWhether L2 will keep producing blocks afterwards
Self-check: which of the five is missing when a user says “my transaction is confirmed but my withdrawal is stuck”?

Availability and settlement. The transaction was included and probably agreed by L2 consensus, but a withdrawal requires the batch to reach STATUS-06 — accepted on L1 — which needs the data and a valid proof in the same L1 transaction.

Where the assumptions live

Every lesson ends with a “challenge this” box naming the assumptions the lesson used. The full list is in the specification's liveness statement and in 01 — requirements and threat model. The short version: fewer than one third of stake is malicious, enough validators are online and timely, somebody keeps the data until the proof lands, at least one prover finishes the job, and Ethereum keeps working.
