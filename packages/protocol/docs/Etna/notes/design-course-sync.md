# Keeping the learning course aligned with the design

The engineering reference owns proposed protocol rules. The learning course explains the same candidate with fewer concepts per lesson; it must not promise stronger guarantees, omit material limits or silently use different constants. This is a **manual publication checklist and dependency map**, not an automated guarantee of semantic consistency, a build step or a protocol authority.

The [current requirement ledger](../README.md#requirement-ledger), [launch evidence dashboard](../design/assurance.html) and [comment dispositions](pr-comment-dispositions.md) control present-day status. Historical review records retain their original snapshots and verdicts. A clean historical review is not an excuse to leave current teaching material outdated. Live GitHub comments can change or disappear; local rules and dated, version-pinned analysis remain authoritative. Exact fixture outputs remain provisional until durable independent reproduction; a lesson must never promote them above their owning encoding formulas.

## Publication checklist for every design update

1. **Identify the changed claim.** Record the starting commit, changed rule/constant/interface/argument and owning reference section. Classify the change as mechanism, parameter, client behavior, new evidence or presentation. Do not describe a changed consensus rule as editorial.
2. **Select every affected row above.** Include downstream examples and the final assembly. Record an explicit reason for “not affected”; a blank row is not evidence of review. Add a row when a new mechanism has no teaching dependency yet.
3. **Update reference and teaching material together.** Check prose, numbers, diagrams/captions, hidden answers and challenge boxes. Keep prerequisite order and the existing problem/mechanism/example/attack/self-check structure. Do not teach the whole design early just to mention a new caveat.
4. **Reconcile status everywhere.** Check the README ledger, all top-level design pages, arguments, dashboard, course index, all lesson banners and final assembly. Scope old review results to their immutable inputs; record a current addendum instead of rewriting old reports. Open items remain open until the specified evidence or mechanism exists. Refresh PR feedback before publication, record the latest observed update/cutoff and preserve substantive dispositions locally even if a live source disappears.
5. **Check exact technical repetitions.** Recompute numeric examples from the owning formula. Search the documentation for the old constant, selector or guarantee, including SVG text and answer blocks. Retain historical values only where clearly identified as historical. Formatting edits must preserve preformatted code, text meaning and SVG geometry.
6. **Validate the artifacts.** Check local paths and fragments, unique IDs, HTML parsing, no external runtime assets/scripts, native answer expansion, desktop/mobile widths and readable scrolling diagrams. Confirm no edits outside the authorized Etna directory. Use the manual recipe and record commands/checks and observed results in [validation](../validation.md); site checks do not measure protocol gas or security. The session's throwaway-checking code is not a committed validator or CI artifact. State that reproducibility limit instead of implying that numeric page counts are permanent or independently certified.
7. **Perform a separate consistency read.** A reader compares the affected reference and lessons, including the assembly, against the actual final diff. Document unresolved mismatches. Publication may call the sites synchronized only after this check; otherwise place a visible pending notice on affected lessons and state the limitation.
8. **Commit one coherent result.** Link the review/change record and validation evidence. A substantive mechanism change needs corresponding security analysis; successful teaching updates do not inherit old convergence. This checklist requires human or agent judgment and cannot guarantee future semantic consistency automatically.
