## Missed facts

- **Codeless remote verifier = accept-all.** `Risc0Verifier` and `SP1Verifier` only check `success` of a `staticcall`; a `staticcall` to an address with no code returns `success = true`, so if `riscoGroth16Verifier`/`sp1RemoteVerifier` were ever an EOA, self-destructed, or a wrong address, every proof with trusted ids would pass. The constructors check only `!= address(0)`, not `code.length`. — Risc0Verifier.sol:33,77-80; SP1Verifier.sol:34,76-83
- **Owner bypass of the validity delay (G8a) is unreachable on a registrar-gated deployment unless owner == registrar.** `registerInstance` first requires `registrar == 0 || msg.sender == registrar` (:319), and only then applies `msg.sender == owner()` (:455). With mainnet params (owner = DAO controller, registrar = admin.taiko.eth) the owner cannot call `registerInstance` at all; every mainnet registration via this path carries the 24h delay. — SgxVerifier.sol:319,455; DeployHackRecoveryContracts.s.sol:86-89
- **Registration depends on a fee-less attestation entrypoint.** `registerInstance` is non-payable and forwards `{value: 0}` to the `payable` `verifyAndAttestOnChain`; if the (upgradeable, DAO-owned) entrypoint ever enables a fee (`AutomataDcapAttestationFee`), SGX registration bricks. — SgxVerifier.sol:332-335; IDcapAttestation.sol:6,23-26
- **Deleted instances can never re-register with the same key.** `deleteInstances` only `delete instances[idx]` and never clears `addressRegistered`, so `_addInstances` rejects that address forever (`SGX_ALREADY_ATTESTED`). Instance ids are never reused either. — SgxVerifier.sol:245,569-571,587
- **`proposalAge` is computed inside `unchecked` from prover-supplied data.** `block.timestamp - commitment.transitions[offset].timestamp` sits inside the `unchecked {` block opened at :322; a future-dated `timestamp` wraps to a huge value rather than reverting. The Inbox itself never validates `transitions[].timestamp`; it is only bound by the proof.
