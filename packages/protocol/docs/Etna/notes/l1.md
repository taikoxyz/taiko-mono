# Phase 1: current L1 contracts

Baseline: repository commit `961bbd8ff55a0f66f44ad04160eb51638d655b66`, inspected 2026-09-30. This is a source review, not a verification of deployed bytecode or current on-chain configuration. Paths and line numbers below refer to this commit. **Proven** means established by source inspection or the stated deduction; **assumed** marks an external security premise; **open** marks information not established here. No Etna mechanism is designed in this note. URC: **removed in Etna**.

## Overview

**Proven:** the current core is the Shasta-style `Inbox`, with separate blob-backed proposal and proof transactions. It deliberately uses a different inbox address from Pacaya (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:24–34`). `propose(bytes,bytes)` records a hash-linked proposal containing derivation sources; it does not receive or verify an execution proof (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:270–289,577–623`). `prove(bytes,bytes)` accepts a proof covering a contiguous range of already proposed proposals, advances the proven head and saves a checkpoint in the same transaction (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:321–399`). This current path does **not** use the contest/dispute-tier state machine described by older Taiko documents: the proof-verifier interface has only `(proposalAge, commitmentHash, proof)` and reverts on invalidity (`packages/protocol/contracts/layer1/verifiers/IProofVerifier.sol:7–24`).

**Proven:** a proposal is metadata and one or more blob derivation sources, not an individual L2 block. Its fields include proposal ID, L1 acceptance timestamp, submission-window end, proposer, parent proposal hash, origin L1 block number/hash, basefee-sharing percentage and sources (`packages/protocol/contracts/layer1/core/iface/IInbox.sol:51–79`). Each proof commitment includes the first proposal ID and parent L2 block hash, last proposal hash, actual prover, final L2 block number and state root, and a transition per proposal (`packages/protocol/contracts/layer1/core/iface/IInbox.sol:111–144`). A transition contains only proposer, timestamp and end-block hash; the compact codec uses 58 bytes (20 + 6 + 32), not a per-L2-block proof object (`packages/protocol/contracts/layer1/core/libs/LibTransitionCodec.sol:10–34`).

**Proven:** mainnet source configuration currently sets minimum and liveness bonds to zero, a four-hour proving window, a seven-day withdrawal delay and a 75% basefee share (`packages/protocol/contracts/layer1/mainnet/MainnetInbox.sol:24–52`). The Unzen deployment script wires the bond token to `LibL1Addrs.TAIKO_TOKEN`, and wires both proposer and prover whitelists (`packages/protocol/script/layer1/mainnet/DeployUnzenContracts.s.sol:61–68`). These are source/deployment-script facts; live values remain **open** until independently queried.

## Propose / prove / finalize state flow

1. **Activation.** Owner supplies a nonzero last-Pacaya block hash; repeat activation is permitted within two hours. Initial next proposal is 1, last proposal block is 1, finalized timestamp is current time and finalized hash is the supplied hash (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:185–200`; `packages/protocol/contracts/layer1/core/libs/LibInboxSetup.sol:17–20,54–88`). Correct migration head is an **assumption** of this owner-supplied activation.
2. **Proposal input.** Decode deadline, blob reference and number of forced inclusions. Nonzero deadline must not have elapsed (`packages/protocol/contracts/layer1/core/iface/IInbox.sol:99–109`; `packages/protocol/contracts/layer1/core/impl/Inbox.sol:270–278,764–765`).
3. **Capacity and sequence.** At most one proposal per L1 block. Require `ringBufferSize > nextProposalId - lastFinalizedProposalId`; this reserves a ring entry and halts new proposals before overwriting needed unfinalized history (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:588–593`).
4. **DA and authorization.** Dequeue requested FIFO forced sources, requiring all due entries among the first ten. Append a normal source referencing blobs of the current transaction. Invoke proposer checker unconditionally; if minimum bond is positive require active, sufficiently funded bond (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:595–607,637–673`; `packages/protocol/contracts/layer1/core/libs/LibBlobs.sol:37–54`).
5. **Commit proposal.** Origin is the previous L1 block so `blockhash` is available. Hash full ABI-encoded proposal; store at `id % ringBufferSize`; increment next ID, record L1 block number, emit `Proposed` (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:284–289,609–628,746–755`; `packages/protocol/contracts/layer1/core/libs/LibHashOptimized.sol:18–27`). Execution happens off-chain under derivation/proof rules; proposal acceptance alone does not certify execution.
6. **Proof bounds.** Proof may overlap finalized history but must advance at least one proposal, cannot leave a gap from current finalized head, and cannot prove an unproposed ID (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:788–811`). This tolerates some overlapping proof races; a completely stale proof reverts with `LastProposalAlreadyFinalized`.
7. **Proof continuity.** Select the proof transition before the first newly finalized proposal, or `firstProposalParentBlockHash` for no overlap; require equality to stored finalized L2 hash. Require last proposal hash equal ring-buffer hash (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:342–351`). The circuit must link intermediate transitions to the hash-linked proposal chain and execution: Solidity checks the terminal proposal hash, not every proposal's full metadata (**assumed** proof-program correctness; input binding is **proven** by `packages/protocol/contracts/layer1/core/libs/LibHashOptimized.sol:32–82`).
8. **Bond and checkpoint.** If no effective prover whitelist, late proof debits first newly finalized proposal's proposer and credits `actualProver`. Save `{blockNumber: endBlockNumber, stateRoot: endStateRoot, blockHash: last transition.blockHash}` to `SignalService.saveCheckpoint`; update finalized head and timestamps; emit `Proved` (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:353–387,729–742`). This is the exact current L1 rollup-to-SignalService interface.
9. **Verifier.** Invoke configured `verifyProof(age, hashCommitment, proof)`; age is real age only for exactly one newly finalized proposal, otherwise zero. Although called after writes, verifier failure reverts the entire transaction, including checkpoint writes and bond ledger changes, under **assumed Ethereum atomic transaction execution** (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:389–398`). Thus no separate finalization transaction or challenge delay exists in this path.
10. **L1 finality.** `lastFinalizedProposalId` denotes successful contract proof verification, not Ethereum CL finality. Checkpoints and events remain reorgable with their containing L1 block. This distinction follows from ordinary contract writes at `packages/protocol/contracts/layer1/core/impl/Inbox.sol:364–380`; Ethereum finality is an **assumption external to these contracts**.

## Whitelist guarantees and permissionless replacement obligations

### Preconf whitelist

**Proven guarantee:** at a given consistent L1 state and period timestamp, deterministic selection chooses at most one eligible proposer. Owner-curated entries link an on-chain proposer to an off-chain sequencer. Two-period activation avoids changes from additions in the current period; immediate removals can change the candidate set immediately. Selection is `beaconRoot % activeCount`, with delayed EIP-4788 root lookup (`packages/protocol/contracts/layer1/preconf/impl/PreconfWhitelist.sol:42–54,126–150,203–265,275–313`). Missing root lookup can return zero and `_getRandomNumber` does not reject it, so zero is also a deterministic selection seed (`packages/protocol/contracts/layer1/preconf/libs/LibPreconfUtils.sol:23–38`; `packages/protocol/contracts/layer1/preconf/impl/PreconfWhitelist.sol:309–313`). This is deterministic coordination, **not a proven unbiased or manipulation-resistant lottery**.

**Assumed guarantee:** the owner/ejecter chooses reliable and independently operated participants and removes misbehavior. There is no stake-based or evidence-based qualification in `addOperator` / `removeOperator`; no on-chain punishment for withholding appears here (`packages/protocol/contracts/layer1/preconf/impl/PreconfWhitelist.sol:94–109,207–265`). Entry count is uint8, so membership is inherently bounded, not an unbounded open registry (`packages/protocol/contracts/layer1/preconf/impl/PreconfWhitelist.sol:54,219–223`).

Replacement obligations: establish public sequencing rights and sequencer-key authorization without curated membership; make membership/state changes locally interpretable; replace trusted ejection with objectively enforceable fault/recovery rules; define behavior for zero healthy sequencers; remove all 12-second/32-slot dependencies; evaluate randomness bias and Sybil resistance explicitly. These are consequences of R1/R5/R6 and the source guarantees, not an Etna design.

### Prover whitelist

**Proven guarantee:** while count is nonzero, only curated sender addresses can cause checkpoints to be finalized. It is an extra barrier independent of proof validity, and disabling it is possible by zero address or zero member count (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:771–778`). Membership does not prove computational ability or prove that `actualProver == msg.sender`; the latter is merely a committed payout identity (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:729–742`; `packages/protocol/contracts/layer1/core/iface/IInbox.sol:130–131`). The whitelist causes liveness-bond processing to be skipped (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:356–359`).

**Assumed guarantee:** curation reduces the chance that an attacker with compromised proving technology or a proving-program exploit can submit a harmful proof before privileged intervention. It does not establish cryptographic soundness or ensure continued proving if members stop. Replacement obligations: permissionless verification must rely on correctly bound proof statements and audited verification rules; capacity/reward mechanisms must incentivize recovery; remove off-chain authorization and operational revocation dependence. Current owner's trusted program-key setters and SGX allowlists must also be considered under “no whitelist of any kind,” not only the two named whitelist contracts (`packages/protocol/contracts/layer1/verifiers/SP1Verifier.sol:41–46`; `packages/protocol/contracts/layer1/verifiers/Risc0Verifier.sol:40–45`; `packages/protocol/contracts/layer1/verifiers/SgxVerifier.sol:249–319`).

## Forced inclusion and data availability constraints

**Proven:** both ordinary proposal and forced-inclusion references are current-transaction blobs: `blobhash(startIndex+i)` must be nonzero, and at least one blob is required (`packages/protocol/contracts/layer1/core/libs/LibBlobs.sol:34–54`). No calldata DA path exists in the current `ProposeInput`/`ForcedInclusion` interface (`packages/protocol/contracts/layer1/core/iface/IInbox.sol:99–109`; `packages/protocol/contracts/layer1/core/iface/IForcedInclusionStore.sol:9–24`). Offset meaning is described inconsistently as field-element offset vs byte offset in `LibBlobs.sol:15–25`; downstream derivation is needed to settle precise encoding.

**Proven:** forced inclusion is FIFO and limited to one blob per entry; the “one L2 block” restriction is explicitly delegated to nodes/provers, not enforced by the L1 storage library (`packages/protocol/contracts/layer1/core/libs/LibForcedInclusion.sol:9–15,51–64`). Up to ten queue heads are inspected for due status, and a successful proposal must request at least that many; proposer may consume earlier than due. Due status does not itself grant proposing rights (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:650–667,601–603`). Execution validity and actual user transaction inclusion remain a derivation/proof-program question, not a claim that every arbitrary malformed submitted transaction executes.

**Proven:** queue data can outlive blob availability. The owner's `init3` hook documents a real repository-described need to void entries queued during disabled forced inclusion because blobs expired, leaving their fees in the contract (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:246–257`). **Open:** independently verify incident and on-chain recovery history before treating comments as external fact. **Assumed:** ordinary DA retention relies on Ethereum blob availability plus node archival, not eternal on-chain payload bytes.

## Withholding exposure

**Proven scope boundary:** L1 proposal checks do not require a preconfirmation signature, gossip receipt, availability certificate, or prior published preconf commitment; they authorize the proposer and reference current-transaction blobs (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:577–623`). A selected proposer can therefore privately build a batch and first reveal its data through the L1 blob transaction. Valid proof guarantees execution according to derivation and program rules, not that the batch was gossiped in time. No preconf data-withholding challenge is present in this source surface; current preconfer's checker explicitly says whitelist slashing is disabled (`packages/protocol/contracts/layer1/preconf/impl/PreconfWhitelist.sol:139–140`).

**Concrete current exposure:** an authorized proposer privately executes transactions, withholds P2P payloads, then submits its privately selected valid data via blobs. Off-chain participants building/proving on an assumed public tail may need to discard work or reorg to the L1-derived chain. Whether and when today's clients accept that tail is **open to the client review**; the L1 contracts alone do not prevent the trace. A private signature is neither visible nor slashable here. A malformed proof reverts; an execution-valid but previously withheld batch is not rejected for withholding.

**Proven limitation:** the generic late-proof penalty, where enabled, penalizes missing a public L1 timestamp deadline, not missing P2P gossip. It only processes the first new proposal per successful proof, and is disabled when prover whitelist is nonempty (`packages/protocol/contracts/layer1/core/impl/Inbox.sol:356–359,729–742`). Mainnet source additionally sets liveness bond to zero (`packages/protocol/contracts/layer1/mainnet/MainnetInbox.sol:37–38`). Trusted ejection may respond to observations, but requires no L1-verifiable evidence (`packages/protocol/contracts/layer1/preconf/impl/PreconfWhitelist.sol:98–109`).

**Fundamental observation (proven by indistinguishability):** absent a timed public obligation, an L1 contract cannot distinguish “the sender never gossiped bytes” from “bytes were sent but a recipient/network failed.” Objective timeout/default penalties can certify failure of an agreed on-chain response, not global nonpublication itself. Any replacement must name synchrony, data propagation, honest responder/witness and L1 inclusion assumptions, then account for honest timeout failures and selective-disclosure evasion. This is a research obligation, not a current-system property.
