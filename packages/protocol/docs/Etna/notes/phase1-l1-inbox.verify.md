## Missed facts

- `init(address _owner) external initializer` (`Inbox.sol:181-183`) is an entrypoint the gate table omits: it is guarded only by OZ `initializer`, so whoever calls it first on a fresh proxy becomes owner. Standard UUPS pattern, but it belongs in any roles table. — `contracts/layer1/core/impl/Inbox.sol:181-183`
- Ordering inside `_buildProposal`: forced inclusions are dequeued and their ETH fees sent to `msg.sender` (`:595-596` -> `:710 _feeRecipient.sendEtherAndVerify(totalFees * 1 gwei)`) and the caller's blob is validated (`:598-599`) *before* the proposer gate `checkProposer` runs (`:602-603`). An unauthorized caller therefore triggers an external ETH call to itself before being rejected; safe only because the whole tx reverts and `nonReentrant` is held. `sendEtherAndVerify(addr, amt)` forwards `gasleft()` (`contracts/shared/libs/LibAddress.sol:60-61`), so the fee recipient gets a full-gas callback while the reentry lock is set. — `Inbox.sol:595-603`, `:710`
- The vestigial permissionless-proposing hook is still computed and thrown away: `_dequeueAndProcessForcedInclusions` returns `oldestTimestamp_` (`:683-684`, `:713`) and `_consumeForcedInclusions` discards it with `(, head) = ...` (`:671`); the `ConsumptionResult` NatSpec still says "and whether permissionless proposals are allowed" (`:635-636`). This is where `permissionlessInclusionMultiplier` was meant to plug in. — `Inbox.sol:635-636`, `:671`, `:683-684`, `:713`
- `proposalAge = block.timestamp - commitment.transitions[offset].timestamp` (`:336`) is computed inside `unchecked` (`:322`) from a prover-supplied timestamp; a future timestamp underflows to ~2^256 and that value is forwarded to `verifyProof` for single-proposal proofs (`:395`). Harmless today because every verifier ignores the argument, but a designer adding age-based verifier logic must bound it. — `Inbox.sol:322`, `:336`, `:395`
- `IProposerChecker.checkProposer` is declared non-view (`external returns (uint48)`, `contracts/layer1/core/iface/IProposerChecker.sol:16-21`), so a proposer checker is allowed to mutate state during `propose` (a lookahead/URC-style checker would). `PreconfWhitelist` happens to implement it as `view` (`PreconfWhitelist.sol:127-132`). `IProverWhitelist.isProverWhitelisted` is `view` (`IProverWhitelist.sol:12-15`). — `IProposerChecker.sol:16-21`
- `init2`'s NatSpec says the chosen finalized proposal "must still be anchored in the current ring buffer" (`Inbox.sol:214-215`), but the code only checks arithmetic bounds (`:227-233`); it never checks `_proposalHashes[id % ring] != 0` nor that `_lastFinalizedBlockHash` corresponds to it. The owner is fully trusted here. — `Inbox.sol:214-215`, `:227-233`
- `LibInboxSetup.validateConfig`/`activate` and `LibForcedInclusion.saveForcedInclusion`/`getCurrentForcedInclusionFee` are `public` library functions (`LibInboxSetup.sol:9-10` "forces external linking", `:24`, `:54`; `LibForcedInclusion.sol:42-48`, `:75-80`), i.e. the Inbox implementation DELEGATECALLs into separately deployed, linked library contracts.
