## Missed facts

- Operator activation wall-time is 385–768 s (1–2 epochs), not 2–3 epochs (see §4.6 correction) — `layer1/preconf/impl/PreconfWhitelist.sol:176-179,218`
- The next-epoch NatSpec is stale too: `getOperatorForNextEpoch` "uses the beacon block root of the first block in the current epoch", but code uses `(E+1) − 2 epochs = E−1` — `layer1/preconf/iface/IPreconfWhitelist.sol:45-46` vs `layer1/preconf/impl/PreconfWhitelist.sol:150,279-281`
- All epoch timestamps are truncated to `uint32` (`epochStartTimestamp` casts, `OperatorInfo.activeSince` is `uint32`) and `getEpochTimestamp` uses checked `block.timestamp - genesisTimestamp`, so it reverts on any chain whose `block.timestamp < genesis` — `layer1/preconf/impl/PreconfWhitelist.sol:16,176-179`, `layer1/preconf/libs/LibPreconfUtils.sol:67`
- `latestActivationEpoch` is only ever raised (on add) and never lowered on removal, so removing a still-pending operator leaves the slow (O(n) scan) path in force until that future epoch passes; `_hasAnotherActiveOperator` and the slow path are both linear in `operatorCount` — `layer1/preconf/impl/PreconfWhitelist.sol:228,237-266,194-199,296-303`
- Existence checks differ: `_addOperator` treats "present" as `activeSince != 0`, `_removeOperator` as `sequencerAddress != 0`; `removeOperator(index)` additionally requires `index < operatorCount` — `layer1/preconf/impl/PreconfWhitelist.sol:101,214,241`
- `saveForcedInclusion` is `payable` but **not** `nonReentrant`; the refund is sent with `sendEtherAndVerify` using all remaining gas (`gasleft()`) after the queue write, so re-entry is harmless but a contract caller that cannot receive ETH must pay the exact fee — `layer1/core/impl/Inbox.sol:431-442`, `shared/libs/LibAddress.sol:52-62`
- Forced-inclusion fee payout also uses `sendEtherAndVerify` with `gasleft()` and reverts the entire `propose` if `msg.sender` (the proposer) rejects ETH; a contract-based proposer under a permissionless design must accept plain ETH — `layer1/core/impl/Inbox.sol:710`, `shared/libs/LibAddress.sol:60-61`
- The fee paid to the consuming proposer is the fee recorded at save time (`feeInGwei`), not the fee current at consumption — `layer1/core/impl/Inbox.sol:706`, `layer1/core/libs/LibForcedInclusion.sol:61`
- `_consumeForcedInclusions` also `break`s on a zero `blobSlice.timestamp` (defensive; cannot occur for stored entries since `validateBlobReference` always sets `block.timestamp`) — `layer1/core/impl/Inbox.sol:656`, `layer1/core/libs/LibBlobs.sol:53`
- `IForcedInclusionStore` NatSpec fee examples use `threshold = 100`, `baseFee = 0.01 ETH`; mainnet is `50` / `0.001 ETH`, so the doc examples do not describe production — `layer1/core/iface/IForcedInclusionStore.sol:29-34` vs `layer1/mainnet/MainnetInbox.sol:48-49`
- `getCurrentForcedInclusionFee` reverts with `InvalidFeeDoubleThreshold` when threshold is 0 (redundant with constructor validation, but it means the view can revert) — `layer1/core/libs/LibForcedInclusion.sol:84`, `layer1/core/libs/LibInboxSetup.sol:38-40`
- Config validation also requires non-zero `proofVerifier`, `signalService`, `provingWindow`, `ringBufferSize >= 2` and `basefeeSharingPctg <= 100`; the summary lists only four of the nine checks — `layer1/core/libs/LibInboxSetup.sol:26,28,30,35,36`
- `ProverWhitelist.init(address(0))` / `PreconfWhitelist.init(address(0))` make `msg.sender` the owner (`EssentialContract.__Essential_init`), which is how the deploy script whitelists the first prover before the two-step transfer to the DAO — `shared/common/EssentialContract.sol:193-197`, `script/layer1/core/DeployShastaContracts.s.sol:98-110`

- `LibBonds.deposit` credits the ledger before `safeTransferFrom` (credit-then-pull); safe only because every Inbox entry point is `nonReentrant` — `layer1/core/libs/LibBonds.sol:47-51`, `layer1/core/impl/Inbox.sol:403-410`
- EIP-4788 only retains ~8191 roots (~27 h); `_getOperatorForEpoch` is only ever called for the current and next epoch (768 s look-back), so this is fine today, but a successor that recomputes historical assignments on-chain cannot rely on `getBeaconBlockRootAt` for older epochs — `layer1/preconf/libs/LibPreconfUtils.sol:44-51`, `layer1/preconf/impl/PreconfWhitelist.sol:144-151`
- Interface-level `nonReentrant` in `EssentialContract` uses transient storage (EIP-1153) and is not virtual — `shared/common/EssentialContract.sol:211-213`

## Overall

The summary is safe to rely on for the things a protocol designer would build on: every access gate (owner / ejecter / ejector-manager / prover-manager / `checkProposer` on `msg.sender` / `_checkProver` on `msg.sender`), every timing constant and mainnet parameter, the forced-inclusion due/consume arithmetic, the bond ledger state machine, the "nothing is enforced" status of `permissionlessProvingDelay` and `permissionlessInclusionMultiplier`, and the storage slots were all confirmed verbatim, and its interface signatures match the code. The one substantive error is the §4.6 statement that a newly added operator waits "2–3 epochs (768–1152 s)": the code activates at the start of epoch `E+2`, so the wait is 1–2 epochs (385–768 s); readers reasoning about onboarding latency or lookahead stability should use the corrected figure. The three imprecisions are cosmetic (a mis-cited line in §4.5, an off-by-one in the beacon-root probe count in C62, and two extra layout files in `layer2/core` for C19). Readers should additionally re-check the missed facts above that matter for a permissionless successor: `checkProposer` is non-view at the interface level (the checker may hold state), forced-inclusion payouts and refunds require the recipient to accept ETH with full gas, and `saveForcedInclusion` is the only value-bearing entry point without `nonReentrant`.
