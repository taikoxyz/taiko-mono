# Anchor transaction removal — design decision, 2026-10-01

Status: mechanism selected for integration and fresh rounds 07–08. The prior rounds 05–06 verdict applies to the earlier specification, not automatically to this revision. No production implementation or deployment is authorized by this document.

## Source and scope

The user requested adoption of David's [issue #22147](https://github.com/taikoxyz/taiko-mono/issues/22147#issue-5516275880), retrieved together with all seven comments on 2026-10-01. The [correction comment](https://github.com/taikoxyz/taiko-mono/issues/22147#issuecomment-5756503026) and [final direction](https://github.com/taikoxyz/taiko-mono/issues/22147#issuecomment-5756531478) control interpretation: keep strictly standard EIP-4788, accept loss of automatic Anchor storage updates, disable the old writer before the first new block, and do not describe the entire EVM as standard. The issue's earlier state-root variant is withdrawn; its 40k reveal-gas and unconditional 4.5-hour retention claims are superseded. Its cited deployment/client observations are historical author reports, not freshly authenticated deployment facts.

**Assumed design choice:** adopt block hash plus reveal. No custom pre-execution hook, new system caller, anchor transaction, fixed-k signing, fee exemption, transaction-zero reservation or anchor gas reserve. Keep the standard EIP-4788 and EIP-2935 calls, with their actual state effects in execution/proofs and ordinary upstream gas/receipt semantics. Existing Taiko fee allocation and other listed Etna execution overrides remain.

## Selected mechanism

- Every Etna L2 header has parentBeaconBlockRoot equal to its segment's authenticated nonzero L1 execution-block hash. Local preconfirmation validation checks exact equality in its named L1 view; mere nonzero is insufficient. Standard EIP-4788 records that word. It is an execution hash on Etna, not a beacon SSZ root or randomness.
- Keep the existing L2 SignalService. Add ordinary permissionless pinCurrentOrigin(), which reads the canonical EIP-4788 contract at block.timestamp and permanently records that nonzero hash in one namespaced mapping. Add revealCheckpoint(uint64 l2Timestamp, bytes l1HeaderRlp): timestamp >0 authenticates against the temporary ring; timestamp=0 authenticates against the permanent pin map. Decode the full strict hash-bound header into the unchanged uint48 number/hash/stateRoot checkpoint. Matching existing checkpoints are idempotent; conflicts and zero roots fail.
- The temporary ring has 8191 entries indexed by timestamp modulo8191; the safe no-collision interval is less than8191 seconds of L2 timestamp advancement, not8191 arbitrary blocks. Pinning removes that deadline for a chosen recorded hash. A forced pin transaction has fixed four-byte calldata and selects the processing block's origin, so long queue delay cannot make its timestamp stale. A later pinned reveal has no expiry.
- Set the common L1 header/reveal cap to1536 bytes (formerly4096), at most32 scalar fields. All accepted origins therefore have a header preimage small enough for a forced reveal. With empty access list, zero value, <=1M gas and the stated type-2 integer widths, reveal raw transaction size is at most1845 bytes, within the existing2048-byte FIFO bound. Future headers exceeding the cap require a reviewed upgrade before use. This is a parser/resource limit, not a gas benchmark.
- Pin/reveal callers pay ordinary ETH transaction fees; no new reward, bond, exclusive relayer or slashing role. Fraudulent calls revert. Any address can enter or stop without affecting stored pins/checkpoints. Canonical progress does not require a pin or reveal in every block. Existing bridge-proof payload/gas limits remain explicit; the pin/reveal construction alone does not make arbitrary-size bridge proofs fit the forced queue.

## Migration and bootstrap

**Assumed rule:** before sealing the legacy parent, verify build/import/prover parity, deploy the exact canonical EIP-4788/2935 contracts, and install fail-closed transitional contracts at the existing Anchor/SignalService proxies. Canonical contract runtime code hashes and all retained layouts belong to the authenticated migration manifest/certificate.

Legacy header rules require parentBeaconBlockRoot=0. Legacy Anchor entrypoints and L2 SignalService.saveCheckpoint permit their old provenance only when the canonical current-timestamp EIP-4788 lookup succeeds, returns exactly32 bytes and equals zero. Etna header rules require the authenticated nonzero origin hash; upstream pre-execution writes it before all transactions, so both old writer paths fail from the first Etna transaction, regardless of old ancestorsHash. Reveal/pin are L2-only and require the current word nonzero. L1 SignalService retains the existing Inbox publication path and explicitly disables these L2 methods. No assumption that an L1 SSZ root lacks a convenient preimage substitutes for that mode check.

No new L2 phase variable or beginEtna call is needed. The L1 Inbox must be ACTIVE, its first parent must equal stored initialHeadHash, and the authenticated first real origin must be at/after activationL1Number. The existing statement/old-head hash binds these facts; the client validates the same public L1 activation context before calling a block valid. Missing context is UNKNOWN. The first segment retains the exact existing bootstrap sentinel and empty forced interval; it installs the first real queue snapshot. It can contain one block with zero transactions, whose full BodyV1 is at most1039 bytes when the header is1024 bytes. System writes still occur and determine its state root.

Anchor's old storage is retained, frozen and never reused; historical getters are explicitly historical. The live anchor-number getter and Anchored events disappear from the live data path. Consumers use the L2 header plus authenticated L1 header; checkpoint consumers continue using CheckpointSaved on reveal. Preserve existing checkpoint/cache/message/token namespaces and every frozen custody address.
