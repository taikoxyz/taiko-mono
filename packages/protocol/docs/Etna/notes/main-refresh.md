## Basefee policy: 75% becomes 100% in current source

**Proven:** [MainnetInbox.sol:45–46](https://github.com/taikoxyz/taiko-mono/blob/31df8fe8ef7c027840abf122ec36f87c41c3ce94/packages/protocol/contracts/layer1/mainnet/MainnetInbox.sol#L45) now configures `basefeeSharingPctg: 100`, with an explicit whole-basefee-to-coinbase comment. [DevnetInbox.sol:43](https://github.com/taikoxyz/taiko-mono/blob/31df8fe8ef7c027840abf122ec36f87c41c3ce94/packages/protocol/contracts/layer1/devnet/DevnetInbox.sol#L43) makes the same change for future local/devnet instantiations. The only constructor-config difference in these two source files is this percentage. Bond denomination, native ETH accounting and the other listed Inbox parameters are unchanged in this delta.

**Proven proposed upgrade semantics:** [Proposal0026.s.sol:49–58](https://github.com/taikoxyz/taiko-mono/blob/31df8fe8ef7c027840abf122ec36f87c41c3ce94/packages/protocol/script/layer1/proposals/Proposal0026.s.sol#L49) encodes an Inbox `upgradeTo` as action 0, without initialization. It retains the existing five address dependencies and specifies that proposals already made keep their committed percentage; the first proposal after a successfully executed upgrade carries 100. The deployment helper checks those dependencies and compares configurations after normalizing only the percentage: [DeployInboxUpgradeL1.s.sol:67–106](https://github.com/taikoxyz/taiko-mono/blob/31df8fe8ef7c027840abf122ec36f87c41c3ce94/packages/protocol/script/layer1/mainnet/DeployInboxUpgradeL1.s.sol#L67). These are script checks, not checks run in this research.

The proposal's [fee propagation explanation:248–270](https://github.com/taikoxyz/taiko-mono/blob/31df8fe8ef7c027840abf122ec36f87c41c3ce94/packages/protocol/script/layer1/proposals/Proposal0026.md#L248) describes the existing event-to-`extraData`-to-execution path. At 100%, the configured basefee remainder to the Anchor treasury is zero; previously accrued ETH is not erased. The Go tests now branch on the actual configuration instead of assuming the treasury always grows: [syncer_test.go:185–194](https://github.com/taikoxyz/taiko-mono/blob/31df8fe8ef7c027840abf122ec36f87c41c3ce94/packages/taiko-client/driver/chain_syncer/event/syncer_test.go#L185) and [syncer_test.go:222–226](https://github.com/taikoxyz/taiko-mono/blob/31df8fe8ef7c027840abf122ec36f87c41c3ce94/packages/taiko-client/driver/chain_syncer/event/syncer_test.go#L222). Their presence is not a claim that this session ran the integration suite.

**Proven economic consequence under correct execution:** a sender controlling the canonical block coinbase can recover its own basefee transfer at 100%. That transfer must not be counted as an irreversible attacker cost. Execution/proving resources, L1 data and transaction costs, external builder payments, and Etna's separately defined irreversible rent remain distinct. The source runbook itself discusses sponsorship and self-dealing at [Proposal0026.md:60–92](https://github.com/taikoxyz/taiko-mono/blob/31df8fe8ef7c027840abf122ec36f87c41c3ce94/packages/protocol/script/layer1/proposals/Proposal0026.md#L60). Normal coinbase fee receipts are neither a guaranteed net profit nor a new issuance subsidy.
