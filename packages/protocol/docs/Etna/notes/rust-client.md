# Rust client baseline reading

Baseline: `961bbd8ff55a0f66f44ad04160eb51638d655b66` (`main`). Scope: driver, proposer, protocol, and whitelist-preconfirmation-driver. This is a code-reading report, not a runtime audit or an Etna design. **Proven** below means the cited source implements the stated behavior; execution-engine correctness is **assumed**, and deployment configuration/parity not established from this checkout is **open**.

## Package map and pipeline

| Package | Responsibility and evidence |
|---|---|

| `proposer` | Periodically selects transactions, assembles a manifest and blob sidecar, then sends `Inbox.propose`: `packages/taiko-client-rs/crates/proposer/src/proposer.rs:172–229,232–262`; `packages/taiko-client-rs/crates/proposer/src/transaction_builder.rs:119–169`. |

| `whitelist-preconfirmation-driver` | Accepts authenticated P2P envelopes, caches missing ancestry, imports through the driver's guarded execution path, and exposes build/sign/gossip operations: `packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/importer/ingress.rs:114–150`; `packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/importer/cache_import.rs:120–181`; `packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/api/service/handlers.rs:59–110,146–200`. |

**Proven — there is no Rust prover crate in this workspace's member list.** The members are client, bindings, driver, proposer, protocol, rpc, test-harness and whitelist-preconfirmation-driver (`packages/taiko-client-rs/Cargo.toml:1–11`). The protocol signer is deliberately usable from zkVM guests such as raiko2 (`packages/taiko-client-rs/crates/protocol/src/lib.rs:11–14`). This is not evidence of an integrated Rust prove-with-propose transaction; the reviewed proposer constructs `Inbox.propose` with blob references and no proof argument (`packages/taiko-client-rs/crates/proposer/src/transaction_builder.rs:158–183`). Proof production/submission elsewhere is outside this Rust scope.

**Proven — normal proposal sequence:** capture L2 parent and current L1 head, use the L1 head timestamp and height in one consistent build context, select transactions, create `BlockManifest` entries, encode/compress them into EIP-4844 blobs, obtain encoded proposal input, submit through a transaction manager (`packages/taiko-client-rs/crates/proposer/src/proposer.rs:50–93,232–262`; `packages/taiko-client-rs/crates/proposer/src/transaction_builder.rs:119–183`). Multi-block manifests stagger timestamps by one second; the source explicitly warns that a block timestamp above its actual L1 inclusion timestamp invalidates the manifest (`packages/taiko-client-rs/crates/proposer/src/transaction_builder.rs:125–131`). The loop delays missed ticks because the current inbox admits at most one proposal per L1 block (`packages/taiko-client-rs/crates/proposer/src/proposer.rs:172–177`).

**Proven — canonical derivation sequence:** decode `Proposed` together with its L1 block number/hash/timestamp; set origin block to inclusion block minus one; fetch ordered blobs by committed hashes; decode manifest; normalize forced/default manifests; validate metadata; construct an `anchorV4` checkpoint from the queried L1 block hash/state root; execute via the engine (`packages/taiko-client-rs/crates/driver/src/derivation/pipeline/shasta/pipeline/mod.rs:36–46,86–109`; `packages/taiko-client-rs/crates/driver/src/derivation/manifest/fetcher/shasta.rs:53–92`; `packages/taiko-client-rs/crates/driver/src/derivation/pipeline/shasta/pipeline/payload.rs:280–324,388–402,894–953`).

**Proven — invalid manifest bytes are not equivalent to unavailable bytes.** Undecodable content defaults to a protocol empty payload, while transient fetch/RPC failures propagate for retry. A forced-inclusion source with other than one block defaults (`packages/taiko-client-rs/crates/driver/src/derivation/pipeline/shasta/pipeline/mod.rs:146–186`). Metadata validation failure also defaults the entire source (`packages/taiko-client-rs/crates/driver/src/derivation/pipeline/shasta/pipeline/payload.rs:300–320`).

## What a node can validate before L1 landing

The immediate result is layered: gossip-admissible, ancestry-pending, locally executed, and later L1-derived are different states. A gossip acceptance is not a statement of irreversible sequencing or future L1 canonicality.

| Check | Source behavior and guarantee |
|---|---|
| Signature domain | **Proven.** Signing digest is `keccak256(32 zero bytes || uint256(chain_id) || keccak256(payload))`. The primary topic signs full SSZ envelope bytes; embedded response signatures sign the advertised block hash (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/codec.rs:56–81`; `packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/api/service/handlers.rs:146–177,180–182`). |
| Signer authorization | **Proven.** Network validation recovers the signer and checks membership in the shared full operator set. Responses require embedded signature and the same membership test (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/network/handler.rs:224–236,249–266,285–303`). |
| Unique sequencing rights | **Proven absence in this gate.** The predicate is membership, not “this address exclusively owns this block/time.” The full operator roster is fetched, including all nonzero sequencer addresses (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/operator_set.rs:103–154`). Do not infer exclusive rights from a successful gossip check. |
| Wire shape and resource bounds | **Proven.** Require nonzero timestamp, beneficiary, gas limit, base fee, extra data, exactly one compressed transaction-list entry, a successfully decoded nonempty list, and an anchor transaction first (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/importer/validation.rs:19–89`). Compressed list cap is `131072 * 6` bytes; decompressed list cap is 8 MiB (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/codec.rs:16–24`). |
| Anchor identity | **Proven.** First transaction must address the configured Anchor, match chain ID, recover golden-touch sender, and invoke `anchorV4` (`packages/taiko-client-rs/crates/protocol/src/shasta/anchor.rs:246–290`). This admission helper does not decode or compare the checkpoint's L1 root/hash with canonical L1; execution validity alone is not evidence of an honest external checkpoint. Canonical derivation independently reconstructs those fields from L1 (`packages/taiko-client-rs/crates/driver/src/derivation/pipeline/shasta/pipeline/payload.rs:894–953`). |
| Parent linkage | **Proven.** Advertised parent must match the local canonical block at height minus one. If missing or different, importer requests parent and defers; production path rechecks expected parent immediately before execution (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/importer/cache_import.rs:154–181`; `packages/taiko-client-rs/crates/driver/src/production/path.rs:79–127`). |
| Execution | **Proven/assumed.** Driver reconstructs via payload attributes, obtains the engine-built payload, and submits it. Only `newPayload` VALID counts; ACCEPTED means unexecuted side chain and is rejected (`packages/taiko-client-rs/crates/driver/src/sync/engine.rs:168–219,286–300`). Correct execution and consensus validation by the external engine are assumptions, not independently proved in this checkout. |
| Advertised hash binding | **Proven limitation.** Importer compares engine-produced hash against signed envelope hash only after import. On mismatch it purges the envelope, while the produced block has already advanced the unsafe head; code comments state this explicitly (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/importer/cache_import.rs:186–208`). This is evidence against equating “import succeeded” with “the signed block is valid.” Full exploit consequences require engine-path analysis. |
| Time | **Proven.** Preconf admission explicitly checks nonzero timestamp and fork-consistent header-difficulty presence (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/importer/validation.rs:25–29,105–131`). Canonical manifest timestamps must exceed the parent by at least one second, respect fork activation / maximum age, and not exceed actual L1 inclusion time (`packages/taiko-client-rs/crates/driver/src/derivation/pipeline/shasta/validation.rs:96–141`). Future L1 inclusion timing cannot be known merely from receiving a preconf. Additional engine timestamp rules are **open** in this scope. |

**Proven conclusion:** a synchronized node with parent state and the full payload can authenticate, inspect, and execute without waiting for the batch's L1 landing. A node lacking the parent cannot immediately decide execution validity: the code explicitly defers it. Even a locally executed preconf does not prove later L1 derivation will preserve it; canonical source validation uses facts only available at L1 landing. Evidence: the parent deferral and inclusion-time checks cited above. No observation of this local protocol establishes universal broadcast availability.

## Whitelist and CL coupling

**Proven:** the operator set bootstraps from `PreconfWhitelist`, refreshes every hardcoded `12 * 32 = 384` seconds, and retains old entries on RPC failure while retrying after 30 seconds (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/operator_set.rs:43–53,64–99`; `packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/cache.rs:28–29`). Revocation therefore is not instantaneous or independently synchronized across nodes. The comment's “within one epoch” bound requires successful reads; failed reads can extend it.

**Proven:** the proposal loop prechecks `getOperatorForCurrentEpoch()` against its L1 proposer address, except when the forced-inclusion permissionless threshold is reached (`packages/taiko-client-rs/crates/proposer/src/proposer.rs:270–324`). Local build API checks only that its own P2P signer is in the full set (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/api/service/handlers.rs:5–20,98–110`). Epoch sequencing duties and all-whitelist gossip admission are distinct controls.

**Proven:** end-of-sequencing (EOS) messages are mapped to beacon epochs using the BeaconClient (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/importer/ingress.rs:85–110`; `packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/api/service/handlers.rs:202–213`). The Rust driver does not own the complete handover policy: source states Catalyst owns handover and supplies an explicit build parent (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/importer/mod.rs:176–184`). Its code alone cannot establish the safety of operational role rotation.

URC-specific paths, including generated `bindings/src/lookahead_store.rs`: **removed in Etna**. No URC mechanism was used in this reading or proposed as a successor primitive.

## Missing data, withholding and reorgs

**Proven — recovery, not accountability:** absent ancestry triggers throttled hash requests. Pending cache is 768 envelopes, recently served cache 1024, duplicate request cooldown ten seconds (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/importer/cache_import.rs:154–169`; `packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/cache.rs:20–29`). Responses can come from recent envelopes or local L2 full blocks with a stored nonzero origin signature; event-confirmed blocks are not served as unsafe responses (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/importer/ingress.rs:154–191,218–238,269–289`). These paths neither prove withholding nor slash its author.

**Proven — unsafe branch replacement remains possible:** parent-valid preconf payloads above the event-confirmed boundary are sent through engine forkchoice; same-height sibling injections are explicitly anticipated (`packages/taiko-client-rs/crates/driver/src/sync/event.rs:591–620`; `packages/taiko-client-rs/crates/driver/src/sync/engine.rs:174–180`). A delayed private branch with available ancestry can compete within that unsafe range. The source does not provide a quorum certificate or an on-chain publication deadline in the reviewed preconf path. **Open:** the complete conditions under which a competing branch wins depend on engine behavior and external sequencer policy.

**Proven — confirmed boundary protection (WLP-INV-002/003/004):** ingress opens only after scanner-live plus strict confirmed readiness; target proposal is `nextProposalId - 1`, and for nonzero targets its block mapping and `head_l1_origin >= target_block` must exist. Before processing every preconf under a shared router lock, the driver rereads `head_l1_origin` and rejects stale heights (`packages/taiko-client-rs/crates/driver/src/sync/confirmed_sync.rs:5–40`; `packages/taiko-client-rs/crates/driver/src/sync/event.rs:551–616,1818–1822,1865–1871`). Genesis has a zero boundary; non-genesis missing custom tables keep import fail-closed (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/importer/mod.rs:197–220`). A tip-read failure during initial cache admission is deliberately deferred to these authoritative later checks (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/importer/ingress.rs:42–76`).

**Proven — L1 reorg recovery differs from preconf ancestry recovery (WLP-INV-009):** scanner reorg notifications invalidate remembered proposal logs above a common ancestor and reset the head-origin boundary; scanner errors reconnect for replay (`packages/taiko-client-rs/crates/driver/src/sync/event.rs:1824–1861`). Event-confirmed here means derived from L1 events, not necessarily Ethereum-finalized; these events can still reorg. The inbox's last finalized proposal ID is separately read at the containing L1 hash as an optional forkchoice hint (`packages/taiko-client-rs/crates/driver/src/derivation/pipeline/shasta/pipeline/mod.rs:61–83`).

## Forced inclusion

**Proven:** proposer precheck permits a normally unauthorized proposer once oldest forced inclusion reaches the configured delay times permissionless multiplier (`packages/taiko-client-rs/crates/proposer/src/proposer.rs:270–324`). Proposal input requests all forced inclusions through `numForcedInclusions = u16::MAX` (`packages/taiko-client-rs/crates/proposer/src/transaction_builder.rs:173–183`). Derivation requires one block per forced source and inherits metadata; malformed contents default rather than permanently halt decoding (`packages/taiko-client-rs/crates/driver/src/derivation/pipeline/shasta/pipeline/mod.rs:146–186`; `packages/taiko-client-rs/crates/driver/src/derivation/pipeline/shasta/pipeline/payload.rs:297–320`). The P2P forced flag alone does not establish that L1 queued or ordered a user transaction; canonical forced-source status comes from the L1 event (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/payload.rs:14–35`; `packages/taiko-client-rs/crates/driver/src/derivation/pipeline/shasta/pipeline/mod.rs:146–152`).

## Verified differences from Go and remaining uncertainty

1. **Proven:** Go exposes current and next operators as `P2PSequencerAddresses`, while Rust's examined network predicate permits the full refreshed roster (`packages/taiko-client/driver/preconf_blocks/server.go:1047–1061`; `packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/network/handler.rs:297–303`; `packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/operator_set.rs:103–154`). This is a real predicate difference; complete Go gossip enforcement belongs to the Go report.
2. **Proven:** Rust explicitly delegates handover/EOS request initiation to Catalyst, whereas its source identifies the Go handover loop as publishing EOS recovery requests (`packages/taiko-client-rs/crates/whitelist-preconfirmation-driver/src/importer/mod.rs:176–184`). Rust responds to requests and stores epoch markers.
3. **Proven:** multi-block proposer timestamps intentionally follow Go's `L1 head time + index` convention, including its unknown future inclusion-time ceiling (`packages/taiko-client-rs/crates/proposer/src/transaction_builder.rs:125–131`).
4. **Open:** no external alethia-reth checkout or Catalyst implementation was inspected. Their engine validation, metadata persistence, recovery and handover semantics must be verified before making an end-to-end safety claim. The Rust proposer itself warns that engine-mode preview can persist ghost origin rows on engines without the referenced deferred-persistence fix (`packages/taiko-client-rs/crates/proposer/src/proposer.rs:141–149`).
5. **Open:** reviewed source does not measure P2P propagation or execution latency, prove a one-second soft-confirmation SLA, establish economic penalties for equivocation/withholding, or show production config values. Those cannot be inferred from “can build preconfirmation payloads.” The observed signer, execution and missing-parent checks support only the narrower guarantees above.
