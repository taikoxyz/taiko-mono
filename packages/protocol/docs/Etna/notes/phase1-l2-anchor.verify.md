## Missed facts

- `l1ChainId` immutable is validated in the constructor but never read by any Anchor logic; it exists only as a public getter (no cross-chain-id check on `anchorV4`) — `packages/protocol/contracts/layer2/core/Anchor.sol:50,103,108` (grep shows no other use).
- `Anchor` has no `receive()`/`fallback()`; ETH can reach it only through protocol-level base-fee crediting (or selfdestruct/coinbase), never via a `call` with value — `Anchor.sol` (no such function; comment at `:141-142`).
- Go syncer has a second calldata-decoding exception: proposal id == 1 with a non-genesis parent uses the parent's `anchorV4` calldata on every chain, not just mainnet ids ≤ 7 — `packages/taiko-client/driver/chain_syncer/event/syncer.go:318-324`.
- `DelegateController.onMessageInvocation` is `payable` and `Controller` has `receive()`; bridged DAO messages can carry ETH which actions then spend via `call{value}` (test moves 0.1 ether) — `packages/protocol/contracts/layer2/governance/DelegateController.sol:40`; `packages/protocol/contracts/shared/governance/Controller.sol:36,71`; `test/layer2/governance/DelegateController.t.sol:97-100,129-130`.
- `Controller.dryrun` is permissionless *and* `payable` and executes arbitrary `Action[]` with `msg.sender == DelegateController` (the owner of every L2 contract) before unconditionally reverting; safety rests solely on the trailing `revert DryrunSucceeded()` — `Controller.sol:46-53`.
- `BridgedTaikoToken.burn` burns only `msg.sender`'s balance (`_burn(msg.sender, _amount)`), so the vault/owner can only burn tokens they hold — `packages/protocol/contracts/layer2/mainnet/BridgedTaikoToken.sol:49`.
- `__Essential_init` substitutes `msg.sender` when `_owner == address(0)`, so `Anchor.init(0)` / `BridgedTaikoToken.init(0)` make the deployer the owner — `packages/protocol/contracts/shared/common/EssentialContract.sol:195`.
- `EssentialContract.pause()`/`unpause()` are `public` and mutate `__paused` *before* calling `_authorizePause` (the revert still protects, but the ordering is unusual) — `EssentialContract.sol:150-165`.
- Mainnet proposals run to at least Proposal0024 (`BRIDGED_ERC20 ... registered ... by Proposal0024`); grep confirms only 0007/0009/0011 touch `L2.ANCHOR`, so section 4.6 is the complete anchor subset but not the full L2 governance history — `packages/protocol/contracts/layer2/mainnet/LibL2Addrs.sol:18-20`; `packages/protocol/script/layer1/proposals/`.
- `_calcAncestorsHash` leaves ring-buffer slots zero when `parentId < 255` (guard `parentId >= i + 1`), and `block.number - 1` underflows/reverts at block 0 — `Anchor.sol:132,199,209`.
- There is no admin/owner function to reset `_blockState` (`ancestorsHash` or `anchorBlockNumber`); a stuck chain is recoverable only via `upgradeTo` to an implementation that writes storage — `Anchor.sol:113-115,145-156` (only `init` and `withdraw` besides `anchorV4`).
- `SignalService._authorizedSyncer` is `internal immutable` with no getter, so the wired Anchor proxy address cannot be read on-chain — `packages/protocol/contracts/shared/signal/SignalService.sol:37`.
- Preconf API indexes `parent.Transactions()[0]` without a length check (panic on an empty parent such as genesis) — `packages/taiko-client/driver/preconf_blocks/api.go:118`.
- Rust `decode_anchor_proposal_id` returns 0 for block 0 and requires `extra_data.len() >= 7` — `packages/taiko-client-rs/crates/driver/src/sync/event.rs:1632-1641`.
- `Controller.lastExecutionId` is a `uint64` at "slot 2" after `__reserved0`; `DelegateController` adds its own `uint256[50] __gap` — `Controller.sol:25-32`; `DelegateController.sol:27`.

## Overall

The summary is safe to rely on: every on-chain gate, timing constant, storage slot, address and interface signature I checked matches the code line-for-line, and the central invariant (one successful `anchorV4` per block after bootstrap, stuck forever if one is missed) is correctly derived from the ring-buffer construction. Two items need re-reading: (1) G9 overstates the blast radius of replacing the L1 DAOController or L2 Bridge — the DelegateController is UUPS-upgradeable by itself, so a planned migration is a single bridged upgrade action, not a redeploy plus ownership re-transfer of every L2 contract; (2) section 4.7/C53 omits the Go syncer's `proposal id == 1` calldata-decoding branch, which applies on every chain. Readers designing a permissionless successor should also note the missed facts above, especially that `l1ChainId` is dead weight, that the Anchor has no receive path or state-reset path, and that `dryrun`/`onMessageInvocation` are payable with the controller as `msg.sender`. Node-side enforcement of the 1,000,000-gas / first-tx rule remains unverifiable in this repo, as the summary itself flags.
