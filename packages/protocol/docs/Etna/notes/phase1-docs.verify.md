## Missed facts

- `LibForcedInclusion.isOldestForcedInclusionDue` is dead code (defined but never called); the only due-check that runs is inline in `Inbox._consumeForcedInclusions` and short-circuits on `timestamp == 0` — `P/contracts/layer1/core/libs/LibForcedInclusion.sol:152-170`; `P/contracts/layer1/core/impl/Inbox.sol:654-658`
- Slashed liveness bonds are never burned or transferred: `settleLivenessBond` only decrements the ledger and emits `slashedAmount`; the TAIKO remains inside the Inbox. Likewise the ETH fees of forced inclusions voided by `init3` "remain in the contract" and the Inbox has no owner withdrawal path (only `sendEtherAndVerify` at `:441` refund and `:710` fee payout) — `P/contracts/layer1/core/libs/LibBonds.sol:160-167`; `P/contracts/layer1/core/impl/Inbox.sol:251-252,441,710`
- Nothing in the Inbox is pause-gated at all (no `whenNotPaused` on propose, prove, deposit, withdraw, saveForcedInclusion); `pause()` on the Inbox is a no-op for behaviour. `Anchor.anchorV4`, `PreconfWhitelist` and `ProverWhitelist` are likewise unpaused-gated. `SignalService.saveCheckpoint` is not `whenNotPaused` either, so pausing the SignalService blocks bridge proof verification but not checkpoint writes — `grep whenNotPaused` over `Inbox.sol`, `Anchor.sol`, `PreconfWhitelist.sol`, `ProverWhitelist.sol` → no hits; `P/contracts/shared/signal/SignalService.sol:174-184`
- Proposer selection depends on the EIP-4788 beacon-root precompile at a hard-coded address and hard-coded per-chain beacon genesis timestamps (mainnet, Holesky, Helder, Hoodi only; any other chain id returns genesis 0). The lookup scans at most 32 slots forward and returns `bytes32(0)` on failure; `_getRandomNumber` then yields 0 so operator index 0 is deterministically selected (no revert) — `P/contracts/layer1/preconf/libs/LibPreconfConstants.sol:11-17`; `P/contracts/layer1/preconf/libs/LibPreconfUtils.sol:12,23-36,44-50`; `P/contracts/layer1/preconf/impl/PreconfWhitelist.sol:293,310-313`
- The timestamp validator also defaults a source when `lowerBound > proposal.timestamp` (i.e. the parent's timestamp already equals the proposal's L1 timestamp, or a forced-inclusion chain would exceed it); this is the concrete mechanism behind the `MAX_FORCED_INCLUSIONS < 12` comment and is not stated in `Derivation.md` — `RS/crates/driver/src/derivation/pipeline/shasta/validation.rs:110-112`; `GO/driver/chain_syncer/event/derivation/source_fetcher.go:294-302`
- `proposalAge` passed to the verifier is computed from the prover-supplied `transitions[offset].timestamp`, not from any stored proposal timestamp; it is bound only through the commitment hash the proof commits to — `P/contracts/layer1/core/impl/Inbox.sol:336,394-398`
- `IProposerChecker.checkProposer` is declared non-`view` in the interface (state-changing checkers such as a lookahead poster are allowed); `PreconfWhitelist` narrows it to `view` — `P/contracts/layer1/core/iface/IProposerChecker.sol:16-21`; `P/contracts/layer1/preconf/impl/PreconfWhitelist.sol:127-134`
- `Anchor` skips the ancestors-hash continuity check on the very first anchor (stored hash == 0) — `P/contracts/layer2/core/Anchor.sol:176-178`
