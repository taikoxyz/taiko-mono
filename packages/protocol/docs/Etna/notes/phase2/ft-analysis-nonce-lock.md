**Hypothesis under test.** Every Taiko proposal is an EIP-8141 frame transaction with `sender = G` (a non-upgradeable gate contract) and `nonce = nonce(G)`; the loser of a same-nonce race is *invalid* (not includable in any valid block, pays nothing: no execution gas, no blob fee) rather than *included-and-reverted*.

## 0. Decisive spec passages (all VERIFIED, raw md fetched 2026-09-30)

These are numbered so the claim tables can cite them.

- **Q1 nonce check, first step, before signatures and frames** — [8141 L390-392] "To begin processing a frame transaction: 1. Ensure `tx.nonce == state[tx.sender].nonce`" then "Compute the canonical transaction signature hash" then "For each `sig` in `tx.signatures`, ensure `validate_signature(...) == true`".
- **Q2 nonce increment point** — [8141 L715-717] `APPROVE_PAYMENT`: "If `sender_approved == false`, revert the current call frame." ... "Increment the sender's nonce, set `payer = resolved_target`, and collect the transaction's `max_cost` from `payer`." `APPROVE_EXECUTION` [L709-711] sets only `sender_approved = true` (no nonce change).
- **Q3 VERIFY failure = invalid** — [8141 L423-425] "Execute the frame as a `STATICCALL`, disallowing state manipulation. Only `APPROVE` can modify the state or transaction context in `VERIFY`. If the frame fails by reverting or halting exceptionally, the transaction is invalid. This unrolls any effects of `APPROVE`."
- **Q4 nothing charged until payment approved** — [8141 L1104] "A frame transaction is charged nothing until one of its frames approves payment".
- **Q5 same-nonce alternatives** — [8141 L1096] "Pending frame transactions are identified by `(sender, nonce)`. The sender's nonce is consumed exactly once per transaction when payment is approved, so two pending transactions sharing it are alternatives, of which at most one can ever be included."
- **Q6 expiry verifier** — [8141 L323] "A `VERIFY` frame whose `frame.target` equals `EXPIRY_VERIFIER` is an **expiry verifier frame**. It calls the expiry verifier contract deployed at `EXPIRY_VERIFIER` with `frame.data` as calldata. The calldata is interpreted as an 8-byte unsigned big-endian expiry timestamp. The call reverts unless `block.timestamp <= expiry_timestamp`." Constants [L40-41]: `EXPIRY_VERIFIER = address(0x8141)`, `EXPIRY_DATA_LENGTH = 8`. Static rules [L325-332]: flags 0, value 0, limits.state 0, `len(data) == 8`, at most one. No `valid_after` anywhere (grep: zero hits).
- **Q7 mempool expiry drop** — [8141 L973] "A node MUST drop a frame transaction from the public mempool if it contains an `expiry_verify` frame whose deadline is less than the node's view of the current block timestamp at any point." and [L971] "An `expiry_verify` frame MAY appear only as first frame in the frame list."
- **Q8 SENDER frame needs approval; ORIGIN** — [8141 L407-413] "If mode is `SENDER`: `sender_approved` must be `true`. If not, the transaction is invalid. Set `caller` to `tx.sender`." ... "The `ORIGIN` opcode returns frame's `caller` throughout all call depths."
- **Q9 APPROVE authority** — [8141 L702-711] "If `ADDRESS != resolved_target`, revert." ... `APPROVE_EXECUTION`: "If `resolved_target != tx.sender`, revert the current call frame." Static [L182-184]: "if frame.flags & APPROVE_EXECUTION: assert frame.target is None or frame.target == tx.sender". [L1154] "Because `DELEGATECALL` preserves `ADDRESS`, code executed via `DELEGATECALL` from the resolved target may also execute `APPROVE` successfully."
- **Q10 contract senders allowed; other tx types not** — [8141 L1110-1114] "Do not apply the restriction put in place by [EIP-3607] to frame transactions. Specifically, `SENDER` frames originate calls where `tx.sender` is a contract account. Validation logic for other transaction types remains unchanged, i.e. the transaction is only valid if the sender account's code is either empty or a valid delegation indicator."
- **Q11 default code (EOA payer)** — [8141 L664-671] "If `mode` is `VERIFY`: Read the allowed approval scope ... `allowed_scope = frame.flags & APPROVE_SCOPE_MASK`. If `allowed_scope == APPROVE_SCOPE_NONE`, revert. Let `sig_index = 0` if `allowed_scope & APPROVE_EXECUTION != 0`, else `sig_index = 1`. If there is not a `SECP256K1` signature `sig` at index `sig_index` such that `resolved_signer == resolved_target` and `sig.msg == Bytes()`, revert. Call `APPROVE(allowed_scope)`." [L673] "The default code draws no execution gas of its own: the frame's only execution charge is the resolved target's access, taken at frame entry".
- **Q12 signature rules** — [8141 L220-221] "For `SECP256K1` and `P256`, the `signer` is a 20-byte Ethereum address. If absent, `tx.sender` is used (for introspections as well). For `ARBITRARY`, `signer` MUST be empty." [L225] "if `len(msg) == 0`, the signature is signed over `compute_sig_hash(tx)`". Static [L157-158] ARBITRARY: `assert len(sig.signer) == 0`; `validate_signature` ARBITRARY branch [L313] "return len(sig.signer) == 0" (no length constraint on the raw bytes). [L249-255] `compute_sig_hash` elides raw bytes of every empty-`msg` signature. [L1444-1446] "When an `ARBITRARY` signature has empty `msg`, its raw bytes are elided from the canonical signature hash and can therefore be changed without changing `TXPARAM(0x08)`." Gas [L211-215]: ARBITRARY 100, SECP256K1 2800; [L481-485] `signature_data_cost` bills `calldata_cost(sig.signature)`.
- **Q13 entry access charge and pre-warm set** — [8141 L406] "Charge the resolved target's warm or cold account access ([EIP-2929]) from `gas_left`, before the balance check and before dispatch. ... If `gas_left` cannot cover the charge, the frame halts exceptionally." [L440] "`accessed_addresses` is initialized as in [EIP-2929] and [EIP-3651] (`tx.sender`, the coinbase, and precompiles warm) ... Being a frame target does not warm an address ... `ENTRY_POINT` is not pre-warmed". [L420] "if `resolved_target` uses an [EIP-7702] delegation indicator, execute according to [EIP-7702]'s delegated-code semantics."
- **Q14 introspection indices** — TXPARAM [L739-752]: 0x01 nonce, 0x02 sender, 0x03 max_priority_fee_per_gas, 0x07 len(blob_versioned_hashes), 0x09 len(frames), 0x0A current frame index, 0x0B len(signatures). FRAMEPARAM [L797-810] stack "`frameIndex` on top and `param` second": 0x00 resolved_target, 0x01 limits.execution, 0x02 mode, 0x03 flags, 0x04 len(data), 0x08 value, 0x09 limits.state. SIGPARAM [L825-838] "`signatureIndex` on top and `param` second": 0x00 resolved_signer (halt for ARBITRARY), 0x01 scheme, 0x02 msg, 0x03 len(signature) (ARBITRARY only). FRAMEDATALOAD [L760-765] "`top - 0` offset, `top - 1` frameIndex". APPROVE [L679-685] "`top-0` offset, `top-1` length, `top-2` scope". [L733] "The instructions in this section are defined only during the execution of a frame transaction. Executing any of them in the context of any other transaction type results in an exceptional halt." APPROVE [L703] "If the current transaction is not a frame transaction, an exceptional halt occurs."
- **Q15 mempool (policy, not consensus)** — [L864] "Transactions outside these rules may be accepted into a local or private mempool, but must not be propagated through the public mempool." Constants [L870] `MAX_VERIFY_GAS = 100_000`. Recognized prefix [L932-940] `[only_verify, pay]` (+ optional leading `expiry_verify`, [L971]). Rule 6 [L963] "The sum of `limits.execution` values across the validation prefix, plus the intrinsic cost of validating `tx.signatures`, must not exceed `MAX_VERIFY_GAS`." Rule 7 [L1091] "A node should keep at most one pending frame transaction per sender in the public mempool. A new transaction from the same sender MAY replace the existing one only if it uses the same nonce and satisfies the replacement rules below." Replacement [L1098] "+10% conventional default" on both fee fields; "A blob-carrying frame transaction additionally follows the blob pool's replacement conventions for `max_fee_per_blob_gas`." Eviction order [L1102] "first transactions already invalid against the current head, then transactions with the nearest expiry deadline, then transactions with the lowest effective priority fee." Payer exposure [L1100] "A node must not hold pending frame transactions whose summed maximum costs exceed the payer's balance"; "a `pay` frame whose target has the empty code hash (a default-code sponsor) is not a paymaster and is governed by the per-payer exposure rule alone." Producer bound [L1104] "A block producer SHOULD bound the unpaid validation work ... after a bounded number of consecutive block-building attempts in which the transaction's validation prefix fails to approve, the producer MAY evict it". Revalidation [L1108] "This includes at least transactions for the same sender". Banned opcodes [L1002-1030] include TIMESTAMP "Except in an expiry verifier frame executing the canonical runtime code at `EXPIRY_VERIFIER`", BALANCE, SELFBALANCE, GASPRICE, NUMBER, BASEFEE, BLOBBASEFEE, etc.; [L1030] "`SLOAD` can be used only to access `tx.sender` storage". Trace rules [L989-998]: reject if "a frame in the validation prefix reverts", "execution reads storage outside `tx.sender`", "CALL* or EXTCODE* to ... an address that uses an EIP-7702 delegation, except for `tx.sender` default-code behavior".
- **Q16 blob handling** — [8141 L653-655] "the payer is also the blob-fee payer ... The transaction is only valid for inclusion in a block if `tx.fees.max_fee_per_blob_gas >= blob_base_fee` of that block. ... The payer is charged `blob_gas * blob_base_fee`; no additional blob fee is collected or refunded." Settlement [L608-618] `max_cost = max_gas * max_fee_per_gas + blob_gas * blob_base_fee`; `charged_fee = gas_used * effective_gas_price + blob_gas * blob_base_fee`.

[L535] "A charge that exhausts either pool halts the current call frame rather than changing the transaction's static validity. - **Q18 approval scope** — [L1464] "`sender_approved` is a single transaction-scoped flag. Once a frame grants `APPROVE_EXECUTION` ..., every subsequent `SENDER` frame executes with `caller` set to `tx.sender`". ## 4. Worked example

Setup (concrete values are illustrative; spec constants are VERIFIED, byte-composition estimates are mine):
- `G` deployed by CREATE2; `nonce(G) = n = 4242` after block N−1 (slot S−1, timestamp `T_{S-1} = T_S − 12`).
- Proposers A (`P_A`) and B (`P_B`), plain EOAs, each holding ≥ `max_cost`.
- Each builds the 4-frame tx of §1.1 with `expiry = T_S`, `nonce = 4242`, `sender = G`, **2 blobs** (`blob_gas = 2 × 131,072 = 262,144`), `max_fee_per_blob_gas` ≥ expected `blob_base_fee`.
- Frames: f0 `[VERIFY, 0, 0x8141, [3200, 0], 0, be64(T_S)]`; f1 `[VERIFY, 2, null, [5000, 0], 0, ""]`; f2 `[VERIFY, 1, P_x, [3500, 0], 0, ""]`; f3 `[SENDER, 0, INBOX, [300_000, 200_000], 0, proposeFor(P_x, packed)]` where `packed` = deadline 0 ‖ start 0 ‖ numBlobs 2 ‖ offset 0 ‖ numFI 0 ‖ expectedProposalId (say 90001).
- Signatures: `[[ARBITRARY, "", "", ""], [SECP256K1, P_x, "", sig_x]]`.
- Fees: A tip 3 gwei / max_fee 40 gwei; B tip 2 gwei / max_fee 40 gwei. Both have `max_priority_fee ≥ MIN_TIP`.
- `max_gas` (Q19, [L515]) = intrinsic (≈ 18,840) + Σ limits.execution (3,200 + 5,000 + 3,500 + 300,000 = 311,700) + Σ limits.state (200,000) ≈ **530,540**. `max_cost` ≈ 530,540 × 40 gwei + 262,144 × blob_base_fee — escrowed from `P_x` only if/when f2's APPROVE runs.

What every honest node does on receiving either tx (Q15, policy): static checks → signature validation (sig1 recovers to P_x, msg = `compute_sig_hash`) → simulate f0 (expiry ok while head timestamp ≤ T_S), f1 (G's pins → `APPROVE(2)`), f2 (default code: sig index 1 is SECP256K1 by P_x, msg empty → `APPROVE(1)`: balance ok, nonce increments in simulation, payer = P_x) → stop (rule 7 of the structural rules, [L964]). Cost to the node: unpaid simulation ≤ 14,600 gas-equivalents. Admission: one `(G, 4242)` per node; a second variant is admitted only as a replacement with +10% on both 1559 fields and, per blob-pool convention, +100% on all three caps — B (tip 2 < 3 gwei) **cannot** replace A on a node that already holds A; a node that saw B first keeps B and rejects A unless A's caps are ≥ 2× B's (blob rule) — A's 3 gwei tip is not 2× B's 2 gwei, so that node keeps B. Both also submit directly to builders.

### Scenario (i): A lands, B loses
- **Slot S, block N (timestamp T_S)** — builder holds both; picks A (higher tip). Execution of A in block N: step 1 `4242 == state[G].nonce (4242)` ✓; sigs ✓; f0: `T_S ≤ T_S` ✓ (gas ≈ 3,051 of 3,200); f1: G's ~45 pins ✓ → `sender_approved = true` (≈ 1,100 of 5,000); f2: cold access to P_A 3,000 of 3,500, default code → `APPROVE(1)`: **`state[G].nonce → 4243`**, `payer = P_A`, escrow `max_cost`; f3: caller = G, cold Inbox 3,000 + Inbox ≈ 55k execution, state writes from the 200k state budget → `Proposed` event, `lastProposalBlockId = N`. Settlement: `P_A` pays `gas_used × effective_gas_price + 262,144 × blob_base_fee`; unused frame gas and state gas refunded to `P_A`. Estimated `gas_used` ≈ 18,840 + 3,051 + 1,100 + 3,000 + 58,000 + state ≈ **84k execution + Inbox state gas** (vs ≈ 71k for a post-2780 type-3 tx doing the same Inbox work; UNVERIFIED absolute numbers).
- **If the same builder also appended B after A in block N** — B's step 1: `4242 ≠ 4243` → `invalid_transaction()` → the block is invalid (Q20). No honest node accepts block N; see (iii).
- **After block N is canonical** — every node's revalidation re-simulates same-sender txs [L1108]; B fails step 1; B is evicted ("already invalid against the current head" is first in eviction order [L1102]). **B pays: 0 gas, 0 blob gas, 0 wei.** B's 2 blobs (256 KiB) were gossiped for nothing — cost borne by the network, bounded by rule 7 (one pending per sender per node).
- **Slot S+1** — B reads `nonce(G) = 4243`, drops A's L2 blocks from its batch, signs `nonce = 4243, expiry = T_{S+1}`. If A *also* pre-signed 4243 for slot S+1 (not prevented by anything), the same race repeats at nonce 4243; if A pre-signed 4243 and got it into block N right after 4242, A's second tx is valid (nonce matches) and reverts at `CannotProposeInCurrentBlock` — A pays ≈ 30k gas + full blob fee and nonce 4243 is burned for everyone (3.01).

### Scenario (ii): nobody lands before expiry
- **Slot S is missed / builder ignored both.** No block with timestamp ≤ T_S includes a `(G, 4242)` tx. `state[G].nonce` stays 4242. Nobody was charged (Q4: no APPROVE ever executed on-chain).
- **Block N' at slot S+1 (timestamp T_S + 12)** — either tx, if attempted: f0 reverts (`T_S + 12 > T_S`) → VERIFY failure → invalid (Q3) → no valid block can carry them; a builder attempting inclusion produces an invalid payload (as in iii).
- **Pool behaviour** — Q7: nodes MUST drop when the deadline "is less than the node's view of the current block timestamp". Literal reading: head = N−1 (timestamp T_S − 12) until N' arrives, so the variants stay pooled through slot S and are dropped only once N' (T_S + 12) is the head — the PDF's "one slot late". Practical consequence: if A or B resubmits for slot S+1 (same `(G, 4242)`, `expiry = T_{S+1}`) *before* N' is seen, the new tx is a **replacement** of their own still-pooled variant and needs +10%/+100% bumps on nodes still holding it (CANNOT DETERMINE: a node may instead use the *expected next* timestamp as its "view"). Builders receiving direct submissions can simply prefer the newer one.
- **Who pays: nobody.** Node/builder side: each variant cost ≤ ~15k gas of unpaid simulation per build attempt; the producer-side bound [L1104] limits repeats.

### Scenario (iii): a malicious builder tries to include B after A
- **Block N candidate = [..., A, ..., B]** — A executes as in (i), nonce → 4243; B fails step 1 (`4242 ≠ 4243`) → invalid transaction → **invalid block/payload** (Q20). Note: including B *before* A instead is simply "B wins, A is the loser" — legal and the builder's prerogative (1.11).
- **Under ePBS (Glamsterdam, live before 8141)** — the builder's `ExecutionPayloadBid` (amount = its bid) is recorded; when the builder reveals the payload, `verify_execution_payload_envelope` asserts `execution_engine.verify_and_notify_new_payload(...)` → fails → the envelope never enters the store; the slot is *Empty*. The builder's bid is still paid if the beacon block collected ≥ 60% same-slot attestation weight (`process_builder_pending_payments`, VERIFIED in client-behaviour §4b). **Builder: pays its bid, gets nothing. A: not included, pays 0 (its tx remains valid for the next block ≤ T_S — usually none, so A also expires and re-signs). B: pays 0.** The L2 loses the slot. The design's promise ("does not rely on builder good behavior") holds in the sense that no proposer pays; it does not prevent a builder from burning its own bid to waste the slot.
- **Under MEV-Boost (if still used)** — relay `ValidateBuilderSubmissionV3` executes the block and rejects it; the bid never wins. Optimistic relay: header may be signed → missed slot, builder collateral refunds the proposer. A and B pay 0.
- **Under a self-building validator** — its own EL rejects the payload at `newPayload`; the validator simply cannot propose that block.

## 5. Assumptions the analysis depends on

Tags: **spec-guaranteed** (quoted consensus text of EIP-8141 as of 2026-09-30) / **client-policy** (mempool "should"/"must" in the non-consensus Mempool section, or observed client code) / **builder-policy** / **open** (not decidable from sources fetched).

1. The nonce check is step 1 of frame-tx processing, before signatures and frames; failure → invalid, nobody charged. — **spec-guaranteed** (Q1, Q4).
2. The nonce increments exactly once, inside the payment-scoped APPROVE, and a later SENDER-frame revert never rolls it back. — **spec-guaranteed** (Q2, Q17).
3. An invalid frame transaction makes the containing block invalid (so a builder cannot "force it in"). — **open** as an 8141 sentence; **spec-guaranteed** by the general execution rule for existing types (execution-specs `check_transaction`), and the only coherent reading of `invalid_transaction()`.
4. The blob fee of a frame tx is part of `max_cost` collected from `payer` at APPROVE and settled at inclusion; an invalid tx has no payer and no blob charge. — **spec-guaranteed** (Q16, Q4).
5. `EXPIRY_VERIFIER` is `address(0x8141)` with 8-byte calldata and upper-bound-only semantics. — **spec-guaranteed today**; **open** going forward (PR #12387 changes the address; PR #12252 the calldata).
6. Opcode numbers 0xaa, 0xb0-0xb5 and the TXPARAM/FRAMEPARAM/SIGPARAM index tables are as quoted. — **spec-guaranteed today**; **open** until Final (PR #12253 registry; EIP-8250 adds TXPARAM indices and changes `nonce`).
7. Only code executing with `ADDRESS == tx.sender` (or delegatecalled by it) can grant APPROVE_EXECUTION; G's bytecode contains no CALL/DELEGATECALL/CREATE/SELFDESTRUCT. — first half **spec-guaranteed** (Q9); second half an **open** audit obligation on bytecode that does not yet exist.
8. Non-frame transaction types cannot have a contract sender (EIP-3607 kept for them). — **spec-guaranteed** (Q10).
9. The EOA default code approves payment only for a SECP256K1 signature at index 1 by the target with empty msg. — **spec-guaranteed** (Q11).
10. Cold account access = 3,000 (EIP-8038), value-less call intrinsic = 15,000 (EIP-2780), both active before Hegotá. — **spec-guaranteed** by EIP-8038 text; fork placement per EIP-7773/phase-2 roadmap (Glamsterdam SFI) — **open** until Glamsterdam ships on mainnet (Sepolia 2026-10-06; mainnet date undecided).
11. Public-mempool nodes keep at most one pending `(G, n)` tx per node and treat a second as a replacement requiring +10% (1559) / +100% (blob caps). — **client-policy** (Q15 rule 7 is "should"; blob bump verified only in type-3 pools; no shipped type-0x06 pool).
12. Nodes drop expired variants when the head timestamp exceeds the deadline; whether "the node's view of the current block timestamp" means head or next block. — **client-policy / open**.
13. Nodes revalidate same-sender txs on every new head and evict stale-nonce ones. — **client-policy** (Q15 revalidation; verified in geth/reth/Nethermind for existing types).
14. Builders pick among same-nonce alternatives by tip and do not deliberately waste slots. — **builder-policy**; the "nobody pays" property does not depend on it, the "slot is used" property does.
15. Under ePBS an EL-invalid payload is rejected while the bid is paid on a 60% attestation quorum. — **spec-guaranteed** (consensus-specs gloas, VERIFIED in client-behaviour §4b); that ePBS is the builder market at 8141 activation — **open** (Glamsterdam mainnet date undecided).
16. Revert protection for privately submitted flow is per-builder policy and does not cover public-mempool copies. — **builder-policy** (Flashbots/Titan docs; public-copy leakage inferred).
17. The Taiko-side changes (proposeFor, due-FI processing, pull fees, expectedProposalId, opened checker, no bond check on the G path) are all deployed in the same upgrade. — **open** (none exist at HEAD 61d8f18); without the due-FI change G's `numForcedInclusions == 0` pin reverts on every due FI.
18. `MIN_EXEC`/`limits.execution` and `limits.state` chosen by P cover the 10-due-FI worst case and first-lap ring-buffer writes under EIP-8037/8038 pricing. — **open** (numbers not measured on a Glamsterdam schedule); failure mode is a nonce burn paid by P.
19. `P` is a plain EOA (empty code hash) at landing time. — **spec-guaranteed** consequence (a delegated P cannot pass f2 unless its delegate approves payment); a P that delegates deliberately can only hurt itself (1.3.04).
20. Third parties cannot alter a signed variant except the elided ARBITRARY bytes, which G pins to length 0. — **spec-guaranteed** (Q12, Q18).
21. G can be authored and tested: standalone Yul `verbatim`/Huff/raw bytecode; test only on EELS/hive/devnet. — **open** (tooling status; upstream revm/solc support UNVERIFIED).
22. A same-slot race between *different* proposers can occur at all. — **open**: today's `PreconfWhitelist` admits one operator per epoch (Taiko facts §(g)); the design presupposes opening the checker.
23. Reorg handling: a reorg that un-mines the winner re-opens the race; the loser may then land and pay. — **client-policy** (Nethermind re-adds; geth reinject UNVERIFIED).

## 6. Provisional observations for the synthesizer (not a verdict)

- Every load-bearing *consensus* claim of the hypothesis is supported by verbatim EIP-8141 text as of 2026-09-30: nonce check first (Q1), increment at payment approve (Q2), VERIFY failure = invalid and unrolls APPROVE (Q3), nothing charged before approve (Q4), blob fee only from `payer` (Q16), contract senders allowed (Q10), approval authority (Q9), default code (Q11), introspection (Q14). No EIP change is *required* for the core mechanism.
- The claims that only **HOLD WITH CAVEAT** cluster in three places: (1) everything about the public mempool is policy with no shipped implementation (1.09, 1.4.02, 1.4.07, 3.02, 3.03); (2) the Draft-spec pin list is stale — #12198 is dead, but **#12387 (address change) is a new, direct break of G v1's `0x8141` pin** (3.07); (3) the nonce-burn inventory misses SENDER-frame OOG/state-gas exhaustion driven by third-party FI stuffing under the very rule change the design requires, and the direct-propose path during transition (3.05, 3.08).
- The one **structural** thing the design cannot deliver is "the slot is not wasted": an ePBS builder can pay its bid and reveal an invalid payload (1.4.05), and n+1-in-same-block or any residual SENDER revert burns the nonce for everyone (3.01, 3.05).
