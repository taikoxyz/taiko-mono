## B-D41-01: inclusive latency reaches the first voidable instant

**[proven conditional counterexample; Medium]** Exact source claims: line 40, “proves and submits a hatch of up to HATCH_K blocks within HATCH_WINDOW minus one slot”; line 37, “includes a blob-free landing of about 1.2 M gas within one slot”; line 454, “If it can be proven, it is executed on L1 by close.” R04 lines 99–103 expires at `T >= close`.

Assume a 12-second L1 interval for this example, both required proofs available within the stated inclusive budget, an already active chain, no poison and no CONFLICT. Save censor entry c followed by provable CALLDATA target t at time zero. The censor controls sequencing and transaction order, which §9 already permits.

1. The censor keeps the parent changing until an ordinary landing at 14,400 executes only c. The new parent becomes public then. R04 opens t at 14,400 and closes it at 16,200.
2. E proves and submits on that parent at 16,188, exactly `1,800 - 12 = 1,788` seconds later. Inclusion at 16,200 meets the stated one-interval T1 budget.
3. The censor orders a pre-proved ordinary landing first at 16,200, with `n = v = 1` and no request block. R04 now gives `E = R = 1`; R06 allows the void and burns t's bond. E's parent and journal are stale.
4. The censor never certifies a replay. The permissionless hatch cannot list replay ids. The provable request therefore need not execute by its §9 bound, even though the literal latency premises held.

The censor spends one executed entry's save fee (approximately 0.001 ETH at the empty queue), refundable bond capital and landing gas; the victim loses 0.05 ETH and the execution guarantee. This is an endpoint failure, not accepted poison/stuffing delay.

**[open: owner correction]** Require acquisition/proving/submission plus inclusion to finish **strictly before** the first voidable instant, with a positive margin expressed in seconds, or change the endpoint rule consistently. State the exact interval used by L_K's price calculation. Test the equality case explicitly. No larger scheduling redesign is requested.

## B-D41-03: an honest certificate can form after the void

**[proven conditional counterexample; Medium]** Exact line 295: “Under T11 a replay carries only an id whose block was certified before the void”. Line 346 similarly introduces the T11 case as “a voided entry whose request block is already on the certified chain”. R05(b) instead checks contiguity at the block's anchor, not certificate creation time; T18 lines 395–400 already describes the ingredients of this schedule.

Let an entry's close be `u + 48`, where u is a term start. Let canonical anchor A have timestamp `u - 12` and still show that entry as head. A sound ordinary landing at `u + 48` voids the entry without a request block and advances to a prefix X of the ongoing, valid certified chain. Ordinary blocks above X keep the same opening live; no request block occurs between the older anchored lastLanded and the next block B.

Only **after** that void, the authorized holder creates B at timestamp `u + 49`, using A and the next certified parent on that same chain. Its anchor age is 61 seconds, inside V5's 48-to-1,800-second bounds. Its timestamp is in the same term; the parent is already VALID_GOSSIP, so C7-R07 does not need acceptance through the later L1 landing. At A, the id is the head and was not expired. R05(b) contiguity therefore passes. Honest attesters receive B on time, see it extend their locks and certify it under S2-R04. No quorum cartel, false certificate or T11 failure is needed.

The next range lands B as a replay using the void-set bit; its deposit stays burned. At-most-once execution, correct payload and save-before-anchor still hold. The incorrect part is the narrower certification-time condition: a void is not cancellation of every request lacking a certificate at that instant. The party pays ordinary production/landing costs and gains this additional delayed-execution opportunity without corrupting a quorum.

**[open: owner correction]** State the T11 case in terms of an eligible pre-void anchored view, rather than a pre-existing certificate, and add this vector. Bound that honest-validity exposure separately from D55(3)'s arbitrary later replay outside T11. Record the exact limitation coverage; do not infer extra user sign-off from D55. A certificate-time restriction, if desired instead, needs its own rule and review.

## B-D41-04: signal recovery is not universally under nine hours

One provable request ahead adds another 1,800 seconds before any per-hatch contribution. D55's poison-adjacent residual is much longer. No global under-nine-hour bound follows.
