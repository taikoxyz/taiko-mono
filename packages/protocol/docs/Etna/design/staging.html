Etna · round06 candidate · normative specification

Public data before the proof race

Anyone publishes a candidate's complete data. Ethereum later chooses an eligible, fully proved candidate in one atomic canonical action.

Core specificationRolesAccountabilityBridge & migrationArguments & verdictLearning course
Proposed specification, not deployed code. The rules below define complete public staging; the current candidate additionally includes absolute bonded-fragment deadlines, canonical rent and exact bootstrap construction. Staging adds an L1 data transaction and pays to publish accepted data twice. It creates no canonical unproved block, sequencing reservation, committee or checkpoint. Implementation, circuit, gas and economic launch checks remain open.

Classification: unlabelled normative rules and ABI sketches are proposed behavior under A-IMPLEMENTATION. Proven identifies a deduction under named premises, not machine verification. Assumed identifies environmental or cryptographic premises. Open identifies measurements or decisions still needed. This page is authoritative for staging commitments, producer authorization and the block-hash tree; accountability specifies reserved service liabilities.

1. What staging changes

A valid canonical segment must identify a matching actual-data publication at least 360 seconds old and no more than 900 seconds old. Its final submission still carries the complete identical data and a valid ZK proof. The first valid L1 action extending the accepted head wins. Many candidates may be staged for one parent; no stage chooses between them.

Proven under A-L1/A-DA/A-CRYPTO: a complete private branch cannot first disclose its execution payload in the action that makes it canonical. Its exact public context and DA commitment already appeared in a qualifying L1 publication. Private computation before timely publication remains possible; a mature public competitor may still replace a provisional branch. Staging is an enforceable public-data lead, not soft finality or proof of universal P2P delivery.

Proven — based boundary: no incumbent witness, worker or sequencer must approve staging or canonical inclusion. A too-young payload fails a nonexclusive, deterministic publication-age condition. Once eligible, a current L1 proposer can include its valid proof and data without a new external signature. Final ordering remains L1-selected. If “based” is separately defined to forbid every publication-maturity condition, that additional interpretation needs explicit adjudication; it does not follow from the prohibition on external committees or exclusive sequencer leases.

Proven — R7 boundary: the single canonical action still supplies and checks both full data and proof atomically. Earlier generic data publication does not create an accepted unproved state. Literal R7 does not expressly prohibit earlier copies. The extra transaction and duplicated DA cost are substantive changes, not free optimizations; this construction would conflict with a separate requirement that first-ever publication occur only with the proof.

2. Exact context, deterministic identifiers and no circular hashes

All hashes use canonical abi.encode, never abi.encodePacked. Integers have the declared unsigned widths, checked before narrowing. Exact ABI decoding rejects trailing bytes and inconsistent dynamic offsets. Hash strings below are literal UTF-8 strings. The execution domain is the core statement's domain:

The exact field order above is normative. Construct the context by projecting the same-named fields from SegmentStatement; the statement's taskHash must equal the recomputed context hash. Context excludes producer, beneficiary, rewardAuthorizationHash, taskHash itself, jobId, stageId, producer key ID and signatures. The full final statement includes its selected producer, beneficiary, job and stage ID and is independently proof-bound and owner-authorized.

Proven — dependency direction: derive execution outputs and the block tree, compute the context and its hash, choose a salt and compute stage ID, construct the complete statement, then sign/prove that statement. No assigned L1 counter or future publication timestamp enters the stage ID, current block hashes or current execution task. Set Head.segmentCommitment=contextHash=taskHash, not the full statement hash. A speculative child's parent execution head is therefore computable from the sealed parent's execution context before staging, job registration or payment assignment. Changing only producer, beneficiary, job or stage ID does not change that head; changing execution context does and requires descendants to be rebuilt. The accepted receipt separately retains the full statement hash for exact authorization, reward and job evidence.

Required indirect-cycle rule: current-segment stage ID, authorization, payment assignment, producer identity and job ID cannot determine that segment's EVM execution, headers or anchor calldata. A header's coinbase is an explicit staged input; it is not silently derived from the later L1 beneficiary or producer. An authenticated previous head may already contain the previous statement's commitment; that ordinary backwards dependency is permitted. These exclusions apply to derivation logic as well as to the direct hash field list.

The complete context appears in the staging call's public calldata. The staged canonical body supplies every transaction, header-affecting field, ordering choice, expected output and manifest dependency required by the core derivation rules. Its block sequence uses the exact uncompressed canonical RLP schema in the execution codec. That page also fixes the two separately tagged block-fragment and segment manifest roots, every rejected forced input, and the public system transaction. Origin and queue context are public in the descriptor. No later private permutation, timestamp, anchor value or execution-affecting option can be selected without changing the context/body and obtaining another qualifying stage. Payment and job reassignment may use the same execution context, but still require a newly appropriate full proof/authorization. Another entrant can produce its own complete statement and self-authorization using the same public context/stage; the original stager or producer's signature is not an approval gate for that entrant's proof.

Proven: a stage does not certify the descriptor's execution outputs. It may contain a false state root or impossible task; only the final proof and core checks establish correctness. Recomputing the descriptor hash and matching its declared DA commitment to actual publication are nevertheless mandatory at staging. Otherwise a caller could occupy a deterministic ID with unrelated bytes.

Context has exactly 22 ABI words, including its four-word origin. A blob staging call has 740 bytes: selector plus context plus salt. The helper performs no body execution, queue scan, block-hash tree construction, ZK verification or loop over candidates; those semantic checks belong to the final proof and Inbox. Historical revisions may still publish under their recorded domain/schema for existing serving duties; publication itself does not make a retired revision canonically admissible.

After all gates, a previously absent stage ID creates exactly one immutable receipt using the actual block.timestamp and block.number. For a previously unseen context hash, also create its immutable earliest-publication record. A feasible layout uses two storage slots per new stage receipt and one packed slot for the first context publication, excluding ordinary configuration; no unbounded list of stagers or candidates is appended. The two events have bounded fixed fields; full context/body are already in transaction calldata or its validated blob.

If the stage ID already exists, require its stored context hash to equal the recomputed hash, then return the old receipt without changing its timestamp or emitting a second new-stage record. The actual-data gates still apply: a duplicate does not provide a hash-only registration path. Matching front-running only makes the same data public earlier at the front-runner's expense. Repeated identical publication cannot delay maturity, occupy an ID with different data, erase a miss, or create a reward.

Proven storage scope: every call has bounded execution and writes. The total number of paid records can grow with total L1 use; this is not a claim of constant lifetime storage. State growth, archival access and gas repricing remain L1 resource assumptions. A spammer must pay for each publication and new record, but paid spam can still consume bandwidth. No honest peer is required to execute or prove every staged candidate; the public lead gives a funded entrant time to inspect and prove its selected candidate.

Open launch checks: benchmark both modes at the launch fork, including intrinsic/data-floor gas and storage. The 4,000,000-gas availability-response quote elsewhere is not a measured staging cost. Confirm descriptor/body parser vectors, exact blob field encoding and the circuit's full KZG-to-body relation. The registry itself cannot read opaque blob payload bytes, so no stage-time claim of semantic decoding is made.

4. Publication history, expiry and reorgs

getFirstPublication(contextHash) records the earliest successful publication of that exact complete context, independent of salt, stager or later canonical success. It is permanent evidence for publication-by covenants. getStage(stageId) is the particular immutable receipt used for a canonical attempt or proof job. These lookups serve different purposes: a new salt may create a new maturity interval, but cannot rewrite when the context first became public.

Staging expiry removes eligibility; it does not delete receipts, unlock a promise early or erase evidence. Ordinary APIs have no reset, prune, manual timestamp, cancellation, rescue-owner or record-overwrite selector. Honest upgrades preserve these records and the historical domain/key meanings needed by outstanding duties. The existing DAO upgrade trust assumption still applies.

Proven expiry interaction: a real fixed origin predates staging. With both origin age and staging age capped at 900 seconds, a stage that has expired also has an expired origin. A fresh salt alone cannot revive that execution context. Refresh the origin and affected anchors, queue snapshot, body and proof as required; a new context then has a new public-data interval. Even before expiry, a stage first published more than 540 seconds after its origin cannot mature for 360 seconds before that origin expires. Generic staging may record such unusable work, but clients and jobs reject infeasible timing rather than assuming the registry guaranteed success.

Assumed A-DA: the launch network's blob retention and retrieval service cover at least the 900-second maximum usable stage age plus the stated retrieval margin. Verify the actual launch-fork policy; do not convert a block-count retention rule into a fixed number of seconds without a valid bound. Final acceptance publishes the identical data again for canonical history. Long-term canonical reconstruction still needs A-ARCHIVE. Calldata mode uses ordinary L1 historical calldata availability and its smaller body cap; a large blob segment cannot be replaced by a hash-only calldata fallback.

Proven under A-L1: an L1 reorg removes registry writes, first-publication records and dependent accepted transactions in that reverted history. A stage receipt on an orphaned branch is not evidence in the replacement state. If the data transaction is included again, that new canonical inclusion supplies the receipt time; nodes recalculate maturity and respect canonical state. Reorg-finality risk is not removed by a signed timestamp. A finalized stage still does not force L1 to select its candidate.

5. Exact atomic acceptance match

Project StageContext from the submitted complete statement and recompute contextHash. Require s.taskHash=contextHash, a live getStage(s.stageId) with that exact context hash, and publishedAt+360 <= now <= publishedAt+900. Publication time is read from immutable registry state, not supplied as a proof witness. Check arithmetic in full width. The chosen salt need not be passed again: the recorded ID/context association was checked when created and is immutable.

Then require full same-mode republication: blob mode checks the actual current transaction's versioned hash equals the staged context's hash and its exact one-blob rule; calldata mode checks all bytes against the same body hash and size. The ZK proof binds the canonical body encoding, every context field, computed KZG/versioned hash in blob mode, block-hash tree, exact old head, origin, forced prefix and all additional statement fields. Require origin age at most 900 seconds and the core timestamp rules. The stage cannot replace an execution proof, import another origin, choose a new order or waive forced work.

Verify the explicit producer authorization below and ordinary reward/job authorizations. Only then atomically consume the exact current parent, record the complete immutable accepted receipt, credit the specified ledgers and publish the proven checkpoint to the existing SignalService address. Any failure reverts the entire canonical action. Staging never calls SignalService, Anchor, Bridge or Vaults; their retained addresses and root provenance are unchanged.

Proven: a freely copied stage or proof cannot redirect its proof-bound beneficiary. The producer's endorsement cannot be inferred from who staged, relayed or paid. Existing frame-transaction and ordinary-transaction transports may carry the final action; EIP-8141 is not necessary to observe staging age or to keep publication permissionless.

6. Producer assent, keys and historical receipts

The final statement's address producer names the accountable canonical endorser. It need not equal the fee beneficiary, prover, stager, transaction sender or payer. An attacker cannot assign a victim as producer without authenticating that victim's assent to the exact statement.

keyId=0 uses a direct canonical secp256k1 signature recovered to the nonzero s.producer. For a nonzero key ID, the registry record must already exist, be active at acceptance and have owner=s.producer; recover its immutable nonzero signing key. An EOA or contract can register a key by its own authenticated call, with owner=msg.sender; no incumbent approval or token stake is required. Allocate never-reused nonzero key IDs with checked increment. Only the recorded owner can revoke a key for future acceptance. Rotation registers a new record; it never rewrites an old owner or key. Contract owners do not depend on mutable ERC-1271 decisions at evidence time.

Require a 65-byte signature, v in {27,28}, nonzero r/s, canonical low-s, and nonzero recovered address. Verify the typed domain, exact complete statement hash, stage ID equality and chosen key. No nonce is needed for a distinct exact parent-consumption action: the statement binds revision and old head, and the Inbox consumes that head once. Signature replay cannot select another body, stage, payout, job or producer. Revoking a still-unused key prevents future acceptance under it; it cannot erase an authorization already checked in an immutable receipt.

The accepted receipt records at least statementHash, oldHeadHash, newHeadHash, beneficiary, taskHash, jobId, stageId, producer, producerKeyId, producerAuthorizationHash, revision, firstL2Number, endL2Number, blockHashesRoot, acceptedAt, acceptedL1Number. Here producerAuthorizationHash is the typed structure hash above; the receipt attests that its signature and active owner/key conditions were successfully checked at acceptance. Historical evidence uses that checked identity and immutable signing key, not today's activation state. The execution domain is reconstructed from receipt revision and the fixed chain/contract scope, or checked against the complete exact statement preimage.

Proven — no beneficiary framing: naming Alice as a beneficiary creates no evidence that Alice endorsed the task. The mandatory producer authorization is what attributes the accepted execution to Alice. A third party naming Alice but lacking her valid authorization fails before canonical state effects. Compromise of an active authorized key remains its owner's named key-security risk; revocation provides a permissionless prospective response without changing historical liabilities.

7. Ordered block hashes and exact conflict evidence

The validity program derives every block hash from its proved execution. It constructs exactly 64 leaves, with one real leaf per segment block and deterministic padding. The actual count is N=endL2Number-firstL2Number+1, constrained to 1…60. All tags and integers below use the shown ABI types.

treeDomain = keccak256(abi.encode("ETNA_BLOCK_TREE_V1",
    s.domain, s.revision, s.oldHeadHash, s.firstL2Number, s.endL2Number));

// Real leaf i, 0 <= i < N:
leaf[i] = keccak256(abi.encode(uint8(0), treeDomain, uint8(i),
    uint48(s.firstL2Number + i), bytes32(provedBlockHash[i])));

// Padding leaf i, N <= i < 64:
leaf[i] = keccak256(abi.encode(uint8(2), treeDomain, uint8(i)));

parent(left, right) = keccak256(abi.encode(uint8(1), left, right));
// Combine adjacent pairs through exactly six levels.
s.blockHashesRoot = root;

// Evidence supplies index i and exactly bytes32[6] siblings.
// Require i < N and claimedHeight = firstL2Number + i.
// For level 0…5, bit (i >> level)&1 chooses left/right order.
// The recomputed root must equal the accepted receipt's blockHashesRoot.

There is no sorted-pair convention, variable-depth proof, omitted padding, duplicated-leaf shortcut or reporter-supplied unverified header list. Leaf tags distinguish actual blocks from padding and interior nodes. Index, height, full domain and exact segment range prevent a membership proof from being reused for another position or branch context. The terminal real leaf must equal the statement's proved terminal block hash under the same execution program.

Proposed precise offense: an authentic bonded publisher claim X and an accepted block Y conflict only when X's collateral owner equals the receipt's authenticated producer; their revision matches; X.baseHeadHash=receipt.oldHeadHash; their L2 height is equal; and their proved/signed block hashes differ. The reporter supplies X's ordinary signature plus this bounded Y-membership proof. Check X's evidence window and unslashed reserved position; slash only X's existing 10-TAIKO position once, with the existing 10% reporter/90% sink split. An unbonded canonical producer is not given an invented additional collateral balance.

Proven scope: another owner winning a valid fork is not evidence against X's publisher. Distinct payments, jobs or segment lengths are not conflicting block hashes. If Y does not include X's height, this predicate is absent. A claim's bucket base remains its stated canonical base, while a later pipelined segment may have a different immediate parent; no unbounded ancestry search equates them. This exact-context rule therefore has cross-segment/pipeline and cross-owner false negatives. Independent universal staging eligibility applies to every canonical segment and does not depend on extending that slashing attribution.

This is a distinct reserved publisher promise issued when the exact sealed context is known. The accountability contract applies ordinary bucket owner/key/domain/revision/base/range checks and issuedAt within the preexisting 60-second issuance window. The claim's base matches its bucket; it need not equal the promised context's immediate parent, because a sealed pipelined segment may name a predicted future parent. This promise is to publish exact data, not to assert that parent is already canonical. The signer promises the identified complete context; the client checks its public descriptor, recomputed context hash and exact body commitments before accepting the promise. A random unauthenticated hash cannot create someone else's liability.

At now>publishBy, anyone may submit the authenticated claim as evidence. Absence of a context publication receipt, or an immutable first publication strictly later than the deadline, establishes default. A timely stage by any address and any salt satisfies it. A late stage never rewrites first publication or cures default. Reserve, evidence horizon, repeat-report, pull-payment and 10%/90% accounting follow the accountability specification; no additional insurance is minted. At exactly the deadline publication remains timely. Signed issuedAt is bounded by a recorded window, not proof of real-world signing time.

Required binding boundary: an early block-fragment keccak digest is not a later sealed segment's versioned blob hash. Every version-2 early DutyClaim instead has its own absolute issuedAt+240 deadline: actual fragment calldata plus the exact FR preimage must appear through the publication registry. The already-computable FR is independent of the future segment boundary. A sealed claim binds its complete context only after that context and DA commitment are computable. Generic stage receipts never implicitly satisfy an early fragment receipt: the separate exact-publication predicate in accountability is required. No unverified blob membership assertion is credited.

10. Everyone offline, malicious stages and permissionless recovery

If every existing publisher, custodian and worker disappears, a new entrant needs no permission from them. It retrieves the latest accepted canonical state and data under A-ARCHIVE, and may either use still-available staged data or construct another valid child. It stages the complete new context, prepares a proof, waits for maturity and submits with the current canonical rent. If it waits until the900-second rent decay reaches zero, it must retain or construct a still-fresh origin and stage; zero rent never revives an expired proof. A missing staged body, absurd stage descriptor, failed optional job or unavailable old soft suffix never reserves the head. If every capable prover everywhere is unavailable, progress stops until one returns; staging cannot manufacture a proof.

Nodes keep unavailable soft dependencies UNKNOWN and stop confirming that branch. Recover from available canonical state rather than synthesize missing bytes. Existing serving and publication duties remain independently settleable; losing a canonical race neither creates an automatic misconduct slash nor cancels an already missed publication duty. Once a recovered child consumes the parent, old competing proofs are stale. An old stage, signature or witness certificate cannot overwrite the new head.

Proven: this avoids both an unavailable candidate holding recovery hostage and an attacker using an ordinary competing winner to slash an honest loser. It cannot promise that the entrant's preferred optional transactions win; the parent-frozen force prefix supplies the separate censorship escape. Malicious data staging costs L1 resources but can still impose inspection load, so nodes bound parsing and choose work by explicit policies.
