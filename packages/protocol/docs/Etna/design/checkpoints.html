Etna · proposed normative module · reviewed in rounds 07–08

An origin hash, then an ordinary checkpoint reveal

Standard Ethereum system calls record block history. Anyone can preserve an authenticated L1 origin and reveal its complete checkpoint with ordinary paid transactions.

Proposed specification, not deployed behavior. This module replaces Etna's signed anchor transaction and custom activation transaction. It follows David's requirement to keep the pre-execution call strictly standard EIP-4788. Pins and reveals are optional ordinary transactions. No transaction-zero reservation, fee exemption, anchor gas reserve, custom system call or automatic SignalService write is added.

Classification: every normative rule, parameter and ABI below is proposed under A-IMPLEMENTATION. Proven marks a deduction under the cited premises, not an executed implementation test. Assumed marks environmental, cryptographic or migration premises. Open marks unverified launch evidence. This page is authoritative for L2 origin persistence and checkpoint reveal. The codec controls header validity and the migration controls the authenticated boundary, shared custody and contract installation. Rounds 07–08 conditionally reviewed the anchor-removal snapshot; see the historical adjudication and its evidence limits. The storage analysis below clarifies those existing rules without adding a fee, retention limit or new interface. Historical acceptance of the state-growth risk does not establish an affordable production profile.

1. One authenticated hash, three availability states

Every Etna L2 header sets parentBeaconBlockRoot = segment.origin.hash, the exact nonzero hash of the segment's authenticated L1 execution header. Derivation, local validation in a named L1 view and the complete validity program enforce this equality. The segment origin is fixed before staging and execution. An arbitrary nonzero word is invalid. On Etna this field is an execution-block hash, not an Ethereum beacon SSZ root, randomness or proposer lookahead.

Before ordinary transactions, unmodified EIP-4788 writes that word into its canonical timestamp ring. Anyone may immediately call revealCheckpoint(t, header) while timestamp t > 0 is still readable. Alternatively, pinCurrentOrigin() permanently records the current hash, then revealCheckpoint(0, header) reveals against that pin at any later time. Persisted checkpoints use the existing SignalService mapping and CheckpointSaved event.

Proven under A-CRYPTO/A-IMPLEMENTATION: the temporary ring and permanent pin authenticate the same exact hash. Hashing the complete revealed header binds its number and state root. No additional trusted relayer, fixed signing key or independently asserted checkpoint root is introduced. Canonical provenance still depends on the proof's origin equality and the authenticated L1 history; EIP-4788 alone cannot establish which L1 block should have been selected.

2. Standard system-call boundary

Operation Input and state effect Limits
EIP-4788 at 0x000F3df6D732807Ef1319fB7B8bB8522d0Beac02 Caller 0xfffffffffffffffffffffffffffffffffffffffe; raw 32-byte header root; zero value; 30,000,000 call gas. At i=timestamp%8191, store timestamp at i and root at i+8191. Before all ordinary transactions; no ordinary signed envelope, nonce increment or receipt; outside ordinary block gas accounting. Real state writes remain in the state root and proof.

The standard calls have no ordinary transaction fees or synthetic log/receipt. Ordinary pin/reveal calls do. Etna runs EIP-4788 then EIP-2935, before ordinary transactions, as specified by the execution profile. Building, importing, reexecuting and all proving programs must agree on that order and exact state effects; source conformance and deployment parity remain launch checks. Preserve upstream genesis behavior: no EIP-4788 system operation and a zero root at genesis; the first Etna upgrade block is a non-genesis block. Standard no-code behavior is silent, so deployment/runtime verification is a prerequisite to usable oracles. Do not replace it with a custom Taiko consensus failure rule.

Proven ring bound: a timestamp t cannot collide with a distinct greater timestamp t' while 0<t'-t<8191. At t+8191 its slot may be overwritten after only one successor block if timestamps jump. Strictly increasing Etna timestamps rule out equal-timestamp overwrites. An exact two-second cadence happens to yield a longer cycle, but neither 8191 arbitrary blocks nor 4.5 hours is a guarantee. These are L2 timestamp differences, not promises about wall-clock inclusion.

The EIP system caller has no known signing authority available to users. Ordinary transactions recover their own sender. EIP-7702 recovers the authority that grants delegation; naming the system address as a delegation target does not grant its execution identity. Delegatecalling oracle code from another account does not mutate the canonical oracle's storage. Authenticate the exact canonical runtime and preserve standard EVM call rules. The retired public legacy sender receives no privileges or additional Etna identity ban after writer retirement; its ordinary transactions pay all ordinary fees.

3. Exact ordinary contract interfaces

Add this interface at the existing L2 SignalService proxy. Return types below are part of the ABI. Mutating methods are nonpayable. Existing getCheckpoint(uint48), signal methods, legacy HopProof encoding and CheckpointSaved remain unchanged. The explicit implementation mode is immutable: L1 rejects both mutations; the L2 implementation accepts them only under the current nonzero-root guard below.

interface IEtnaCheckpointStore is ICheckpointStore {
    /// @notice Emitted once when an authenticated origin hash is first pinned.
    /// @param originHash The exact L1 execution block hash recorded on L2.
    /// @param l2Timestamp The L2 execution timestamp at which it was pinned.
    event OriginPinned(bytes32 indexed originHash, uint64 indexed l2Timestamp);

    /// @notice Permanently pins the origin of the current L2 block.
    /// @dev L2 Etna mode only; reads the standard current-timestamp oracle.
    /// @return originHash_ The nonzero authenticated execution-block hash.
    function pinCurrentOrigin() external returns (bytes32 originHash_);

    /// @notice Reports whether this proxy has permanently pinned an origin.
    /// @dev Informational getter; it does not establish the current origin.
    /// @param _originHash The L1 execution-block hash to query.
    /// @return pinned_ Whether the permanent pin exists; false for zero.
    function isOriginPinned(bytes32 _originHash) external view returns (bool pinned_);

    /// @notice Persists an authenticated L1 checkpoint from its complete header.
    /// @dev Timestamp zero uses a permanent pin; positive timestamps use 4788.
    /// @param _l2Timestamp The recording timestamp, or zero for a pinned hash.
    /// @param _l1HeaderRlp The exact canonical complete L1 execution header.
    /// @return checkpoint_ The new or identical existing checkpoint.
    function revealCheckpoint(uint64 _l2Timestamp, bytes calldata _l1HeaderRlp)
        external returns (Checkpoint memory checkpoint_);
}

The inherited event remains CheckpointSaved(uint48 indexed blockNumber, bytes32 blockHash, bytes32 stateRoot). Emit it only when a fresh checkpoint record is written. Repeated identical pins/checkpoints return successfully with no duplicate event and no change. Conflicting checkpoint data always reverts. The pin event records when persistence occurred, not an independent L1 number or evidence of canonical finality. The getter is informational and may be called in either mode; L1 has no valid pin writes.

No new role: there is no registration, bond, assigned pinning duty, reward, subsidy, per-origin owner or exclusive relayer. Anyone may pin/reveal or stop. The caller pays ETH for ordinary execution, calldata and storage under Etna's normal fee rules. Those fees are not an irreversible storage charge: an integrated caller and coinbase can recover them under the 100% coinbase allocation. An invalid call reverts and pays normal failed-transaction gas; this is not slashing. Protocol head advancement and empty blocks do not depend on a pin/reveal being present. Optional builder pin/reveal policies carry no consensus privilege.

4. Current-root guard and bounded canonical reads

The immutable deployment mode is exactly L1_INBOX or L2_ORIGIN. It cannot be inferred from an RPC chain label or the contents of a hash. Pin/reveal first require L2_ORIGIN, then require a successful current read read4788(block.timestamp) != 0. L1 saveCheckpoint keeps its exact Inbox caller authorization and does not use the L2 oracle. L2 legacy saveCheckpoint and every old Anchor write selector retain their legacy caller checks and additionally require a successful current read equal to zero. Missing or malformed reads always revert; they never select legacy mode.

BEACON_ROOTS = 0x000F3df6D732807Ef1319fB7B8bB8522d0Beac02
ORACLE_READ_GAS = 100_000
EXPECTED_4788_CODEHASH = keccak256(exact canonical EIP-4788 runtime bytes)
    // immutable, authenticated in the migration manifest

read4788(t):
    require t != 0
    require EXTCODEHASH(BEACON_ROOTS) == EXPECTED_4788_CODEHASH
    STATICCALL with gas operand ORACLE_READ_GAS, destination BEACON_ROOTS,
        input exactly uint256BE(t), input size 32, output buffer size 32
    require call succeeded and RETURNDATASIZE == 32
    return the one returned bytes32 word

requireL2Etna():
    require implementationMode == L2_ORIGIN
    h = read4788(block.timestamp)
    require h != 0
    return h

Allocate only the fixed 32-byte oracle output buffer and check actual returned size before interpreting it; do not copy unbounded return data. read4788 accepts a zero returned word because the legacy guard needs that exact value; callers in Etna mode reject it. Positive reveal timestamps also require _l2Timestamp <= block.timestamp and a nonzero returned word. Timestamp zero is an API discriminator and is never sent to the canonical oracle. Reuse the current result if the supplied positive timestamp equals block.timestamp. The current root is not required to equal an older valid pin/reveal hash.

The 100,000 limit is a bounded ordinary STATICCALL budget, not a gas credit or the EIP's 30,000,000 system-call limit. Caller gas still pays the call and EIP-150 limits apply; insufficient gas fails closed. Open preflight: measure canonical code checks and both cold SLOADs under the exact selected fork. A later L2 gas repricing that makes this cap insufficient needs a reviewed contract/execution revision before activation. Upstream EIP-2935 account/storage accesses remain cold for the first ordinary user call.

Proven first-block gate under A-IMPLEMENTATION and the authenticated migration: legacy headers record zero and Etna headers record the exact nonzero origin. Standard 4788 executes before all ordinary transactions, so the legacy Anchor and SignalService writer guards fail from the very first Etna transaction. No optional pin, reveal or L2 phase-flip transaction controls this boundary. The old ancestors-hash coincidence cannot reopen it. The migration manifest and rehearsal must cover all inherited/fallback selectors and deploy the exact EIP code only after builder/importer/guest parity is established.

5. One new namespace; preserve all historic mappings

The sole new mutable protocol state is mapping(bytes32 originHash => bool pinned) pinnedOrigins in a dedicated ERC-7201 namespace. Its exact namespace ID is taiko.etna.origin-pins.v1. Define the root slot and mapping locations exactly as follows, with subtraction on uint256 before the outer hash:

P = keccak256(abi.encode(
        uint256(keccak256(bytes("taiko.etna.origin-pins.v1"))) - 1
    )) & ~bytes32(uint256(0xff))

struct OriginPinsStorage { mapping(bytes32 => bool) pinnedOrigins; }
// The storage struct begins at P; its only mapping uses slot P.
pinnedOrigins[h] uses keccak256(abi.encode(bytes32(h), bytes32(P))).
// Canonical bool word: 0 = not pinned, 1 = pinned.

pinCurrentOrigin() obtains h=requireL2Etna(). If the pin already exists it returns h. Otherwise it stores true and emits OriginPinned(h,uint64(block.timestamp)). The cast is safe because Etna's header timestamp already fits uint48; implementations still enforce the selected header bound. No public method clears or transfers a pin. A new implementation must preserve the namespace unless a separately reviewed history migration explicitly says otherwise. Reorgs revert pins and checkpoints as ordinary state: persistence means permanence within the accepted chain history, not immunity to reorganization.

Existing SignalService linear slots remain untouched: Pacaya reserves at 251–252, received-signal cache mapping at 253, checkpoint mapping at 254 and the existing gap beginning at 255. Keep VERSION=1 and both existing nested-key encodings. An API/proof-envelope version is not permission to invalidate the historic checkpoint/cache namespace. The existing checkpoint mapping value remains CheckpointRecord{bytes32 blockHash,bytes32 stateRoot}, keyed by uint48 number, not the larger external Checkpoint struct. No new latest-checkpoint counter, number mapping or automatic storage write is required.

The current checkpoint mapping and verification helpers are private. A shared internal helper/visibility refactor is permitted when it preserves storage shape and authorization; an L2 subclass cannot simply reach private storage. SignalService and retained Anchor keep their existing proxy addresses and inherited/fork-router layouts. Anchor's old mapping and block-state slots are frozen, not reused. Namespacing new state does not excuse skipping generated before/after layout checks.

6. Exact reveal algorithm and parser

  1. Require explicit L2 mode and successful nonzero current oracle root. Require 0 < headerRlp.length <= 1536. Compute h=keccak256(the exact complete headerRlp); require h != 0.
  2. Parse one complete canonical RLP list with 12–32 top-level scalar byte-string fields. Validate list/item lengths before allocation, reject trailing bytes and nested lists, and reject nonminimal length encodings. Extract parentHash at item 0, stateRoot at 3, number at 8 and timestamp at 11. Require both hashes to have exactly 32 payload bytes; stateRoot must be nonzero. Number and timestamp are minimal unsigned big-endian integers fitting uint48 before casting. Zero is an empty byte string; nonempty integers have at most six bytes and a nonzero first byte. Never truncate an oversized integer or accept byte 0x00 as canonical integer zero.
  3. The resulting checkpoint is {blockNumber:number, blockHash:h, stateRoot:stateRoot}. Look up _checkpoints[VERSION][number]. If either persisted field is nonzero, require both nonzero and both exactly equal the new fields, then return the existing checkpoint without writing/emitting. This idempotent return uses the existing authenticated record and does not depend on its recording timestamp remaining in the ring or on a pin having been created.
  4. For a fresh record, if the timestamp is zero require pinnedOrigins[h]. Otherwise require a nonfuture timestamp, read standard 4788 at that timestamp, and require the returned nonzero hash equals h. Do not silently fall back from an expired positive timestamp to the pin path: the caller selects timestamp zero explicitly. Store the two nonzero fields, emit the existing CheckpointSaved and return the new checkpoint. A positive reveal does not implicitly create a permanent pin.

Do not compare the revealed L1 number to the executing L2 block number. Do not require an older pinned header's timestamp to equal the current origin timestamp. Authentication comes from the full hash and its permitted provenance path. The stable-prefix parser is identical in limits and scalar decoding to the L1 HeaderStore parser; its source of authenticated hashes differs. All suffix fields remain committed by the complete-header hash. A future L1 header with more than 32 fields, more than 1536 bytes, nested/noncanonical fields or a changed stable prefix cannot be selected until a reviewed parser revision supports it. The current module does not invent that future suffix schema.

Out-of-order valid reveals are allowed. Repeating a number with a different hash or root fails; neither timestamp order nor permissionless caller identity permits overwrite. An existing nonzero hash with zero root, or the converse, is an invalid stored record and fails closed. The existing getCheckpoint missing-record check remains, and both persisted and newly revealed checkpoint uses retain explicit nonzero-root validation. Corrupt history is a migration/audit failure, never an excuse to accept a zero proof root.

Proven under A-CRYPTO/A-IMPLEMENTATION/A-L1: any newly revealed tuple is bound to an authenticated execution-block hash that previously appeared as an Etna origin in this L2 history. Pinning before revealing cannot change that hash. This proof also requires that L1 mode rejects reveals explicitly; the absence of an easily found header preimage for an L1 SSZ root is not the security boundary.

7. States, ordinary failures and examples

Persistence state machine for a particular nonzero origin hash h
State / transition Successful result Failure / expiry
Absent → temporary Standard system write in a block whose header names h; read by that block's timestamp. Invalid origin equality makes the block invalid. Missing canonical deployment prevents relying on the oracle.
Current temporary → pinned Any valid paid pinCurrentOrigin() stores h permanently; duplicate is idempotent. Wrong mode, zero/current unreadable root, bad code hash or insufficient execution gas reverts. Pinning selects current h only.
Temporary → checkpoint Positive-timestamp reveal verifies the complete header and writes unchanged checkpoint format. Overwritten/missing timestamp, future timestamp or wrong header fails. Ring expiry does not erase an already persisted checkpoint.
Pinned → checkpoint Timestamp-zero reveal verifies the complete header against the permanent bool pin. Unknown hash or malformed/conflicting checkpoint fails. This authentication path has no ring expiry.
Checkpoint → bridge proof Existing nonzero number/root lookup and ordinary account/storage proof verify the signal. Missing signal, wrong remote service, invalid proof or Bridge constraints fail independently.

Success example: block timestamp 100,000 records authenticated origin hash H. A paid pinCurrentOrigin() in that block stores H. By timestamp 108,191 a different root can occupy the same ring residue. At timestamp 120,000 a caller submits revealCheckpoint(0,headerH); the pin authenticates H despite that overwrite. A fresh matching checkpoint emits CheckpointSaved. The caller then submits the unchanged bridge proof against that number/root.

Expiry example: without a pin or checkpoint, revealCheckpoint(100000,headerH) after the collision fails its oracle read. It cannot claim that the stale hash remains current. The caller can reveal another live origin whose state actually contains the signal, or first pin a suitable current origin. If no checkpoint exists, a stale positive-timestamp request remains stale even if the same hash was independently pinned; resubmit with timestamp zero to select that path. An already persisted identical checkpoint returns idempotently without the historical oracle read.

Delayed forced request: a funded caller queues a valid ordinary transaction whose data is only pinCurrentOrigin()'s four-byte selector. At processing, it pins H2, the processing block's origin, regardless of how long the queue waited. The processing L2 header supplies H2 through parentBeaconBlockRoot, and isOriginPinned(H2) confirms persistence. A first-pin event supplies the same hash/timestamp when emitted; an already-pinned origin succeeds without another event. The caller retrieves the matching complete L1 header, then queues a valid revealCheckpoint(0,headerH2) without an oracle deadline. A wrong nonce, insufficient balance/fees, execution out-of-gas or other invalid transaction outcome does not produce a pin: the forced path still follows the existing inclusion/outcome rules.

Failure example: an attacker supplies a header containing a fabricated state root, or uses an EIP-7702 transaction hoping to impersonate the system caller. The fabricated complete header does not hash to a permitted authenticated origin; naming a delegation target does not manufacture its authority. Both fail under the standard cryptographic assumptions. A funded ordinary transaction from the old public legacy sender cannot use its retired checkpoint-writing privilege because the current nonzero gate closes that path before transaction execution.

Proven byte bound: for a 1536-byte header, revealCheckpoint(uint64,bytes) calldata is 4+64+32+1536=1636 bytes (selector, two ABI head words, dynamic length and padded bytes). Its RLP string prefix adds three bytes. Bounding chain ID and both fee integers by 33 encoded bytes each, the uint64 nonce by nine, gas limit ≤1,000,000 by four, destination by 21, zero value and empty access list by one each, parity by one, and signature scalars by 33 each gives 99+9+4+21+1+1639+1+1+66=1841 payload bytes. Add the outer list's three-byte prefix and one-byte transaction type: 1845 bytes ≤2048. Narrower runtime chain/fee fields only reduce this conservative bound. A future transaction-envelope change must recompute it.

Assumed liveness: the existing affordable L1 inclusion, canonical progress, forced-queue processing, funded valid transaction and data/archive premises must hold. A dedicated funded sender with no competing nonce use and a fee cap covering the fixed 1-gwei basefee maximum supplies a constructive ordinary submission strategy; keep enough balance for the full gas purchase and fee policy. A successful pin removes the ring's deadline for the subsequent reveal. It does not guarantee pin inclusion by itself, supply a missing L1 header/state proof, ensure an already-sent signal remains at the configured remote service forever, or make an oversized bridge proof fit the queue. To bridge an older signal using a later checkpoint, establish that the later authenticated remote state still contains that signal. The current append-only signal write supports that use within the preserved service history; arbitrary future storage upgrades require separate analysis.

Fresh pin/reveal SSTOREs and RLP parsing cost real execution gas. Neither the original 40k estimate nor the later approximately 100k discussion is a measured bound for this module. The fixed forced-call envelope must pass worst-case cold-state, maximum-header and duplicate/conflict preflight measurements before launch. Do not treat the former 1,000,000 anchor reserve as funding these calls: it is removed.

8a. Permanent-state budget and unresolved pricing

Conditional deduction from the specified provenance rules: let N be the number of accepted Etna segments after activation in one canonical history. Each segment supplies exactly one authenticated origin to all its blocks. A fresh pin accepts only the current origin; a fresh checkpoint accepts only a recorded origin or an earlier pin. Therefore those N segments can introduce at most N distinct origin hashes, at most N new pin value words and at most 2N new checkpoint value words: at most 3N additional 32-byte values. Repeated callers, addresses and transactions cannot multiply entries for the same hash or checkpoint number. Discarded speculative branches do not persist in this accepted state. The preserved legacy state is a separate fixed baseline. This bound relies on the exact origin/proof binding and current-root writer gates; it does not count sent signals, received-signal caches, other contracts or other protocol ledgers.

Assumed example, not a protocol rate cap: one accepted segment with a distinct origin every 60 seconds for 365 days gives N=525,600. Pin values alone occupy 16,819,200 raw bytes; all pin and checkpoint values together occupy at most 50,457,600 raw bytes. These counts exclude storage keys, trie nodes, database overhead, witnesses, logs, receipts, archive history and any implementation amplification. The protocol has no fixed lifetime N cap. L1 interval changes require new operating scenarios, not a slot-based admission rule.

Unresolved economic concern: a producer that also controls the transaction payer and coinbase can recycle ordinary L2 basefee and tips. Proof, L1 data, rent and execution costs remain, but paying L2 gas alone does not internalize permanent storage cost. Charging only pinCurrentOrigin() would also leave a bypass for general origin-state growth: a positive-timestamp revealCheckpoint creates two permanent checkpoint words without any pin. A tariff limited to these two APIs would still not price all other application or SignalService state.

9. Existing bridge interface and consumer migration

The initial version deliberately keeps existing HopProof[] encoding and empty cached proofs. It adds no extended-proof envelope, embedded header reveal or view-only virtual checkpoint. A caller first uses an already persisted checkpoint or completes an ordinary reveal, then calls the existing prove/verify/Bridge path. The exact number and root used by the hop must match the persisted checkpoint and both hash/root must be nonzero. Preserve proveSignalReceived's current return value 0; a reveal's SSTORE count is not a cache-operation reimbursement count.

Bridge's proxy/custody address, replay/status data, message commitments, remote SignalService and immutable local SignalService reference stay fixed under migration. A standalone pin/reveal is not measured inside the subsequent Bridge.processMessage gas accounting and receives no automatic reimbursement from that claim. Users/relayers must fund it or arrange ordinary off-protocol payment. No generic wrapper changes Bridge's msg.sender or owner/relayer semantics. Existing 200,000-byte relayer proof limits, target gas requirements and queue transaction bounds remain independent.
