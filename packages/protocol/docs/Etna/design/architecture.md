# Etna draft architecture and normative coordination brief — revision 0

Status: **draft for falsification, not ready**. This is the common specification used by the design pages. Page-level refinements must be reconciled here before review. Strict based interpretation is the default pending user clarification; an independent canonical sequencing committee is not silently introduced.

## Chosen boundary

Canonical sequencing remains an always-open L1 race between complete, proof-bearing segments extending the exact accepted head. Any address may submit; no service ticket, committee certificate, prover assignment or private relay is required. ZK proof + canonical DA + forced FIFO obligations are mandatory. Preconfirmation publishers and availability custodians are voluntary bonded services for a provisional branch. Their certificates establish attribution and data-serving obligations, **not irreversible canonical ordering**. Nodes execute each full preconf immediately against a known parent/L1 view, returning VALID/INVALID/UNKNOWN; a missing parent is UNKNOWN. A soft head may be displaced by another valid L1 submission even if its publisher is honest. This limitation and whether historical private-before-landing withholding satisfies the brief are explicit red-team targets; do not claim R6 already passes.

## Canonical data and state

- Genesis/migration head `H = (revision, segmentNumber, l2Number, l2BlockHash, l2StateRoot, l2Timestamp, forceCursor, nextForceCut, nextForceTime, segmentCommitment)`. Hash all fields in canonical ABI encoding with chain IDs and Inbox address. No hash truncation.
- A `Segment` contains exact old head, canonical list of at most 60 L2 block headers/bodies (total encoded bytes ≤122880), terminal head, fixed L1 origin header, next force snapshot, derivation revision, proof beneficiary, and optional service reward authorization. No field is derived from future landing timestamp, L1 transaction sender or unknown future proposal ID. Parent segment number +1 is deterministic.
- One-second timestamp increments for a contiguous live preconf branch; gaps are allowed after halt. Every block timestamp >parent timestamp and ≤origin.timestamp+60; last timestamp must also be ≤landing block.timestamp. The origin used to seal/prove must be no older than 600 seconds at landing and strictly advance relative to the parent segment's origin. A proof can expire under congestion; this is an explicit bounded-liveness assumption, not instantaneous invalidation by new queue entries. The head includes originNumber/originHash; the statement and accepted receipt include taskHash and jobId (zero for no job); firstConsumedAt/parentConsumption are permanent historical receipts. Revision activation records an immutable retirement timestamp for the old revision so before-deadline retirement can cancel inapplicable voluntary jobs, never erase an earlier default.
- L1 HeaderStore is a new permissionless helper, not a frozen shared address. `pinHeader(RLPheader)` verifies keccak(header)=EVM BLOCKHASH(number) while available, extracts number/hash/stateRoot/timestamp using fork-versioned canonical header parsing, and stores the tuple immutably/idempotently. Only n<block.number, nonzero BLOCKHASH. Stored header is canonical in the same L1 history; reorg rolls back pinning when its ancestor changes. There is no CL lookahead or slot arithmetic. Pinning does not publish L2 data or reserve a segment.
- A proof authenticates every L2 anchor's L1 header through an ancestry chain ending at the pinned origin; all anchors nondecreasing and ≤origin. Bind chain IDs, Inbox, Anchor, code/verifier revision, full old/new heads, exact data commitment and actual blob hashes/calldata hash, forced entries/outcomes, L1 origin, beneficiary and service rewards. It proves EVM execution, header/hash/receipt/gas validity and every first system anchor transaction. No TEE-only path or mutable owner-selected verifier allowlist; circuit key is immutable per implementation revision, DAO may upgrade the implementation.
- Ordinary type-3 blob transaction or calldata transaction calls one `submitSegment` action. Preferred EIP-8141 four-frame action is only an optional direct-builder optimization: scoped contract sender, payer approval, SENDER submit, terminal VERIFY of exact successful state effect. Ordinary public fallback always callable. Never give a shared nonce to entry, exit or slashing.

## Forced FIFO without continuously invalidating proofs

- `force(bytes rawL2Transaction)` stores an immutable request record and bytes in L1 calldata plus an on-chain hash, enqueue timestamp and enqueue L1 block number. At most 2048 bytes/request; declared gasLimit ≤1,000,000. Each request has a monotone index. No expiry/privileged voiding. Malformed/state-invalid transactions produce a proved rejection outcome when processed; reverting valid execution counts as included.
- Each accepted head freezes `nextForceCut` = queue tail at its proof's fixed origin block (not at landing), and `nextForceTime` = origin.timestamp. Tail boundary can be checked against append-only enqueue block numbers: record[cut-1].blockNumber≤origin.number and record[cut].blockNumber>origin.number if present; endpoints checked. No new enqueue mutates an existing snapshot. Permanent immutable request metadata supports these checks.
- Every child segment consumes exactly the first up to four still-unconsumed requests with index<parent.nextForceCut and enqueue timestamp+120≤parent.nextForceTime, in FIFO order before discretionary transactions. If more due, later accepted segments continue. A child may not skip a mandatory request or skip ahead. Derive required end cursor in bounded work; circuit proves bytes/outcomes, contract checks cursor/record commitments. Fresh requests cannot invalidate that child's proof.
- The child selects its own next origin/snapshot while being built; that commitment is known to preconf descendants before the child lands. Competing accepted parents can still invalidate a provisional branch. Every canonical successor must advance origin; 600-second freshness prevents keeping old queue snapshots forever. For a queued item, later arrivals cannot increase its number of predecessors.
- Initial force fee 0.001 ETH × (1+floor(pending/50)); no administrator modifies it during operation. Fee becomes a pull credit to proof-bound batch beneficiary when its request is processed. Ethereum gas costs remain ETH; existing L2 native token remains ETH. No guarantee under unbounded L1 gas prices or infinite affordable adversarial load.

## Resource and economic baseline for role pages

- Keep current EIP-4396-style fee calculation and 75% coinbase /25% Anchor allocation; set one-second target as a justified cadence parameter change. Keep a 10,000,000 gas block limit initially, with total segment execution gas ≤120,000,000. Whether the launch engine/prover sustains this at 1 s/180 s is **open** and must be benchmarked; it is not a measured claim.
- Ordinary segment data ≤122880 bytes (120 KiB, fits one blob with 31-byte-per-field-element encoding and a 64-byte length/version header); calldata mode ≤32768 bytes including batch body but excluding bounded proof/metadata, with total transaction envelope ≤65536 bytes and proof bytes ≤16384. If a segment does not fit calldata mode, a smaller segment/proof is required; cannot change bytes under the same proof. One blob maximum initially; optional larger future policy is an upgrade. Proof+all processing must fit 16,777,216 execution gas and applicable state budget; **open launch measurement**.
- TAIKO base units = token-wei, 10^18 per TAIKO; preserve gwei ledger conversion where reusing old bond records. New ledgers use uint256 base units, no ETH/TAIKO oracle. All new service collateral is TAIKO, challenge response gas bonds are ETH with objective basefee quote.
- No mandatory bond for raw proof submission: invalid proof already costs ordinary-transaction gas or uncharged builder simulation on optional private frames. A service worker may voluntarily accept a separately funded proving job. A proof job never reserves canonical submission rights.
- Suggested publisher duty bucket: 60 positions, 100 TAIKO per position =6000 TAIKO reserved. Custodian same 60 positions, 100 TAIKO/position. Each signed duty position binds one immutable payload digest; incompatible signatures slash at most that reserved position once. No unbounded per-user compensation. Positions are obligations, not CL slots. A bucket is registered on L1 before signatures, binding signing key, parent/context, position range and a retention horizon. Exit cannot release reserved balances until evidence/response periods finish. Key rotation has no effect on historic liability.
- Body limit for a custodial availability claim is32768 bytes, served fully in one calldata response. Retention86400s; evidence window604800s; response timeout600s; maximum L1 inclusion delay120s assumed for a conforming funded responder. Claims signed without a valid preexisting reserve are not accepted by clients as bonded. Larger block/body data needs multiple separately reserved claims and explicit client completeness checking, bounded by segment byte cap.
- Challenge admits signed obligation, full digest/length/context, and ETH bond = 2×4,000,000×(block.basefee+2 gwei). Anyone may respond with the complete data before deadline. Keccak/canonical encoding must match claim. A successful response makes data publicly retrievable and permanently satisfies that digest's serving obligation; paid reward goes to actual responder, not the accuser. No repeated paid challenge once revealed. Default after deadline releases challenger ETH bond and slashes the reserved position. False challenge claims fail before state reservation and pay gas. Duplicate evidence is idempotent/no second reward.
- Slashed TAIKO split:10% permissionless reporter,90% permanently excluded from withdrawable accounting (“sink”, not falsely claimed token burn). Self-slashing therefore loses90%; no owner sweep. ETH challenge reward is fee for publication, paid from challenger deposit; it is not newly minted compensation. Full accounting and multiple signer/challenge handling must be specified by the economics page.
- Proving job offer/acceptance: escrow bounty in TAIKO, reserve1000TAIKO worker bond, deadline300s; any proof may land. Pay proof-bound worker if exact task completed; if canonical parent changes incompatibly before deadline, cancel/refund without slashing innocent worker. If task remains applicable at deadline and worker misses, objectively slash reserved bond; fee proceeds reward recovery according to posted immutable terms. Exact output root must be committed before acceptance; no assigner may replace it. No compulsory exclusive worker or TEE identity.
- No ticket auction, exclusive lease or address cap is selected. Canonical exclusivity is zero seconds; there is no finite service capacity to squat. Anti-monopoly guarantees come from open proof rights, mandatory FIFO, and linear collateral per outstanding promise; they do not prove economic actor diversity or prevent an L1 builder cartel. The initial 100-TAIKO/position and seven-day evidence period imply roughly 60.48 million TAIKO for continuous one-promise/second service: this is an explicit economic weakness for review, not a calibrated launch recommendation.

## R1/R2 migration mandate

Reuse all existing Bridge, SignalService and ERC20/ERC721/ERC1155 Vault proxy addresses on both layers. Preserve all existing storage and application authentication. Replace implementations to remove operational pausing/owner mint/token remapping/quota administration/resolver mutation/fee withdrawal; DAO ownership only authorizes upgrades. Contract-only provenance checks (Inbox/Anchor→SignalService, Bridge→Vault) remain mandatory and are not human whitelists. Preserve historic messages, signal slots/cache/checkpoints/version unless a separately proved migration says otherwise. New L1 Inbox/role registry/header helper/frame sender and new Anchor implementation permitted; retain Anchor proxy to ease integration. No live deployment state has been authenticated; exact address/codehash/owner/storage preflight is a launch blocker, not a fabricated migration fact.

## Claims to try to falsify

Safety A-CRYPTO+A-L1+A-UPGRADE: only sound proof/DA/old-head transition publishes a root; service dishonesty cannot forge custody withdrawals. Liveness additionally A-EXEC (some honest capable prover), A-NET, A-L1 inclusion/gas bound, finite mandatory work and economically funded actor. All service publishers/custodians/proof assignees can disappear while open canonical proving/force processing still works if some new prover enters. If every capable prover everywhere stops, progress halts safely.

Withholding: on-chain evidence proves signed equivocation or missed bonded response, not historical gossip intent. An unrevealed private branch with no attributable breached promise can first appear with data+proof and displace a public soft branch. Advisory certificates do not close that attack. False-negative rate for reveal-before-challenge-deadline is100%; persistent failure after an included valid challenge is detected deterministically under L1 inclusion assumptions; false positives can be100% under unbounded censorship. This is the principal possible failure of the user's withholding requirement. Red team/judge must decide against the actual brief; do not silently accept it or announce R6 passed.
