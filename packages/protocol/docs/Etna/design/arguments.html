1. How to read the claims

Proven below means a deduction from the specified rules and named assumptions, or a cited source observation. It does not mean mechanically verified Solidity, a completed circuit audit, or an empirical performance result. Assumed identifies premises the mechanism cannot supply for itself. Open identifies an unresolved obligation and the evidence or decision needed to close it. A-IMPLEMENTATION makes the safety proofs conditional on faithful implementation; it does not prevent an interface-complete design from being reviewed before production code exists. Production implementation is expressly outside this research task. Specification gaps block design readiness; deployment verification and performance benchmarks are separate launch gates. These labels apply to the grouped table rows and numbered arguments as well as their introductions. “Proposed” marks a normative rule assumed to be implemented exactly under A-IMPLEMENTATION, awaiting independent design review; it is not a fourth class of established result.

Proven distinction: an individual block can be locally execution-valid and later lose canonical selection. Local validation answers “does this signed candidate correctly extend this known parent in this named L1 view?” Canonical acceptance answers “did Ethereum accept a valid proof and available data extending the unique Inbox head?” Ethereum finality answers a third question about the containing L1 block. None implies either of the others in advance. One-second issuance and minute-level proof landing therefore do not alone prove an impossibility.

3. Safety proof sketches

S0. Bootstrap gives the first proof one exact parent

Proposed bootstrap rule: the migration specification constructs H0 from the authenticated final legacy height/hash/state root/timestamp and manifest revision, with segmentNumber=0, forceCursor=0, nextForceCut=0, nextForceTime=0, originNumber=0 and originHash=0. Its segmentCommitment is the exact domain-separated bootstrap commitment specified there, not a fictional legacy StageContext. Its head hash uses the same canonical Head encoding. These sentinel values are a single explicit initialization exception, not values chosen by an activation caller.

Proven under the specified bootstrap and A-IMPLEMENTATION: the first Etna statement binds that unique H0. Its real authenticated origin is at or after the activation L1 block and its first system call proves the Inbox ACTIVE state through beginEtna. Because H0's frozen cut is zero, this first segment consumes zero forced requests. Existing inactive-queue records and fees remain untouched, in order. The first successor commits the exact queue snapshot at its real origin; subsequent mandatory prefixes follow the ordinary rule. No later caller can manufacture another sentinel head, reset the cursor, waive due work or select a migration root.

Proposed composition consequence: separating first-block activation witnesses from a four-request mandatory prefix removes that particular combined calldata overload. Migration gives a constructive one-block/one-beginEtna body of at most 17,724 bytes under the stated bounds, below 32,768 bytes. That byte calculation does not prove an arbitrary authenticated launch-state witness executes within the one-million-gas system budget; the complete body, actual witness execution and landing envelope/proof limits must still be checked together. The bootstrap/first-successor example in migration is normative; a missing component must fail closed rather than silently omit old requests.

S1. Only a proven execution transition advances the accepted head

Proven under A-CRYPTO, A-IMPLEMENTATION, A-L1, A-DA and A-UPGRADE: start with the uniquely defined authenticated H0 from S0. Assume accepted head H is correct. The next successful Inbox call requires the statement's old-head digest to equal H, authenticates a mature matching actual-data stage, verifies its proof and the exact freshly republished data relation, checks producer authorization and the frozen forced prefix, charges the current mandatory admission rent, then installs one derived successor. The proof binds chain IDs, Inbox and Anchor addresses, revision, complete parent and terminal commitments, every execution/anchor transition, origin, data mode and commitments, stage ID, producer, ordered block-hashes root, beneficiary and authorized reward terms. A different parent or altered data cannot satisfy that statement without a cryptographic/implementation failure. Induction therefore establishes execution correctness of every accepted head in the chosen L1 history. Staging alone changes no canonical head, rent clock or checkpoint.

Proven scope: sequential Ethereum execution lets at most one incompatible successor consume H. Another sound proof of a different branch from H becomes stale after that consumption; it does not become a proof of an invalid execution. An L1 reorg can replace an accepted history before finality. Users must not infer finality from a frame acknowledgment or a valid local candidate.

S2. Pinned origins authenticate L1 facts without trusting an operator

Proven under A-L1, A-CRYPTO and A-IMPLEMENTATION: a successful HeaderStore pin checks a canonically parsed header's hash against the nonzero EVM BLOCKHASH for an earlier L1 block while the lookup is available. Thus its number, state root and timestamp belong to that ancestor in this history. Every anchor in the segment must use that exact authenticated tuple; the selected execution profile does not permit independently selected older checkpoint headers. A reorg replacing the pinned ancestor necessarily replaces its descendant pin transaction; a valid pin cannot float onto an unrelated history merely because a client cached it.

Open implementation obligation: exact header schemas must match the active fork, reject ambiguous RLP and bind number/hash/timestamp/state root consistently. Pinning only a supplied root, trusting an RPC's claim of finality, or omitting exact origin/checkpoint equality would invalidate this proof. A shorter L1 production interval shrinks BLOCKHASH's wall-clock retrieval opportunity; permissionless timely pinning must be operationally available under A-INCLUDE. No consensus-layer lookahead or fixed slots-to-seconds conversion is used.

S3. The bridge consumes authenticated checkpoints, never soft claims

Proven under S1, S2, A-IMPLEMENTATION and A-UPGRADE: only the authenticated Inbox-to-SignalService path publishes an accepted L2 checkpoint on L1. Only the proved Anchor path publishes an authenticated L1 checkpoint on L2. Existing Bridge and Vault message authentication, replay protection and storage must be preserved by the in-place upgrades described in migration. A publisher signature, availability receipt or job acceptance cannot write either checkpoint. Even complete capture of those soft-service roles therefore supplies no separate path to forge a withdrawal root.

Open launch obligation: authenticate actual proxy addresses, implementation code hashes, owners, resolvers, paused state, storage layouts and historical message/checkpoint formats, then rehearse the migration against that manifest. The source review is not an authenticated live-deployment inventory. No custody-safety conclusion covers an incorrect migration or a later malicious DAO upgrade.

S4. Liability cannot exceed escrow or produce an unbacked payout

Proven under the proposed accounting and A-IMPLEMENTATION: every accepted bonded promise consumes a distinct reserved position; each position can be slashed at most once and pays at most its reserve. Invalid, duplicate and expired evidence cannot allocate another reserve. A challenge receives its own ETH deposit; a selected timely full-fragment response pays that deposit at most once, while default refunds it and separately allocates the reserved TAIKO. The response deadline is clamped to the already signed fragment publishBy; paying for a challenge cannot buy a later deadline. Other satisfied challenges settle/refund lazily without creating duplicate publication rewards. Withdrawal follows settlement of admitted expired obligations. Internal accounting conserves recorded balances across free balances, reserves, pending escrows, unpaid credits and irreversible sink balances, separately for each asset. Their total is at most the held asset balance; unsolicited donations are uncredited surplus. An exact raw-balance equality check would let donations block withdrawals and is forbidden. Surplus creates no claimant entitlement or owner sweep.

Proven limitation: this is an accounting invariant, not an economic security valuation. Ten TAIKO per position can be less than an attack's MEV or a customer's loss. A 10% reporter/90% sink split makes self-slashing lose 90% of the slashed amount before gas, but does not bound profits outside the contract. TAIKO collateral backs finite service penalties; proof soundness and checkpoint provenance protect custody. Separately, pending forced-fee escrow is debited once into a 50% processing credit and 50% irreversible sink. All charged canonical admission rent enters a separate 100% nonwithdrawable sink. Excess rent funding creates only the actual Inbox caller's pull credit; it is neither protocol revenue nor an unbacked reward. Neither same-owner self-processing nor a Sybil recovers either sink.

S5. What a soft confirmation proves

Proven under A-CRYPTO, A-EXEC, A-IMPLEMENTATION and a correct named L1 view: when a node has the complete parent state and bounded candidate body, validates signature/domain/role claims, verifies anchor and forced-prefix rules, and reexecutes the block, its VALID_IN_VIEW result establishes that individual candidate's execution correctness in that context. A missing dependency is UNKNOWN. Optional custodians do not replace execution. Two honest nodes given the same complete inputs agree on validity; they may have different available provisional branches.

Proven limitation: this construction supplies no global first-seen ordering, guaranteed economic-owner diversity, or pre-L1 finality. An honest soft branch may lose to a different fully staged, mature branch at L1. Applications accepting provisional balances or trading against a soft head bear that rollback risk; bridge final settlement does not use those balances.

S6. Every accepted execution payload had an objective public-data lead

Proven under A-L1, A-DA, A-CRYPTO and A-IMPLEMENTATION: the DARegistry records a real current-transaction blob hash or hashes the complete bounded calldata, together with all execution-affecting context. Canonical acceptance proves the exact staged body/context matches its execution statement, requires the selected immutable receipt to be at least 360 and no more than 900 seconds old, and republishes full matching data with its valid proof. Therefore a payload first disclosed only in the canonical action cannot be accepted. A private proof prepared earlier supplies no exception to the age predicate.

Proven scope: a stage proves prior public L1 availability, not execution correctness, ordering priority, universal peer receipt, or when someone began private computation. Multiple conflicting candidates may be staged. A newer stage cannot reset another usable receipt; expired material can be restaged for a new public-data interval. Canonical parent, revision and proof checks remain mandatory. Reorgs roll back stage receipts and dependent acceptance within their affected history.

Proven under A-RETRIEVE and A-PROVE: 60 seconds for retrieval plus 180 seconds for proving fits within the 360-second notice interval, leaving 120 seconds of margin for a same-branch proof to be ready. Inclusion can only be requested once the transaction is eligible; A-INCLUDE does not promise a transaction is included before maturity. Neither this opportunity nor a faster private proof determines which eligible candidate Ethereum selects.

S7. Every bonded fragment has an absolute publication obligation

Proposed duty: every accepted bonded DutyClaim under the EtnaDuty version 2 domain requires complete fragment bytes in L1 calldata together with the exact codec FR preimage by publishBy=issuedAt+240. The fragment publication registry verifies that preimage, signed fields, fragment index, length and digest and records the first matching publication. Any holder may fulfill the duty; a later response never rewrites that time. A sealed generic stage alone is not this receipt: its blob/versioned hash cannot stand in for a checked fragment/FR relation.

Proven under A-CRYPTO/A-L1/A-IMPLEMENTATION: after publishBy, an authentic live claim plus the absence of a timely first fragment publication establishes default, with or without an earlier challenge. Before publishBy, an optional paid challenge has deadline=min(openedAt+600,publishBy); opening it later cannot postpone the obligation. A successful timely selected response receives Q once; other timely satisfied challenges refund. A response after the absolute deadline cannot earn that timely-response reward or cancel the slash. Once publicly revealed there is no continuing personal server-retention duty; long-term retrieval is A-ARCHIVE, not proof of the original signer's uptime.

Proven scope: issuedAt now changes an objective deadline and is a semantic signed field. Two otherwise equal DutyClaims with different issuedAt are not harmless retries. Version 2 prevents silently applying this stronger duty to a version 1 signature. No retrospective penalty or hidden reinterpretation of old commitments is allowed. Timely publication can still follow selective early gossip and can still earn the voluntarily funded publication fee; the new guarantee is a fixed latest public availability time, not proof of earlier intent or zero responder profit.

4. Liveness proof sketches and their limits

L1. Incumbents cannot reserve all canonical admission rights

Proven under the admission rules: any address can stage actual data and submit an eligible valid segment without a publisher ticket, custodian certificate, job acceptance, private relay or administrator action, while paying the deterministic current admission rent when it is nonzero. Producer assent is an objective self-authorization, not someone else's approval; relay and fee payer may be different parties. The DAO has no routine operation to perform. Assigned workers have no exclusive claim, and their deadlines do not delay a replacement proof. A malicious incumbent cannot squat a finite global registry capacity because there is no such capacity or canonical lease. Staging supplies no head reservation and does not obligate others to use its candidate.

Proven conditional progress: suppose a reconstructible accepted head remains unchanged long enough for a funded honest entrant to acquire bounded work, stage it, reach the 360-second age threshold, prove it and have its still-valid submission included within both 900-second freshness limits. A-DA, A-PROVE, A-INCLUDE and the applicable rent funding yield a successor. If a competing eligible action instead consumes the parent first, canonical progress already occurred, although the honest worker's computation and paid stage may be wasted. Repeated competing progress does not prove honest ordinary transactions will be selected; forced FIFO supplies that separate guarantee.

Assumed timing example: seal a 60-second segment at t=60, stage promptly and complete a 180-second proof by t=240. The stage matures at t=420; prompt final inclusion gives roughly seven to eight minutes from the first block. Taking the full 120-second inclusion allowance for staging and again for canonical acceptance instead yields 60+120+360+120=660 seconds, plus header-acquisition time. Proving can run during the public-data interval. These examples fit 900-second freshness when the origin/context are selected consistently and the payer funds the nonzero quote; they are not measured throughput or a universal Δ. The 900-block unsafe horizon bounds soft exposure through that healthy interval. Once origin or stage freshness expires, restage/reseal/reprove as required; no stale receipt silently waives either rule.

Proven revision effect: origins may be reused, with nondecreasing number/timestamp and identical header on equal number. A byte/gas-bound segment need not wait for the next L1 header merely to seal. Within its freshness period, the same origin can support multiple canonical successors. The 900-second age ceiling still forces origins and their exact queue snapshots eventually to advance on an indefinitely progressing chain.

Proposed job feasibility rule: a worker accepts only a known live exact staging receipt/context. Its objective deadline is max(acceptedAt+300, stage.publishedAt+360+120), and both origin.timestamp+900 and stage.publishedAt+900 must be at least deadline+120. Thus a freshly staged job is not slashable merely because its protocol maturity exceeds 300 seconds. Historic parent-consumption and revision-retirement receipts still decide innocent cancellation versus an already missed deadline; no job grants exclusive proof rights.

L2. A fixed forced request cannot be overtaken by later arrivals

Proven under the queue rules and canonical progress: enqueue creates an immutable index and timestamp. A parent's snapshot fixes the exact queue tail at its authenticated origin; a child cannot change that obligation by delaying its landing. At most four due requests at the head of that frozen prefix must be consumed before discretionary transactions, by execution or deterministic proved rejection. New arrivals have larger indices and never increase the number of predecessors of an existing request. Once that request is in a mature snapshot, every accepted successor that has not yet consumed it removes four earlier due requests, or consumes it when fewer remain.

Proven bootstrap scope: H0's empty sentinel is consumed at most once. Its first real successor installs an exact snapshot, preserving every inactive-queue index and fee. Apply the ordinary snapshot induction from that successor. For requests queued before activation, any claimed wall-clock service bound must begin in the ACTIVE progress interval and include the first bootstrap successor; elapsed legacy/drain time is not covered by A-LIVE(Δ). An empty initial cut is temporary deferral, never deletion or permission to remain at the sentinel.

Proven finite-delay bound under A-LIVE(Δ), once the ordinary snapshot induction applies: let a request enqueue at L1 timestamp t, and let p be an upper bound on its still-unconsumed predecessors. Its maturity is 120 seconds. At any acceptance at or after t+120+900, origin freshness forces the selected origin timestamp to be at least t+120. The origin's exact snapshot therefore contains the request and every earlier request is also mature. Within Δ seconds there is such an accepted parent; within a further ceil((p+1)/4) accepted successors, the request is processed. Origin reuse does not weaken this age argument. A conservative bound is:

processedAt ≤ t + 1020 seconds + (1 + ceil((p + 1) / 4)) × Δ
where Δ bounds accepted-successor spacing, not Ethereum slot duration.
For a pre-ACTIVE request, with activation time tA, enqueue time tQ and P predecessors:
processedAt ≤ max(tA, tQ +120) +900 + (1 + ceil((P +1) /4)) × Δ
Here Δ also bounds activation to the first accepted segment. The snapshot-bearing successor covers H0’s one empty cut; inactive legacy-drain time has no unconditional service bound.

Assumed numerical example: with p=9 and Δ=660 seconds, the bound is 1020+4×660=3660 seconds, or 61 minutes after enqueue. This is deliberately conservative and conditional, not an advertised universal forced-inclusion SLA or a claim that a 660-second Δ was measured. A lightly loaded pipelined chain can process much sooner. There is no uniform delay bound across an arbitrarily large paid backlog or a total prover outage.

Proven scope: “processed” means a validity-checked execution attempt, or a proved reason the raw transaction is malformed or invalid in its canonical execution state. It cannot guarantee application success, restore an obsolete nonce, force an oversized transaction, or guarantee the ordering outcome an unforced soft transaction would have had. The 2048-byte and one-million-gas request bounds make each required item finite; launch measurements must establish the affordability of four worst-case requests plus proof verification.

Proven limited deterrent: the fee remains 0.001 ETH×(1+floor(pending/50)), but half is irreversibly excluded from withdrawals. Starting empty, 1000 enqueues without intermediate processing pay 50×0.001×(1+…+20)=10.5 ETH, of which 5.25 ETH is a net sink even if the attacker earns every processing credit. Gas, staging, proof and republication costs are additional. Intermediate processing can lower the next admission fee but must consume existing FIFO work; it cannot cheaply hold a fixed victim behind the same unprocessed prefix forever. This is a concrete resource cost, not a proof that all censorship is unprofitable.

L4. Repeated early control pays an identity-independent admission rent

Proposed normative mechanism: every successful canonical successor pays the global Dutch admission rent. Let R0=50,000,000,000,000,000 wei (0.05 ETH), T=900 seconds, and age=now-rentReferenceTime. Initialize rentReferenceTime to the activation timestamp, then reset it to the current L1 timestamp on every successful acceptance. It is a separate Inbox clock, not a Head field or proof input. A stage, failed transaction, signature, challenge, bid or job cannot reset it. Quote:

q(age) = 0                                      when age ≥900
q(age) = ceil(R0 × (900-age) /900) wei             otherwise
required ETH ≥ q(age); exactly q enters the permanent sink;
excess goes to the actual Inbox caller’s pull credit (msg.sender).

Proven admission and accounting consequences: every address may immediately submit an otherwise valid mature proof/data action and pay the current quote. There is no auction winner, reserved turn, identity lookup or preferential incumbent price. The first accepted action consumes its parent and resets the price for the next parent; several valid advancing actions in one L1 block each face age zero after the first and each pay 0.05 ETH. Each still executes its exact proof and mandatory FIFO prefix. One owner controlling producer, beneficiary, payer and Sybil addresses recovers none of the rent: 100% is permanently excluded from withdrawals. Paying rent cannot cure an invalid proof, stale parent, immature stage, wrong origin or missing forced work.

Proven bounded capture-cost argument under A-COMPETITION(D): on each considered parent, either an honest competitor consumes it by age D or the adversary captures it first by D. Since q decreases while that parent remains unchanged, every such adversarial win pays at least q(D). For D=660, 100 early wins therefore sink at least 100×13,333,333,333,333,334 =1,333,333,333,333,333,400 wei, or 1.3333333333333334 ETH, in addition to normal execution, proving, stage/republication, gas and builder costs. This is true for one owner or many correlated owners. Let G be its won L2 fees plus ordering/external value minus those normal costs. The tactic is unprofitable whenever G < Σq. For example G=0.01 ETH per captured head gives G=1 ETH over 100 wins, leaving a loss of at least 0.3333333333333334 ETH. Assumed model scope and open calibration: A-COMP(660) requires a ready, valid, adequately funded and willing competitor before the zero floor; the existence of some prover does not supply it. The earlier 660-second example excludes header acquisition, so a particular launch workload meets A-COMP(660) only if its complete acquisition/work/inclusion schedule fits 660. Otherwise choose and state its actual D<900 and recompute q(D), or admit that no positive bound follows. If profitable value exceeds rent, concentration can remain profitable. If no competitor can or will fund an early quote, a monopolist may wait 900 seconds and pay zero. These limits are part of the conditional result, not a claim that the selected 0.05 ETH rate has been empirically calibrated.

Proven nonblocking fallback under the liveness premises: an unchanged parent reaches zero rent at age 900 and remains there. Old candidate origins or stages may expire at that same horizon; zero rent does not extend them. An entrant can construct a fresh origin/context, stage it, prove it and wait 360 seconds while the head remains unchanged. It then pays zero rent and normal L1 costs. If someone advances the head first, canonical progress has occurred and the new quote applies. Thus rent cannot reserve a head forever. Target seven-to-eight-minute landing assumes funding the positive quote; a lower-rent policy deliberately accepts longer recovery. A-LIVE(Δ) must include the chosen funding schedule and any reconstruction/restaging, not silently reuse660 seconds for this fallback.

Proven proof-stability property: rentReferenceTime changes only when the parent changes. While that parent remains current, its quote only decreases and does not alter the proved execution statement. A payer may fund the maximum 0.05 ETH and reclaim excess without guessing the inclusion timestamp. Refund attribution is to msg.sender: the ordinary caller or its individually controlled authorized frame sender. The separate transaction-fee payer does not acquire that credit. Positive-rent frames fund the individual sender; the shared per-action nonce/sender construction applies only at zero SENDER-frame value. Quote rounding, ordinary/frame envelope funding, state-first sink/credit updates and the no-sweep rule must agree with the canonical interface. This is a new proposed economic rule awaiting adversarial review, not an already verified R6 pass.

5. Withholding: prevention, attribution and residual limits

Proven first-reveal counterexample W1: without earlier actual DA, an attacker can privately build Y from accepted H and first reveal Y with a valid proof before public X lands, making X stale without a violated signature. Proposed defense: Y must now have complete actual L1 data and execution context staged for at least 360 seconds, and must republish it in its proof-bearing acceptance. W1's first-disclosure-at-landing step fails the eligibility predicate. The attacker may compute privately earlier, but must expose Y and give public peers the same-branch proving opportunity before Y can win. It also pays the current ordinary admission rent; avoiding optional service promises does not bypass that charge.

Proven separation under the named assumptions: mandatory staging prevents first disclosure at acceptance for every producer; every bonded early-fragment promise now has its own absolute actual-publication deadline; an optional sealed covenant separately fixes a whole-segment staging deadline; authenticated owner assent makes a bounded class of conflicting endorsements provable. Rent prices repeated early canonical wins under A-COMPETITION(D). Advisory attestations alone provide none of these universal canonical checks. The complete byte/context and receipt rules are normative in staging, with fragment/evidence settlement in accountability.

Every bonded early fragment must actually be published

Proposed objective duty: a version-2 publisher or custodian signs an exact fragment and ordered FR manifest root, using one reserved position. Its declared in-window issuedAt fixes publishBy=issuedAt+240. It must arrange complete fragment calldata and the checked FR preimage by that deadline without waiting for anyone to buy a challenge. Any holder may fulfill it, and one exact publication satisfies all matching duties for which it was timely. At now>publishBy, a live authentic claim plus the immutable first-publication lookup suffices to report default. No prior request, peer testimony, historical proof of nonreceipt or new 600-second grace period is required.

Proven anti-delay consequence: an optional challenge opened at now<publishBy ends at min(now+600,publishBy). Its first selected timely response can earn Q; standalone publication pays no protocol subsidy, and other timely satisfied challenges refund their Q. A late publication remains useful data but cannot erase default or earn the timely response payout. Generic blob staging alone never satisfies a fragment duty. Under A-PUBLISH, conforming signers can satisfy the fixed deadline with zero objective defaults; the protocol cannot guarantee inclusion during a partition or arbitrary L1 censorship.

Authenticated same-owner conflict

Proven attributable predicate: an accepted receipt records a producer that authorized the exact statement and stage ID using EIP-712 and an immutable authenticated key. A bonded publisher's DutyClaim X and a bounded Merkle proof for a different accepted block Y can establish a conflict only when collateral owner equals that authenticated producer, revision/base accepted head/L2 number match exactly, and block hashes differ. The execution proof binds the accepted block-hashes root; the membership proof uses the fixed encoding in the block tree. Slash X's reserved position at most once. Do not slash a beneficiary merely because someone named it; do not repeatedly evaluate a mutable generic EIP-1271 policy as historical authorization.

Proven scope: someone else's winning branch cannot automatically slash an honest publisher. Distinct owners may share economic control without a provable link. This rule deliberately matches Y's immediate accepted old-head hash to X's explicit base-head context; it does not infer cross-segment ancestral equivalence. A conflicting later segment outside that exact context may escape this specific slash. Ordinary signed-equivocation and publication duties remain independent. This bounded predicate is not a global promise that one publisher can never change any future soft history.

Sealed publication-by covenant

Proposed objective duty: after sealing, the complete DA key and execution context are known. A publisher uses a separate reserved position to sign them with an issuedAt inside its preexisting bucket window and publishBy=issuedAt+240 seconds. Any matching actual stage recorded by publishBy discharges the duty, regardless of who paid for staging. At now>publishBy, a valid signature and the immutable first qualifying stage timestamp or its absence establish default. A late stage cannot cure it; anyone can report and receive 10% of the position's slash while 90% enters the sink.

Proven distinction: a one-second block fragment's keccak digest is not a later unknown segment blob versioned hash. Early fragment claims require their own exact fragment/FR calldata publication; a sealed claim requires actual publication of its exact complete execution context. These independent absolute deadlines use separate positions and distinct signed types. Neither bucket registration nor a signer-chosen issuedAt proves earlier P2P dissemination. The duty is the objectively enforceable publication deadline it says, not a global gossip timestamp.

7. Known limitations and risks requiring explicit acceptance

  • Proven: fully staged, mature competing branches can displace honest soft branches; soft confirmations are revocable. Mandatory prior DA rejects first-disclosure-at-landing, not every MEV opportunity or branch conflict.
  • Proven: faster minimal proofs can repeatedly beat transaction-rich discretionary branches. Frozen FIFO protects eligible forced transactions, but ordinary mempool fairness and honest prover profitability are not guaranteed.
  • Proven conditional limit: mandatory rent prices early repeat-control independently of identity, but its positive lower bound requires A-COMP(D<900). A cartel with value above rent can still profit; one without a ready, funded competitor can wait for zero rent. The 0.05 ETH peak also charges honest fast progress and may reduce affordable cadence. Open: empirical calibration and economic adoption. Ten TAIKO positions remain bounded service penalties, not MEV insurance.
  • Proven: every accepted payload needs prior staging and full republication at acceptance, normally two blob inclusions or duplicate calldata. Every bonded early fragment additionally needs actual calldata plus its FR preimage within 240 seconds, even when the segment uses blobs. Several signers can share one exact publication; a stage is no substitute. Losers may still pay publication/staging cost. The 360-second lead increases soft rollback exposure; it does not strengthen soft finality.
  • Proven under the role schedule: the steady exposure baseline at one 10-TAIKO claim per second for 3600 seconds is 36,000 TAIKO; at four fragments per second it is 144,000 TAIKO. The exact peak for just-in-time full 60-position buckets, including their overlapping 60-second issuance windows and strict release boundary, is 37,200 TAIKO at one claim/second and 147,000 TAIKO at four. Separate sealed covenants add positions. See roles for the derivation; these smaller exposures still impose meaningful capital requirements.
  • Proven bounded-service scope, subject to review: version 2 has no post-publication personal server-retention duty. Its absolute deadline is 240 seconds after the declared issue time, and evidence closes 3600 seconds after the bucket issuance window. Discovery after that horizon may be unpunishable; clients stop calling the claim bonded. This does not waive stage age, recover a released reserve or permit a false custody root. Long-term historic-byte access remains A-ARCHIVE.
  • Assumed: timeouts operate under finite inclusion/observation/funding bounds. Arbitrary censorship, fee spikes and network partitions can cause honest service defaults or proof expiry.
  • Proven: larger transactions cannot use the bounded force path, and an unlimited earlier paid backlog defeats a uniform short inclusion SLA. The user's operation must fit the stated admissible form.
  • Assumed: public archives and execution state remain reconstructible; neither KZG commitments nor execution proofs guarantee perpetual off-chain storage.
  • Open: chosen gas, body, proof-size and deadline values require measurement on the launch engine, prover and active L1 fork. No benchmark or production capacity result is claimed.
  • Proven: optional invalid-on-failure frame transactions incur builder simulation cost even when excluded from L1. Public-mempool support for the terminal guard is not supplied by the analyzed draft; ordinary stale losers can pay reverting gas.
  • Assumed: upgrades preserve safety and historical obligations. An inactive DAO permits routine operation; a malicious DAO remains outside the safety assumption, and permanent compatibility with all future L1 forks is not promised.
