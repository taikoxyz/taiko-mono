Interface sketches

One consolidated view of every function, struct and event the design names, following the repository's conventions (named imports, underscore-prefixed parameters, underscore-suffixed returns, errors at the end of implementation files, NatSpec on interfaces). These are sketches inside a design document, not implementations. Per-block pages hold the rationale; this page holds the union. This page is normative for evidence and struct types (round 4, D9 and R4-C6): where a slashing or certificate sketch elsewhere names a different evidence type (for example a timeout message where a lock vote is meant), the types here govern. The parameters page is normative for constants, the landing page for landing checks and replacement.

Hashing convention (adopted from the Astra candidate, PR #22188). Every protocol hash is keccak256 over the canonical abi.encode of typed fields, never abi.encodePacked or a bare concatenation; ‖ in this design's formulas denotes the fields of one abi.encode. Signed messages and the journal and commitment hashes put the domain tag and the chain id first, and signed messages carry their DOMAIN_* tag inside the encoding. The exceptions to the tag-first rule, each one fixed abi.encode of the fields in this order (round 6 fix pass): the holder walk keccak(seed ‖ 0x01 ‖ t ‖ k) = keccak256(abi.encode(bytes32 seed, uint8 1, uint32 t, uint16 k)), the committee walk keccak(seed ‖ 0x02 ‖ t ‖ m) = keccak256(abi.encode(bytes32 seed, uint8 2, uint32 t, uint16 m)), the redraw walk keccak(seed ‖ 0x03 ‖ t ‖ n ‖ m) = keccak256(abi.encode(bytes32 seed, uint8 3, uint32 t, uint8 n, uint16 m)), the seed accumulator keccak(seedAcc ‖ prevrandao) = keccak256(abi.encode(bytes32 seedAcc, uint256 block.prevrandao)), and the sentinel opening object keccak("ETNA_DEAD" ‖ lastLanded.blockHash ‖ t) = keccak256(abi.encode(bytes32("ETNA_DEAD"), bytes32 lastLanded.blockHash, uint32 t)); the seed itself, seed(c) = keccak(DOMAIN ‖ chainId ‖ seedAcc_at(T_seed(c)) ‖ c) (sequencing page RND2), follows the rule. An implementation that packs fields changes every hash and is not conformant.

2. L2: anchor-free blocks, the Anchor as treasury, the SignalService reveal

Given in full on the Anchor page (anchor-free blocks, issue #22147). An L2 block contains no Taiko-specific transaction: its header carries the hash of the anchored L1 block in parentBeaconBlockRoot and basefeeSharingPctg(1) ‖ termId(4) ‖ view(1) ‖ kind(1) in its 7-byte extraData (kind 0 NORMAL, 1 FORCED, 2 GENESIS_CHILD, 3 FI). IEtnaAnchor: the Anchor proxy stays the fee treasury (withdraw, unchanged); its legacy entry point reverts whenever L2's EIP-4788 contract records a non-zero root for the current block (the current-root guard, every Etna block), and its blockHashes and getBlockState() views freeze at their last Shasta values. IEtnaL2SignalService: the L2 SignalService, upgraded in place (one namespaced pin mapping, no linear slot), adds revealCheckpoint(uint64 _l2Timestamp, bytes calldata _headerRlp), which stores the checkpoint of an L1 header whose hash L2's EIP-4788 contract recorded for that L2 timestamp or, with timestamp 0, that pinCurrentOrigin() pinned, and its saveCheckpoint reverts under the same guard (adopted from the Astra candidate, PR #22188); the same upgrade removes its pause and unpause, as on every shared contract (§3; after the #22188 review, 2026-10-01). Events: the Anchor's Anchored stops at the fork; on L2, CheckpointSaved now comes from reveal transactions (§3).
