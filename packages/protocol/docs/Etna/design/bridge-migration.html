L2 anchor, shared contracts (R2), and migration

Both existing proxies are upgraded in place. The L1 SignalService, the L2 SignalService, the Bridge and the Vaults are not touched: no implementation, no storage, no address, no version bump. Every Etna block opens with anchorV5, which makes the block self-describing, and every anchored checkpoint is bound at landing to an L1 block that was canonical when the landing was included. Source: judge synthesis of the three B8 designs.

What today does and why it fails

anchorV4 checks the 255-ancestor ring and forwards a strictly newer checkpoint to the L2 SignalService; equal numbers are ignored silently, nothing on L2 checks the hash or state root, and a reverted anchor does not invalidate the block (00 §5, §9.2). The only L1 binding is the guest's chain to the proposal's originBlockHash, which the propose step recorded and which disappears with it (TH17, Critical: the L2 Bridge mints against L1 state roots). The block is not self-describing; anchor freshness is 12-second arithmetic. The L1 syncer address is an implementation immutable of the SignalService, so whichever contract lands batches must keep the Inbox proxy address or force a SignalService implementation bump.

1. The anchor transaction: anchorV5(AnchorInput)

Every Etna block's first transaction, from the golden touch with the fixed-nonce ECDSA signature as today, gas exactly 1,000,000, value 0, fee cap equal to the base fee (the four engine pins, re-pinned for the new selector). AnchorInput is the union of what the other blocks need inside blockHash:

  • kind: 0 NORMAL, 1 FORCED (a forced-batch block), 2 GENESIS_CHILD (the first Etna block).
  • checkpoint: the L1 {blockNumber, blockHash, stateRoot}, shape unchanged.
  • termId, view, seat: the sequencing slot; view 255 is the open-empty or dead-mode sentinel, view 254 forced.
  • carriedCertHeight, carriedCertHash, carriedCertBitmap: the carried certificate (lag ≤ 1); zero on the first two blocks of a view.
  • vcHash: keccak of the view change (or, for a sentinel view, the dead-mode or forced opening object) that opened this view; carried on every block of the view (round 3: so the guest rebuilds every signed header from the anchor calldata).
  • fiCursor: the forced-inclusion cursor after this block.

Deliberately absent: a sequencer address (ecrecover of the header signature is the identity; a calldata copy would be a third value no contract can check) and a batch id (ranges are lander-chosen; a block does not know its batch).

Rules the Anchor enforces on L2 (every require is a consensus rule because of A8):

  1. A1 sender and fork gate. Golden touch only; anchorV5 requires block.timestamp ≥ ETNA_T0, anchorV4 requires the opposite (both selectors exist in the new implementation).
  2. A2 ancestors ring. Unchanged; _blockState stays byte-compatible with Shasta (rollback).
  3. A3 checkpoint monotone and conflict-free. A lower number reverts; a strictly greater one is saved through the unchanged ICheckpointStore; an equal one must match the stored record, else CheckpointConflict. Today equal numbers are ignored, so two blocks could carry different hashes for one L1 number; Etna refuses.
  4. A4 term binding. termStart(termId) ≤ block.timestamp < termStart(termId + 1) for ordinary blocks (exempt for kind FORCED, whose timestamps may cross a term boundary); termId non-decreasing.
  5. A5 view binding. (termId, view) changes iff vcHash ≠ parent.vcHash: a view opens with exactly one opening object, carried unchanged by every block of the view. For sentinel views the opening object is keccak("ETNA_DEAD" ‖ lastLanded.blockHash ‖ t), accepted as fresh after any landing (so a dead-mode or no-committee chain that lost a landing race reopens without equivocating; round 2, S9). The genesis child requires an empty previous record and no view change.
  6. A6 forced blocks. Kind FORCED requires view 254 and seat 0; block 0 of a forced batch may advance the checkpoint (the lander's chosen anchor), later ones inherit.
  7. A7 record. Store the packed metadata, the carried certificate hash and the view-change hash in three overwritten slots; emit AnchoredV5. L2 contracts and the guest read one source; the slot numbers are published constants (TH25).
  8. A8 receipt rule (client and guest). An Etna block is valid only if transaction 0 is anchorV5, its receipt status is 1 and its gas used is within the limit. Today a reverted anchor leaves the block valid; under Etna nodes reject it at V6 and the guest asserts it, so a wrong ancestors hash or a checkpoint conflict surfaces as an invalid block, never as a silent checkpoint gap.

What the Anchor does not verify, and why: the L1 hash and state root (needs L1: guest plus inbox), the certificate and view change (needs committee keys and pairings: attesters off-chain, inbox at landing), the sequencing right (needs the registry: inbox at landing). Checking any of these on L2 would make 1-s block production depend on fresh, proven L1 state.

Header rule. extraData stays exactly 7 bytes so the engine's length pin and fee decoder need no change: basefeeSharingPctg(1) ‖ termId(4) ‖ view(1) ‖ kind(1); the guest requires the first byte to equal the protocol constant and the rest to match the anchor calldata. The seat lives in the anchor calldata and the assignment digest in the P2P envelope.

Cost, stated plainly. anchorV5 is an L2 execution-client hard fork: taiko-geth and alethia-reth pin the anchor selector, so both ship ETNA_FORK_TIME = ETNA_T0 exactly as they shipped Shasta and Unzen. Keeping anchorV4 was rejected because the signed header needs the carried certificate and view-change hashes inside blockHash, and the receipt rule is an engine change in any case.

2. Binding every anchored checkpoint to a true L1 block (TH17)

Production-time freshness is V5 on the certificate page: the anchored block is at least 48 s and at most 30 min older than the block, equal to the node's own L1 header, and monotone rather than must-advance (during an L1 stall leaders keep anchoring the last block). Landing-time binding: the journal carries the anchor tip's number, hash and timestamp; the guest witnesses the full header RLP of every distinct anchored L1 block, checks its hash, number and state root, and chains every header from the oldest anchored block to the tip; the inbox checks only the tip. Hence every checkpoint written into the L2 SignalService by a block of a landed range is the hash and post-state root of an L1 block canonical at landing. A batch whose landing slips past the window (an outage longer than 4.55 h at 2-s slots) is unlandable and replaced. proven given T3 and EIP-2935 semantics.

3. The SignalService interface: one call, byte-identical

// from the upgraded Inbox proxy 0x6f21C543a4aF5189eBdb0723827577e1EF57ef1f, once per landing, before verifyProof:
_signalService.saveCheckpoint(ICheckpointStore.Checkpoint({
    blockNumber: uint48(_in.endHeight), blockHash: _in.endBlockHash, stateRoot: _in.endStateRoot }));

Inbox-side invariants, because the SignalService checks none: end height strictly increasing, hashes non-zero. msg.sender == _authorizedSyncer holds because the proxy address is unchanged. On L2 the Anchor's call is unchanged and the L2 SignalService's syncer stays the Anchor proxy; it receives one checkpoint entry per anchored L1 block through anchorV5, the same cadence as today. proveSignalReceived still reads version 1; VERSION is not bumped on either layer. Under EIP-8037 the fresh checkpoint words cost about 196k state gas per landing: unavoidable under R2, paid by the lander. proven no SignalService, Bridge or Vault bytecode or storage changes.

4. R2 decision: upgrade both proxies in place

Upgrade the Inbox proxy and the Anchor proxy in place; touch neither SignalService, nor Bridge, nor any Vault. Reasons: the syncer is an implementation immutable, and a new inbox would force a new implementation on the contract that guards all bridged value, on both layers if the Anchor moved too; the bond ledger and the forced-inclusion queue carry over with no token migration; relayer, indexer and both clients already point at the proxies; rollback is one upgradeTo per chain. Costs accepted: Shasta slots stay allocated; the public-function libraries are redeployed and re-linked with the new registry and slashing libraries beside them. The fallback, only if the in-place storage audit fails: a new SignalService implementation whose constructor names the new syncer, layout untouched.

5. Migration

Two upgrade-class L1 transactions (round 4, R4-C5). Let U be the L1 time at which the DAO's upgrade transaction executes: deploy the linked libraries, the verifier with image windows, the Etna Inbox implementation, then upgradeToAndCall(impl, initEtna(lastFinalizedBlockNumber)). initEtna carries no T0: it verifies the L1 SignalService's checkpoint at that number equals the core state's last finalized hash (this pins the L2 height that the core state does not store), sets the initial lastLanded and opens register(). Let A ≥ U be the time of the second call, armEtna(T0), which requires T0 ≥ A + MIGRATION_LEAD (7 days) and sets the term grid once; the DAO makes it after reading the eligible seat count on-chain and the owner structure off-chain (round 3's single transaction fixed T0 against an empty registry, so the launch condition could only be read after T0 was immovable). T0 defines the term grid; its phase relative to L1 slots is irrelevant (R5). The arming proposal also bridges the Anchor upgradeTo (whose term-grid immutables carry T0) to the L2 DelegateController; both execution clients ship the fork time.

  • M1 drain. Drained once block.timestamp ≥ T0 and every proposal is proven, or abandoned. The first call that observes it records drainedAt and emits ShastaDrained.
  • M2 abandonment (R1). After T0 + DRAIN_DEADLINE (24 h), anyone may call abandonShastaTail(), the effect of today's owner-only init2 made permissionless and time-gated; the unproven tail (at most one hour of Shasta blocks) is void; no bond was at stake.
  • M3 genesis and first term. Genesis parent = the last Shasta-finalized block = the newest checkpoint in the L1 SignalService. The first Etna term is ⌈(drainedAt − T0) / TERM⌉, an L1 storage value every node reads identically. At drainedAt the inbox sets lastLandedTerm = firstEtnaTerm − 1, lastLanded.at = drainedAt and the anchor-tip timestamp to the drain block's, so no fallback (dead mode, replacement, forced batch) is armed at the first term. The genesis lock is lastLanded with no view change for the first view; the first block carries kind GENESIS_CHILD.
  • M4 in-flight objects. Shasta preconfirmations not proposed by the freeze are lost (announced). Proposals proven during the drain finalize through the retained prove with today's verifier. Forced inclusions keep their save time and fee and become due under the new rule; the drain window is far inside blob retention.
  • M5 pause. No Etna block exists before the first term: about one hour if the whitelisted provers prove promptly, at most 25 hours otherwise. During the drain no Etna penalty can fire: the only landing-path debit, MISS, needs a TIMEOUT view change of an Etna term, and no rule reads the absence of a landing (round 4).
  • M6 whitelists. The Etna implementation never reads either whitelist except inside the retained propose, unreachable after the freeze; the retained prove drops the prover gate (safe: the verifier already requires a ZK leaf). Both contracts stay deployed and readable for rollback; setting the prover count to zero is neither required nor wanted.
  • Pre-T0 checklist. Two execution-client releases with the fork time; the guest release with anchorV5 decoding, the header-chain witness and the receipt rule, image ids rotated in the same proposal; the published launch condition, read by the DAO before it calls armEtna(T0) and never enforced by the contract: at least 8 distinct owners and 72 seats with activeFrom ≤ T0, chosen so that a full committee can exist with the primary owner excluded and a small cartel blanks few terms at launch (slashing page §5 table); it delivers neither property as a rule, being a heuristic over a Sybil-able, revocable count that no rule enforces or protects, and launch may begin in no-committee mode if it fails (round 4, R4-C5): seats can be registered to pass it and exited afterwards at the cost of idle capital for seven days (MIN_TENURE), and owners are addresses. If the condition fails at T0, committees are smaller and their quorum scales down (a committee of 8 to 31 seats certifies with a proportionally weaker bound), and below 8 seats launch begins in the no-committee regime; the gate contract for the public-mempool shape is not deployed until EIP-8141 is Final (its immutable address stays zero).

6. Rollback

L1: the DAO upgrades the Inbox proxy to the Shasta implementation plus initRollback(lastEtnaHeight, lastEtnaHash) (reinitializer(5)), which requires the SignalService's checkpoint at that height to match (so the DAO cannot pick a height that never landed), rewrites the core-state fields and one ring slot as activate does. Bonds stay in their slot under Shasta's withdrawal delay; seat records are inert. L2: anchorV5 maintained _blockState byte-for-byte, so upgradeTo(shastaImpl) needs no state fix; clients ship a rollback time after which anchorV4 is required again. Unlanded Etna blocks are void; landed ones are final; bridging is never interrupted in either direction because neither SignalService is touched. Rollback is a DAO decision, never a liveness path. proven that no storage migration beyond those fields is needed.

7. L2 fee flow

Engine semantics unchanged: extraData[0] percent of each block's base fee to the coinbase, the remainder to the treasury address, which is the Anchor predeploy; priority fees to the coinbase. The 75 % split becomes a protocol constant (an Anchor immutable, in the published parameters, guest-asserted) instead of a per-proposal event field. The coinbase is the sequencer's free choice (a fee key, not the slashing key). The Anchor's 25 % stays with the DAO in v1: withdrawable by the DelegateController, never on a liveness path. It is not the reward pool: landers and attesters are paid in TAIKO on the L1 ledger from the responsible holder, so no bridge message, relayer or exchange rate sits on a liveness path. A permissionless sweep to an L1 pool is a storage-compatible later option (it must send with a non-zero gas limit and an L1 receiver, because a zero-gas-limit bridge message can only be processed by its destination owner).

8. Published constants (TH25)

protocolParams() on the inbox returns every guest-visible constant: activation time, term length, lookback, landing windows, anchor ages, anchor gas limit, fee split, history-contract address, Anchor and golden-touch addresses, the three metadata slot numbers, header-chain cap, committee size and quorum, view cap, certificate lag, forced-inclusion delay, expiry, run cap and per-landing cap, encoding version, blob data size, blocks per landing and the ZK threshold. protocolParamsHash = keccak(abi.encode(params)) is a journal field. Guest, both clients and both contracts read this one source; a mismatch is a liveness failure (no valid proof), never a soundness failure.

9. Client changes

Go client: new Etna bindings beside the Shasta ones (kept for drain and rollback); the anchor constructor; the chain syncer with a Landed-driven pipeline beside the Proposed one, switched on the drain event, plus the receipt rule; the preconfirmation driver rebuilt around terms, views, BLS attestations and range sync (lookahead code deleted); driver state where the head is lastLanded; the proposer becomes a sequencer building from the preconfirmed chain, not the transaction pool; the prover builds land and the journal; RPC methods for the inbox views replace the whitelist reads; every 12-s constant listed in 00 §11. Rust client: bindings (delete the lookahead and whitelist bindings); the protocol crate gains Etna anchor, constants and header modules with no slot-derived offsets; the driver's anchor builder, derivation pipeline and sync; the proposer becomes a sequencer; the whitelist preconfirmation driver becomes a term-aware driver. Outside this repository: the raiko2 guest (anchor decoding, header-chain witness, receipt rule, extraData and fee checks, the journal), taiko-geth and alethia-reth (fork time, selector pin, receipt-status validity, extraData length unchanged).

10. Interface sketch: the Anchor

/// @title IAnchorV5
/// @notice Etna implementation behind the Anchor proxy 0x1670…10001, upgraded in place; slots 256-257 unchanged.
/// @custom:security-contact security@taiko.xyz
interface IAnchorV5 {
    struct AnchorInput {
        uint8 kind;                              // 0 NORMAL, 1 FORCED, 2 GENESIS_CHILD
        ICheckpointStore.Checkpoint checkpoint;  // L1 {blockNumber, blockHash, stateRoot}
        uint32 termId; uint8 view; uint16 seat;  // view 255 = open-empty / dead mode, 254 = forced
        uint64 carriedCertHeight; bytes32 carriedCertHash; uint32 carriedCertBitmap;
        bytes32 vcHash;                          // opening object of this view; on every block
        uint48 fiCursor;                         // forced-inclusion cursor after this block
    }
    struct EtnaMeta { uint32 termId; uint8 view; uint16 seat; uint8 kind; uint32 carriedCertBitmap; uint48 fiCursor; uint64 carriedCertHeight; }

    /// @notice Anchors L1 data and the block's self-description; golden touch only; any revert invalidates the block (A8).
    function anchorV5(AnchorInput calldata _input) external;
    /// @notice Legacy entry point; reverts EtnaActive() once block.timestamp >= ETNA_T0.
    function anchorV4(ICheckpointStore.Checkpoint calldata _checkpoint) external;
    function termGrid() external view returns (uint48 t0_, uint32 term_);
    function basefeeSharingPctg() external view returns (uint8 pctg_);
    function getEtnaMeta() external view returns (EtnaMeta memory meta_, bytes32 carriedCertHash_, bytes32 vcHash_);
    // existing: getBlockState(), withdraw(address _token, address _to) onlyOwner: unchanged.

    event AnchoredV5(uint48 indexed l1BlockNumber, uint32 indexed termId, uint8 view, uint16 seat, uint8 kind,
                     bytes32 carriedCertHash, bytes32 vcHash, bytes32 ancestorsHash);
    error EtnaActive(); error EtnaNotActive(); error AnchorRegression(); error CheckpointConflict(); error TermMismatch();
    error ViewChangeMismatch(); error ForcedBlockMismatch(); error GenesisMismatch();
}

The inbox interface, including the migration functions, is on the Interface sketches page. P2P: nothing new; a receiver requires the anchor calldata in the payload's first transaction to equal the signed header's Etna fields, and a mismatch is an invalid message.

11. State machines

Inbox lifecycle (one DAO transaction forward, one back):
[SHASTA] --upgradeToAndCall(initEtna @ U)--> [INITIALIZED: propose ok, prove ok (no whitelist), register ok, no term grid, land reverts]
  --armEtna(T0 ≥ A + MIGRATION_LEAD) @ A--> [ARMED: as before, term grid fixed]
  --t ≥ T0 − FREEZE--> [FROZEN: propose reverts, prove ok]
  --t ≥ T0 and all proven--> [DRAINED @ drainedAt: land ok from the first term]
  --t ≥ T0 + DRAIN_DEADLINE and abandonShastaTail()--> [DRAINED (abandoned)]
  --DAO upgradeTo(shasta) + initRollback; clients ship ROLLBACK_TIME--> [SHASTA'] (unlanded Etna blocks void)

Anchor, per L2 block (any revert is an invalid block by A8):
tx0 = anchorV5(in) → A1 gate → A2 ring → A3 checkpoint (regression | conflict | save) → A4 term → A5 view ⇔ vcHash → A6 forced → A7 record → status 1

13. Attacks defended and not defended

  • TH17 false or stale checkpoint: defended at landing, bounded before it. A sequencer anchoring a fake root containing a fake L1 deposit can have its block attested only if ≥ Q attesters skipped V5(d); the range can never land (no header hashes to the fake root, and a real header has a different root); it is replaced and the sequencer earns nothing from it (no penalty: round 4 removed the abandonment rule, R4H-5). Before landing the poisoned record lives at most about an hour, which is why bridge withdrawals should wait for "landed" and why the unchanged Bridge quota bounds the residual.
  • TH4 and W1: defended. Term, view, seat, carried certificate and view-change hashes sit in the anchor calldata, hence in blockHash, hence under the sequencer's signature; equivocation evidence names them whatever the envelope said.
  • TH12 reorg of an anchored block: defended, residual. A reorg deeper than 48 s invalidates the block identically everywhere; the certified suffix is unlandable and replaced; the holder loses the suffix's revenue and pays no penalty (round 4: no rule reads a missing landing).
  • TH2 prover cartel at migration: defended. Whitelisted Shasta provers can delay the first Etna landing by at most a day; then anyone voids their unproven tail.
  • TH7 across the cut-over: defended. Queue entries survive with their save time and become due under the new rule.
  • TH8 migration griefing: defended. No Etna rule debits anyone before the drain; the genesis check is an equality against the SignalService; the Shasta-tail void (M2) is gated only by time and puts no bond at stake.
  • TH19 DAO inaction: defended. After armEtna nothing needs the DAO; a hostile rollback cannot rewrite landed history without also upgrading the SignalService.
  • TH20 image rotation across migration: defended. Two verifiers coexist and neither path can write the other's checkpoint.
  • TH25: defended for this block's constants through the published parameters; the guest parses L1 headers itself, so an L1 header-format change is a guest release, not an inbox upgrade. Not defended: an L1 fork moving the state-root field index (none scheduled).
  • TH21 SignalService pause: unchanged. saveCheckpoint has no pause gate: a paused SignalService never blocks landing or anchoring; bridging halts, the rollup does not.

14. Failure analysis

  • Sequencers all offline. No new checkpoints on L2, so L1→L2 messages wait; L2→L1 messages in landed blocks are unaffected; the sequencing page's fallbacks apply. All malicious: stale-but-true anchors bounded by ANCHOR_MAX_AGE; false anchors unlandable, replaced, unpaid; they cannot write a surviving bad checkpoint into either SignalService.
  • Attesters all offline. Blocks are sequenced only and unlandable until dead mode; anchors in dead-mode blocks are still L1-bound. All malicious: bounded per TH17; they cannot make a false checkpoint land.
  • Landers and provers all offline. No checkpoints; L2→L1 bridging stalls; L1→L2 continues on the attested chain; after 4.55 h at 2-s slots anchored blocks fall out of the 2935 window and certified ranges become unlandable, which only shortens the replacement path.
  • L1 builders. Can delay landings or reorg an anchored block; cannot forge a checkpoint.
  • DAO offline after U. Etna runs; the 25 % accumulates; no rollback possible (not a liveness need). Execution-client maintainers. A missed fork release forks the client set, as for any hard fork; mitigated by the lead time.

15. False positives and false negatives

  • Anchor age. FP: an attester more than 48 s behind L1 holds the block as pending; a sequencer whose L1 node is dead for 30 minutes produces blocks that fail V5 and that no honest attester certifies, so its term is blank: its blocks at lock + 1 and lock + 2 are signed, available and pass V1, V2 and V6, so no attester times it out; it earns nothing and pays nothing (round 5, R5H-1). FN: anchoring at exactly 30 minutes each block keeps L1→L2 latency at the bound without penalty.
  • Reorged anchored block. FP: an honest holder's range is replaced after a deep reorg and it loses that range's revenue; no penalty. FN: none.
  • Checkpoint conflict (A3). FP: none on the canonical chain. Receipt rule (A8). FP: none; it closes today's silent-gap FN.
  • Drain deadline. FP: a proposal that would be proven at hour 25 is voided; no bond at stake. Genesis and first term. None: both are L1 storage.

16. Robustness

6/4/2-s slots: no rule counts slots; the only block-denominated bounds are L1-given (blockhash 256, EIP-2935 8191) and shrink to 512 s and 16,382 s at 2 s; the worst anchor age keeps a 2.8× margin; the guest's header chain grows to about 2,880 headers, under the cap; blockhash alone fails below 12-s slots, so the 2935 path is the common one. Without Frame Transactions: nothing here depends on EIP-8141. ePBS Empty slots: execution block numbers stay contiguous; no gaps in blockhash or the 2935 ring; canonical-at-N+1 is why ANCHOR_MIN_AGE is 48 s rather than one block. EIP-4788: not consumed.

17. Claims

  1. proven No checkpoint reaches the L1 SignalService without a verified proof whose journal commits to the end height, hash and state root.
  2. proven (given T3 and EIP-2935 semantics) Every L1 checkpoint written by a block of a landed range is the hash and post-state root of an L1 block canonical at landing time.
  3. proven A block whose anchor reverts is in no landed range, so A1 to A7 are consensus rules.
  4. proven No SignalService, Bridge or Vault bytecode or storage changes.
  5. proven by layout: Inbox and Anchor slots 251-257 keep their declared types; additions lie inside the gaps.
  6. proven No interval exists in which Shasta prove and Etna land can both write a checkpoint.
  7. proven The migration needs exactly two upgrade-class DAO transactions on L1 (initEtna, then armEtna; round 4, R4-C5), one on L2, and no later admin action.
  8. proven Rollback needs no storage migration beyond the core-state fields and one ring slot.
  9. assumed Aliased term-record keys are already non-zero on mainnet (an archive read resolves it; if false, only first-lap writes cost fresh-slot gas).
  10. assumed Both execution engines implement the base-fee split exactly as taiko-geth; alethia-reth's executor was not read.
  11. assumed EIP-2935's address and 32-byte return convention stay as deployed; a change is an inbox upgrade with an overlap window.

18. Alternatives rejected

  • Keeping anchorV4 (the header needs the certificate hashes inside blockHash); freshness relative to a seal; a minimum anchor depth in L1 blocks (4 s at 2-s slots); a permissionless genesis-ready flag (replaced by a DAO-armed T0 and the drain-derived first term); a T0 fixed inside initEtna (round 3; removed in round 4 because it fixed the grid against an empty registry); a contract-enforced launch condition (a Sybil-able count would only be gamed); an inbox-recorded L1-hash log fed by landings (covers only blocks some transaction touched, and a dead pipeline is exactly when nobody does); a void rule for legacy forced inclusions; retiring the blob request entry point; the Anchor share as the reward pool (a bridge hop and a relayer near liveness economics, and the proposed sweep could not be relayed as written); a sequencer field or coinbase binding in the anchor; a batch id in the anchor; a hard drain that voids provable proposals; sequencing from T0 on the unfinalized tail; proof verification before the writes; a block-denominated maximum anchor age; certificate or rights verification inside the L2 Anchor (100k+ gas per block and coupling block production to fresh L1 state); a reduced reorg slash rate; an objective attester slash for certifying an L1-rejected anchor (a deep reorg would make honest attesters guilty); a one-day migration lead; a new inbox address with a SignalService bump (fallback only); anchoring through EIP-4788 roots.
