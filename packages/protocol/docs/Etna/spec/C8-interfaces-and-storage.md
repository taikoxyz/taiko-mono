## 2. Conventions

### C8-R01. Sketch status and precedence

**[assumed: proposed rule]** Every declaration in §3 to §9 is a sketch. For a function, event, error or struct the owning section's rule id fixes the semantics; C8 fixes the signature and, where C8-R02 to C8-R06 apply, the encoding. Where candidate A's page and a converged section declare one item differently, the section governs and the page's form is an erratum listed in §15; where two converged sections declare one item differently, C8 does not pick: §15 quotes both and names the owners who decide. Parameter names are descriptive and change no selector; a return type added to an existing selector changes no selector. **Adversary schedule:** an implementer reads two declarations of one struct (the page's and a section's) and ships the one that hashes differently; precedence names the one that governs and §15 lists every known pair. Source: interfaces page introduction ("this page is normative for evidence and struct types", round 4's D9 and R4-C6); C1 §3; DL-1, DL-4.

### C8-R02. The hashing convention

**[assumed: proposed rule]** Every protocol hash is `keccak256` over one canonical `abi.encode` of typed fields, never `abi.encodePacked` nor a bare concatenation. Signed messages and the objects C8-R16 tabulates with a tag put the domain tag (C8-R03) and the chain id first; a signed message carries its DOMAIN tag inside the encoding. The journal and `protocolParamsHash` are untagged under C2-R04, which governs (C8-R01); whether they should carry a tag is §15 item 2. The fixed exceptions to the tag-first order, each one `abi.encode` of the fields in this order, are S1's: the holder walk `abi.encode(bytes32 seed, uint8 1, uint32 t, uint16 k)` (S1-R12), the committee walk `abi.encode(bytes32 seed, uint8 2, uint32 t, uint16 m)` and the redraw walk `abi.encode(bytes32 seed, uint8 3, uint32 t, uint8 n, uint16 m)` (S1-R13), the seed accumulator `abi.encode(bytes32 seedAcc, uint256 block.prevrandao)` (S1-R11) and the sentinel opening object `abi.encode(bytes32("ETNA_DEAD"), bytes32 lastLanded.blockHash, uint32 t)` (S1-R16). C2-R02's blob payload (byte concatenation) and C1-R10's slot formulas are not hashes under this rule. The signed preimages are tabulated in C8-R16. **Adversary schedule:** two typed tuples that pack to one byte string (`abi.encodePacked` of adjacent dynamic or narrow fields), giving two messages one signature; a signature on one message type replayed as another (C8-R03). Source: interfaces page, hashing convention (adopted from PR #22188; exceptions fixed in the round 6 fix pass); S2-R03 (J-2 of J's review of #22197).

**[proven: injectivity, conditional on A-ABI and A-KECCAK]** Every preimage of this convention whose fields are all static is a sequence of 32-byte words with one word per field, so two tuples of one type with any differing field differ in that word, and two preimages whose first words differ are different byte strings. Distinct tags (C8-R03) therefore separate message types even when two preimages have equal length (for example, a DOMAIN_BLOCK digest and the sentinel object both have three words; their first words differ), and modulo a keccak collision no signature verifies as two message types.

**[proven: widths do not change bytes, conditional on A-ABI]** For a value that fits both, `uint48` and `uint64` (or any two unsigned widths) encode to the same word. A width disagreement between two declarations of one field therefore changes no hash, signature or vector while the value is in range; it changes only the range check. C8-R05 relies on this.

### C8-R04. Hash preimage against wire encoding (the SSZ question S2-R03 left)

**[assumed: C8's resolution, recording S2-R03]** S2-R03 fixed `phHash = keccak256(abi.encode(DOMAIN_PH, chainId, the twelve PH fields in declaration order))` and recorded the certificate page's `keccak(SSZ(PH))` as an erratum (J-2 of J's review of #22197, the arbiter's decision). C8 states the rule that decision implies for every object: **no SSZ byte string is ever hashed or signed**. The P2P wire encoding stays SSZ with snappy compression, as the interfaces page §4 states, because nodes exchange it and no rule reads its bytes; every signature and every hash an L1 contract, a node or the guest computes is over the C8-R02 preimage rebuilt from the decoded fields. On L1, `SignedObject.body` for kind HEADER (the evidence S3's `slashSequencerEquivocation`, `slashLockLie` and `slashInvalidNamedObject` take) is `abi.encode` of the twelve PH fields in S2-R03's order, S3 §9's form, not the page's "SSZ SignedHeader". **Adversary schedule:** two encodings of one object yielding two hashes, so a signer escapes S1 or S3a by having signed the "other" encoding; an L1 verifier forced to decode SSZ. Source: S2-R03; interfaces page §4 and `SignedObject`; S3 §9.

**[proven: the L1 recomputation is one concatenation, conditional on A-ABI]** All twelve PH fields are static, so `abi.encode(DOMAIN_PH, chainId, f1, ..., f12)` equals `abi.encode(DOMAIN_PH, chainId)` followed by `abi.encode(f1, ..., f12)`; the inbox computes `phHash` as `keccak256(bytes.concat(abi.encode(DOMAIN_PH, chainId), body))` after checking that `body` is exactly 384 bytes, without decoding SSZ or reordering fields.

### C8-R05. The width of L2 timestamps (uint48 against uint64)

**[assumed: C8's resolution of the width B's C1 verdict item 10 left open]** The value of an Etna L2 header timestamp is bounded by C1-R03 to C1's P-NUMBER profile, `[1, 2^48 − 1]` seconds, a validity bound checked where C1 and C7 check it. Every declaration that passes an L2 timestamp keeps the width it already has: `uint64` in C1's `revealCheckpoint(uint64, bytes)` and `OriginPinned(bytes32, uint64)`, `u64` in the wire `SignedHeader.timestamp` (C8-R16) and in PH (S2-R03). No Etna contract stores an L2 timestamp: every stored time of the inbox (`LastLanded.at`, `TermRecord.landedAt` and `landableFrom`, `FiEntry.savedAt`, `FiStall` fields, `EtnaConfig`) is an L1 time. L1 block numbers and L2 heights carried in a checkpoint stay `uint48` (`ICheckpointStore`, unchanged), and L2 heights in the landing surface stay `uint64` (C2 §10). **Adversary schedule:** a timestamp above `2^48 − 1` in an `uint64` field (refused by C1-R03's bound, never truncated); a guest and a contract that hash one timestamp at two widths (no effect, C8-R02's width lemma). Source: C1-R03, P-NUMBER; C2-R19 (`anchorNumber` `u48`); interfaces page §4.

**[proven: the resolution changes no selector, hash or stored slot]** It renames no type, so no selector moves; by C8-R02's width lemma no hash moves; no contract stores the value. The 48-bit bound is about 8.92 million years (§11). **Not resolved here:** the registry's `uint32` L1 times, a separate question (§15 item 8).

## 13. Argument and adversary coverage

**[proven: one encoding per object, conditional on A-ABI, A-KECCAK and C8-R04]** Every hashed or signed object has exactly one preimage (C8-R16's table), built from typed fields by `abi.encode` with a distinct first word per message type (C8-R03); the wire encoding is never hashed. So two honest implementations that decode the same fields compute the same hash, and a signature verifies for one message type only. The open preimages (§15 items 1 to 3, 11) are exactly the rows of the table without a formula; until they close, the conformance suite cannot be complete.

**[proven: R2 on the interface side, conditional on A-LAYOUT and C4's live audit]** Every proxy address (C8-R17), client-used shared-contract selector (C8-R14) and inherited slot (C8-R15) is kept; additions are as C8-R17's compatibility claim lists.

| Attack trace [assumed: adversarial schedule] | Result under the cited rules, or explicit limit |
|---|---|
| A signer escapes S1 by claiming it signed the SSZ form. | No SSZ form is signed (C8-R04). |
| A REPLACE vote numbered as TIMEOUT by a client. | One numbering (C8-R06); until B accepts it, an open conformance risk. |
| A cached received signal proven against a rolled-back checkpoint. | **Open:** C2-R21 epochs the checkpoint map but not the received-signal cache (§15 item 7). |
| Bond selectors move from `uint64` to `uint256` arguments. | **Open:** §15 item 6. |
