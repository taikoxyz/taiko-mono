C8 is the one owner of the physical layout of every new Etna storage item, the Inbox's `LastLanded` and `ProvisionalRecord` and the SignalService floor list included (C2-R21, C1-R10, C4-R11). **[assumed: notation]** **assumed** heads a proposed rule or a premise; **proven** means an argument on this page, not machine verification; **open** means unresolved, with the closure condition named. `C8-Rnn` has one normative definition. §11 is C8's only numeric register. `‖` denotes the fields of one canonical `abi.encode` (C8-R02). "Page" means candidate A's design page named; "round n, id" cites candidate A's red-team iteration that produced a rule; "after the #22188 review" cites A's 2026-10-01 revision on B's review of PR #22184.

## 2. Conventions

### C8-R01. Sketch status and precedence

**[assumed: proposed rule]** Every declaration in §3 to §9 is a sketch. For a function, event, error or struct the owning section's rule id fixes the semantics; C8 fixes the signature and, where C8-R02 to C8-R06 apply, the encoding. Where candidate A's page and a converged section declare one item differently, the section governs and the page's form is an erratum listed in §15; where two converged sections declare one item differently, C8 does not pick: §15 quotes both and names the owners who decide. Parameter names are descriptive and change no selector; a return type added to an existing selector changes no selector. **Adversary schedule:** an implementer reads two declarations of one struct (the page's and a section's) and ships the one that hashes differently; precedence names the one that governs and §15 lists every known pair. Source: interfaces page introduction ("this page is normative for evidence and struct types", round 4's D9 and R4-C6); C1 §3; DL-1, DL-4.

**Failure behaviour [assumed: stated from the rule text, no behaviour added]:** no failure path: definitional. C8-R01 orders declarations between documents; it takes no on-chain, node or wire input, so nothing is refused under it. A divergence it finds is either resolved (the section's form governs and the page's form is an erratum in §15) or quoted in §15 for the named owners, and C8 picks no form where two converged sections differ; neither outcome is a revert or a verdict. A deployed declaration that follows a non-governing form fails the governing rule's own check or vector, with that rule's error (semantics are the owning rule's, §1). **Vectors:** C8-V16 (a page against a section; two converged sections), C8-V17 (parameter names and an added return type move no selector).

### C8-R02. The hashing convention

**[assumed: proposed rule]** Every protocol hash is `keccak256` over one canonical `abi.encode` of typed fields, never `abi.encodePacked` nor a bare concatenation. Signed messages and the objects C8-R16 tabulates with a tag put the domain tag (C8-R03) and the chain id first; a signed message carries its DOMAIN tag inside the encoding. The journal and `protocolParamsHash` are untagged under C2-R04, which governs (C8-R01); whether they should carry a tag is §15 item 2. The fixed exceptions to the tag-first order, each one `abi.encode` of the fields in this order, are S1's and C4's: the holder walk `abi.encode(bytes32 seed, uint8 1, uint32 t, uint16 k)` (S1-R12); the committee and redraw walks, one layout `abi.encode(bytes32 seed, uint8 kind, uint32 t, uint8 n, uint16 i)` with `kind = 2` for the initial walk and `kind = 3` for a redraw, `n` the redraw count (0 for the initial walk) and `i` the draw counter, no `m` input (S1-R13 at `74e6f88`, D19; this replaces the two `m`-bearing layouts of the earlier head); the seed accumulator `abi.encode(bytes32 seedAcc, uint256 block.prevrandao)` (S1-R11); the sentinel opening object `abi.encode(bytes32("ETNA_DEAD"), bytes32 lastLandedHash, uint32 t, uint48 l1RefNumber, bytes32 l1RefHash)`, five words, its L1 reference added by D38(b) (S1-R16); and C4-R08's bootstrap opening `genesisOpening = keccak256(abi.encode(bytes32("ETNA_GENESIS_OPEN"), genesisLockHash))`, which carries no chain id of its own because `genesisLockHash` binds `l2ChainId` as its second word. C4-R08's `genesisLockHash` follows the tag-first order (`bytes32("ETNA_GENESIS_V1")`, then `uint256(l2ChainId)`). C2-R02's blob payload (byte concatenation) and C1-R10's slot formulas are not hashes under this rule. Nor is the L2 header `mixHash` of C7-R10, `keccak256(abi.encode(uint256 parent.difficulty, uint256 number))`, an execution-layer field inherited from Shasta and kept untagged so the execution client's hash is unchanged [assumed: inherited; revision note 2026-10-03, finding forced-inclusion-02]. The signed preimages are tabulated in C8-R16. **Adversary schedule:** two typed tuples that pack to one byte string (`abi.encodePacked` of adjacent dynamic or narrow fields), giving two messages one signature; a signature on one message type replayed as another (C8-R03). Source: interfaces page, hashing convention (adopted from PR #22188; exceptions fixed in the round 6 fix pass); S2-R03 (J-2 of J's review of #22197).

**Failure behaviour [assumed: stated from the rule text, no behaviour added]:** no failure path of its own: definitional. C8-R02 fixes how each protocol hash is computed and receives no input it could refuse. A value computed any other way (an `abi.encodePacked` or a concatenation whose bytes differ from the canonical preimage, a missing or misplaced tag or chain id, another field order) is not the protocol hash; it fails where the consuming rule compares or verifies it, with that rule's error or verdict (for example C8-R04's hash-before-decode comparison on L1, S2-R03's `phHash` at a node). Where every field is a full 32-byte word, `abi.encodePacked` yields the same bytes as `abi.encode`, so nothing fails and nothing needs to. **Vectors:** C8-V02 to C8-V04, C8-V06 and C8-V09 to C8-V11, the canonical values a consuming check compares against.

**[proven: injectivity, conditional on A-ABI and A-KECCAK]** Every preimage of this convention whose fields are all static is a sequence of 32-byte words with one word per field, so two tuples of one type with any differing field differ in that word, and two preimages whose first words differ are different byte strings. Distinct tags (C8-R03) therefore separate message types even when two preimages have equal length (for example, a DOMAIN_BLOCK digest and a DOMAIN_KEYREG message both have three words; their first words differ), and modulo a keccak collision no signature verifies as two message types. The one preimage with a dynamic field, `carriedCertHash` (C8-R16), ends in `aggSig` as ABI `bytes`: its head word is a fixed offset and its tail is a length word followed by the bytes, so two values of one type with differing `aggSig` differ in the length word or in a data word, and the convention stays injective.

**[proven: widths do not change bytes, conditional on A-ABI]** For a value that fits both, `uint48` and `uint64` (or any two unsigned widths) encode to the same word. A width disagreement between two declarations of one field therefore changes no hash, signature or vector while the value is in range; it changes only the range check. C8-R05 relies on this.

### C8-R04. Hash preimage against wire encoding (the SSZ question S2-R03 left)

**[assumed: C8's resolution, recording S2-R03]** S2-R03 fixed `phHash = keccak256(abi.encode(DOMAIN_PH, chainId, the twelve PH fields in declaration order))` and recorded the certificate page's `keccak(SSZ(PH))` as an erratum (J-2 of J's review of #22197, the arbiter's decision). C8 states the rule that decision implies for every object: **no SSZ byte string is ever hashed or signed**. The P2P wire encoding stays SSZ with snappy compression, as the interfaces page §4 states, because nodes exchange it and no rule reads its bytes; every signature and every hash an L1 contract, a node or the guest computes is over the C8-R02 preimage rebuilt from the decoded fields. On L1, `SignedObject.body` for kind HEADER (the evidence S3's `slashSequencerEquivocation`, `slashLockLie` and `slashInvalidNamedObject` take) is `abi.encode` of the twelve PH fields in S2-R03's order, S3 §9's form, not the page's "SSZ SignedHeader". **Adversary schedule:** two encodings of one object yielding two hashes, so a signer escapes S1 or S3a by having signed the "other" encoding; an L1 verifier forced to decode SSZ. Source: S2-R03; interfaces page §4 and `SignedObject`; S3 §9.

**[proven: the L1 recomputation is one concatenation, conditional on A-ABI]** All twelve PH fields are static, so `abi.encode(DOMAIN_PH, chainId, f1, ..., f12)` equals `abi.encode(DOMAIN_PH, chainId)` followed by `abi.encode(f1, ..., f12)`; the inbox computes `phHash` as `keccak256(bytes.concat(abi.encode(DOMAIN_PH, chainId), body))` after checking that `body` is exactly 384 bytes, without decoding SSZ or reordering fields.

**[assumed: the objects an L1 contract recomputes (J-1 of J's review of #22210)]** Two kinds of C8-R16 byte string are decoded on L1, both `abi.encode` preimages and neither a wire form. (1) PH: the inbox receives it as the 384-byte `SignedObject.body` (and, for S6, as `S6Ancestry.ancestorPh`, S3 §9 at `d97f1fb`), rebuilds `phHash` by the concatenation above and reads the PH fields its rule needs (`termId`, `view`, `vcHash`, `height`, `carriedCertHash`, `parentHash`, `blockHash`) as words at fixed offsets of that same body. (2) The named-object preimages an accuser supplies as raw `bytes`: S6's `_preimage` of `slashInvalidNamedObject` and the carried-certificate preimage `_carriedCert` that S3 §9 at `d97f1fb` adds to `slashLockLie` in the same form. S3-R08's S6 row and S2-R21 read fields out of them: for a carried certificate its `(t, v)`, its `height` against `{n − 1, n − 2}`, its `phHash`, the popcount of its `bitmap` and its aggregate `aggSig`; for a view change its `(t, v, kind)`, `lockHeight`, `lockPhHash` and `l1Ref`. Each is decoded only after its keccak256 equals the hash the signed header names, and only in the canonical layout of C8-R16: the `vcHash` preimage is exactly 320 bytes, ten static words read at fixed offsets (word 0 `DOMAIN_VC`, word 1 the chain id, then `termId`, `view`, `closes`, `kind`, `lockHeight`, `lockPhHash`, `l1RefNumber`, `l1RefHash`), compared with `PH.vcHash`; the `carriedCertHash` preimage is exactly 448 bytes, compared with `PH.carriedCertHash`, its nine static words at fixed offsets (word 0 `DOMAIN_CERT`, word 1 the chain id, then `termId`, `view`, `vcHash`, `redraw`, `height`, `phHash`, `bitmap`), word 9 the offset of `aggSig`, required to equal 320, word 10 its length, required to equal 96, and words 11 to 13 the 96 signature bytes. Requiring word 0 to be the form's own tag is how a preimage is hashed under its form's tag and never the other (S2-R21: a view change's logical preimage never decodes as a certificate). Every other object of C8-R16's table is verified from its `abi.encode` preimage alone: the inbox builds the preimage from ABI-typed calldata fields and checks a signature or a hash over it. No L1 path decodes SSZ, snappy or any other wire form, so PH and these accuser-supplied preimages are the only C8-R16 byte strings with a decode path on L1.

### C8-R05. The width of L2 timestamps (uint48 against uint64)

**[assumed: C8's resolution of the width B's C1 verdict item 10 left open]** The value of an Etna L2 header timestamp is bounded by C1-R03 to C1's P-NUMBER profile, `[1, 2^48 − 1]` seconds, a validity bound checked where C1 and C7 check it. Every declaration that passes an L2 timestamp keeps the width it already has: `uint64` in C1's `revealCheckpoint(uint64, bytes)` and `OriginPinned(bytes32, uint64)`, `u64` in the wire `SignedHeader.timestamp` (C8-R16) and in PH (S2-R03). One L2 timestamp is hashed at `uint48`: the legacy genesis parent's `timestamp` in C4-R08's `genesisLockHash` preimage, an L2 time at `uint48` under C1's P-NUMBER, the width that declaration already has. Subject to §15 item 23, no Etna contract stores an L2 timestamp: C4-R11's namespace stores the bootstrap identities, whose fields are open in item 23, and if they include the genesis parent's timestamp it is stored at C4-R08's `uint48`. Every other stored time of the inbox (`LastLanded.at`, `TermRecord.landedAt` and `landableFrom`, `ProvisionalRecord.landedAt`, the activation and restart times of C4's migration namespace, and the forced-inclusion times `s_i`, `base` and `hatchAt` of C3 at `76c6150`) is an L1 time; `hatchL1` and `hatchTip`'s key are L1 block numbers. L1 block numbers and L2 heights carried in a checkpoint stay `uint48` (`ICheckpointStore`, unchanged), and L2 heights in the landing surface stay `uint64` (C2 §10). An L1 block number in an ABI struct (`anchorNumber` in PH's `abi.encode`, `Replace.l1RefNumber`, the sentinel object's `l1RefNumber`) keeps its `uint48` value bound under C1's P-NUMBER; on the SSZ wire it travels as `u64`, because SSZ has no 48-bit integer (C8-R16; B-C8-01). **Adversary schedule:** a timestamp or L1 number above `2^48 − 1` in a `uint64` or `u64` field (refused by C1-R03's bound or C8-R16's wire bound, never truncated); a guest and a contract that hash one timestamp at two widths (no effect, C8-R02's width lemma). Source: C1-R03, P-NUMBER; C2-R19; interfaces page §4.

**Failure behaviour [assumed: stated from the rule text, no behaviour added]:** C8-R05 adds no check of its own and moves no width. A timestamp or L1 number above `2^48 − 1` in a `uint64` or `u64` field is refused where C1-R03's bound is checked (by C1 and C7, with their verdicts) or, on the wire, by C8-R16's receiver before any conversion (C8-V08's negative); no declaration truncates it. A value in range hashes to one word at either width, so a width disagreement has no failure to report (C8-R02's width lemma, C8-V06). **Vectors:** C8-V06, C8-V08.

**[proven: the resolution changes no selector, hash or stored slot]** It renames no ABI type, so no selector moves; by C8-R02's width lemma no hash moves, the wire `u64` included, since every hash is over the `abi.encode` word rebuilt from the decoded value (C8-R04); no stored slot moves, since no contract stores an L2 timestamp except, subject to item 23, C4's genesis parent timestamp at the `uint48` C4-R08 already gives it. The 48-bit bound is about 8.92 million years (§11). **Not resolved here:** the registry's `uint32` L1 times, a separate question (§15 item 8).

## 9. P2P messages

### C8-R16. Wire formats and signed preimages

**[assumed: proposed formats; the wire is SSZ with snappy (interfaces page §4); topics, streams and limits are S2-R22's]** Topics `/etna/{chainId}/1/{blocks, attestations, views}`.

**[assumed: SSZ integer widths (B-C8-01 of B's W12 verdict on #22210)]** SSZ defines unsigned integers of 8, 16, 32, 64, 128 and 256 bits only; it has no 48-bit type. Every field that an ABI struct of this section declares `uint48` (PH's `anchorNumber`, `Replace.l1RefNumber`, `SentinelOpening.l1RefNumber`, and any other L1 number or time) travels on the wire as SSZ `u64`, little-endian in eight bytes, and a receiver rejects the message, before any conversion, when the decoded value exceeds `2^48 − 1`, C1's P-NUMBER bound for L1 numbers (C1 §6). The hash and the signature never see the wire bytes: the receiver rebuilds the `abi.encode` word from the decoded value (C8-R04), a big-endian 32-byte word, which by C8-R02's width lemma is the word a `uint48` declaration gives. So the wire width changes no hash, no signature and no vector, and a six-byte and an eight-byte implementation cannot disagree about the offsets that follow, since only the eight-byte form is valid. Vector C8-V08 fixes one value through both encodings.

### C8-R18. The manifest field set C3 handed to C8

## 13. Argument and adversary coverage

**[proven: one encoding per object, conditional on A-ABI, A-KECCAK and C8-R04]** Every hashed or signed object has exactly one preimage (C8-R16's table), built from typed fields by `abi.encode` with a distinct first word per message type (C8-R03); the wire encoding is never hashed and no wire form is ever decoded; PH and the accuser-supplied named-object preimages of S6 (with `slashLockLie`'s carried-certificate preimage, the same form) are the only `abi.encode` byte strings an L1 contract decodes, each at fixed offsets and only after its keccak256 equals the hash a signed object names, and every other object is rebuilt from ABI-typed calldata (C8-R04). So two honest implementations that decode the same fields compute the same hash, and a signature verifies for one message type only. The open preimages (§15 items 2, 3, 11, 27) are exactly the rows of the table without a byte layout; until they close, the conformance suite cannot be complete.

**[proven: R2 on the interface side, conditional on A-LAYOUT and C4's live audit]** Every proxy address (C8-R17), client-used shared-contract selector (C8-R14) and inherited slot (C8-R15) is kept; additions are as C8-R17's compatibility claim lists; the QuotaManager keeps its address and storage without an upgrade.
