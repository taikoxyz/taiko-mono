## 1. Boundary, evidence and claim convention

**[assumed: section boundary]** C4 owns the authenticated migration state machine, finite legacy tail, disposition of forced requests and their already-paid fees, initialization of the Etna parent, the retained-surface change table, activation/deployment sequencing, and the permitted forward rollback boundary. C1 owns the execution profile, current-root writer guards, checkpoint/pin semantics and epoch-floor lookup; C2 owns landing, provisional custody roots, CONFLICT and the rollback-floor obligation; C3 owns the normalized FI entry and its execution/void/refund rules; C7 owns the complete validity predicate; C8 owns the consolidated ABI/storage manifest. S1 owns the term grid and registry; S2 owns opening objects; S3 owns ongoing rewards and ledger accounting. This section states no second version of their ordinary rules.

**[assumed: claim convention]** A proposed rule is marked **assumed**; **proven** identifies a conditional argument or a source fact, not implemented verification; **open** names an unresolved choice or required evidence. Every `C4-Rnn` has one normative definition here. Number definitions are in §9; quoted numbers retain their owning section. An exact source layout is not proof of the deployed layout.

| Premise | Required meaning |
|---|---|
| A-MANIFEST | The authorized upgrade commits the complete deployment/revision manifest of C4-R01; actual deployed state, code and owner paths match it. |
| A-LEGACY | The inherited finalized roots, sent signals, received-signal caches, Bridge statuses, custody and wrapper accounting at the boundary are sound. Copying a compromised root cannot establish this premise. |
| A-LEGACY-PROOF | The retained, audited legacy verifier proves the exact legacy transition and authenticated boundary header. Prover admission is permissionless; program soundness and historical data availability are separate premises. |
| A-EXEC | C1's builder/importer/guest parity, including guarded pre-Etna system operations. |
| A-DATA | Full proposal preimages and their original FI `BlobSlice` records can be obtained from authenticated L1 history. Unexpired blob contents additionally remain retrievable when execution needs them. A proposal hash alone does not supply its preimage. |
| A-RECOVERY-FUNDING | At least one actor can pay bounded migration calls and, if needed, proving/landing of the requeued work. The zero-fee requeue does not repay a proof provider or recover the old proposer's payment. |
| A-UPGRADE | Future DAO upgrades are the explicit governance trust boundary. The installed revision cannot assume a future arbitrary upgrade preserves its invariants. |

**[proven: inspected source]** Source citations below are the tree at `bfc09641794cbc172a3255a416a93d0a10a23a1f` (BASE), not assertions about a live deployment. ## 2. Installation, freeze and drain

### C4-R01. One committed migration manifest

**[assumed: proposed rule]** The initial DAO upgrade commits `migrationManifestHash`, an immutable-in-this-revision hash of a canonical C8 encoding. The manifest fixes both chain IDs; all retained proxy and nonproxy dependency addresses; old/new code hashes and implementation immutables; proxy kinds and implementation/admin/beacon slots; linked libraries and verifier images; all initializer versions; DAO and DelegateController authority; resolver bindings; treasury withdrawal authority; checkpoint/cache/layout profiles; the deployed quota configuration and consumption state; every existing wrapper variant and active migration pair; the C1 utility runtime hashes; and the exact legacy proof/derivation revision. No migration caller may replace these with a supplied address, selected root or mutable resolver answer. A public verifier authenticates the required code hashes and storage/implementation slots under the finalized L2 boundary root; an address list or operator signature is not a proof of installation.

The manifest has an explicit no-code/no-route result for unused routers and old contracts. Every reachable alternate writer, fallback/delegatecall, resolver edge and inherited initializer is classified in C4-R10. Missing deployment history or an unsupported wrapper/active migration blocks arming; it does not authorize deleting liabilities. Any amendment is a new reviewed DAO upgrade, never an operational setter. **Adversary schedule:** omit a live router, substitute an implementation with a different immutable, retain a fast owner branch, or bless a compromised inherited cache. Cost: one incomplete deployment bundle; gain: bypass of the claimed custody/authentication boundary. The manifest and terminal-state proof are the countermeasure, conditional on A-MANIFEST/A-LEGACY.

### C4-R02. Ordered L2 prerequisites and guarded legacy operation

**[assumed: proposed rule]** Execute C1-R09's ordered sequence before the terminal legacy boundary: establish builder/sealer/importer/guest parity; activate EIP-2935; activate EIP-4788 so every guarded pre-Etna block records a successful zero current root; install the guarded Anchor and explicit-L2 SignalService, then close every alternate legacy writer. Deploy the canonical utilities through ordinary canonical deployment transactions with normal prefunding (or an explicit genesis allocation for a new network). No first-Etna-block code injection, synthetic transaction or custom operation is introduced. C1 owns the exact addresses, runtime hashes, operation order and gas allowances.

During the drain, legacy execution keeps its authenticated legacy derivation revision, Anchor transaction and fee/gas rules; the added standard utility operations must be supported by its proving path. The proof-backed boundary contains the required guarded implementations and utilities before an Etna child exists. Guard failures halt safely; unavailable code/read is never a zero root. The same guard remains installed through any later rollback. A prior standalone anchor-removal fork may satisfy prerequisites only if its exact resulting execution/proof profile is the manifest's legacy revision; it is not inherited by implication. **Adversary schedule:** the public golden-touch signer races the first Etna transaction, or a sealer omits a system operation importers execute. C1's nonzero current-root guard closes the former before ordinary transactions; parity is indispensable to the latter.

### C4-R03. Initialization and arming

**[assumed: proposed rule]** The in-place Inbox upgrade executes `initEtna` once, using the next audited initializer version (proposed 4, subject to the manifest). It verifies the supplied legacy end-height/header against the existing L1 SignalService checkpoint and `_coreState.lastFinalizedBlockHash`; the header hash, height, state root and timestamp are bound together. `_coreState` does not store that L2 height today, so a caller's height is insufficient without this equality ([Inbox:364](../../../contracts/layer1/core/impl/Inbox.sol#L364), [IInbox:83](../../../contracts/layer1/core/iface/IInbox.sol#L83)). Initialization stores an authenticated moving legacy boundary, opens S1 registration, and leaves the Etna landing head unavailable for use. It installs no usable zero-root parent.

`armEtna(T0)` is a one-time effect of the committed DAO upgrade payload, not a retained day-to-day owner setter, after initialization and after a finalized legacy checkpoint authenticates C4-R01/R02's required L2 installation. Require `T0 >= now + MIGRATION_LEAD`; T0 fixes S1's grid once. This draft moves the installation proof **before arming**, rather than relying on a later bridged upgrade completing before an already-fixed T0. All subsequent migration calls are permissionless predicates on the committed manifest, phase and authenticated state. The launch owner/seat count is S1's disclosed heuristic, not a safety gate or permission to ignore no-committee operation.

Until the freeze, the retained proposer checker may govern legacy `propose`; legacy `prove` drops its caller whitelist immediately at initialization, keeps all proof/parent/hash checks, and uses the manifest's legacy verifier only. Removing `_checkProver` must not accidentally introduce a new legacy bond debit: preserve the original ledger liabilities explicitly, and apply a legacy late-proof settlement only if its recorded configuration already required it. Mainnet BASE has both `minBond` and `livenessBond` zero ([MainnetInbox:37](../../../contracts/layer1/mainnet/MainnetInbox.sol#L37)); other networks require their own manifest. No Etna MISS/reward/seat debit is charged for a pre-activation term. **Adversary schedule:** a whitelisted prover refuses to act. It has no admission veto after initialization; inability of every prover to prove remains A-LEGACY-PROOF/A-DATA, handled by C4-R05's fallback rather than mislabeled a whitelist veto.

### C4-R04. Freeze and permissionless proof-backed progress

**[assumed: proposed rule]** At `T0 - FREEZE`, `propose` and the legacy forced-enqueue selector reject before value/state effects. Etna enqueue also rejects until ACTIVE. A public `freezeShasta()` snapshots the last proposal id `P = nextProposalId - 1`, queue `head H` and `tail Q`, and the proposal-ring size; the timestamp guards already prevent a late caller from extending them. This finite intake gap is a disclosed migration cost: clients retain unsubmitted requests and resubmit after activation; the contract accepts no fee or request liability during the gap. Closing intake is this draft's explicit completion bound, not a new administrative pause.

While FROZEN/DRAINING, anyone proves the already-proposed suffix through the retained `prove`. Every successful proof atomically updates the authenticated legacy boundary using `Commitment.endBlockNumber`, `endStateRoot` and its final transition hash, writes the existing checkpoint, and verifies the old proof with revert rollback ([Inbox:321](../../../contracts/layer1/core/impl/Inbox.sol#L321)). The queue head cannot change: it moved at proposal time, not proof time. No new discretionary or forced-only legacy proposal is created by this selected migration route. When all ids through P are finalized, `finishDrain` closes legacy proving and records READY. Pending never-proposed queue entries survive for C3; they do not need to drain under the legacy engine before READY.

**[proven conditional]** A whitelisted party cannot gate this proof-backed phase, because `prove` has no caller whitelist. B's full proof-backed alternative also proposed deterministic permissionless legacy forced-only proposals until the frozen queue was empty; that would preserve original derivation for all accepted requests, but its completion still depends on legacy data and proving availability. The selected fallback below accepts loss of the ordinary unfinalized tail after a fixed deadline. It must not be justified by the incorrect statement that *every* proof-backed drain necessarily retains a prover whitelist.

**Adversary schedule:** submit a proposal or paid forced enqueue after the timestamp cutoff, or repeatedly postpone the public freeze call to grow the tail. The entry-point timestamp guards reject before value effects, so a delayed snapshot still captures the fixed tail. Cost: one rejected transaction; gain: none beyond ordinary inclusion delay.

### C4-R05. Authenticated abandonment with an explicit phase lock

**[assumed: proposed rule]** After `now >= T0 + DRAIN_DEADLINE`, if P is not finalized, anyone may start ABANDONING. The call snapshots the actual last-finalized id F and its authenticated boundary, the frozen P and consumed head H, and **closes legacy `prove` in the same transaction before any abandonment progress**. Ordinary transaction ordering decides a proof racing this call: a proof first updates F; an abandonment first makes the proof revert `ProvingClosed`. No half-abandoned range remains provable. This explicit phase lock replaces A's reliance on a fabricated finalized pointer and an argument that no future proof could extend it.

`abandonShastaTail(Proposal[] chunk)` processes **descending proposal ids**, starting at P and ending at F+1. Each chunk starts at `scanPrev`, contains 1 through MIGRATION_CHUNK_MAX consecutive descending ids and at most MIGRATION_CHUNK_MAX forced sources in total. Each full Proposal must hash under the existing codec to `_proposalHashes[id % ringBufferSize]`; it must also match the parent hash expected from the previously processed higher proposal. Its forced sources form the legacy forced prefix, followed by the ordinary source, with the exact legacy shape bound. The final low proposal must link to the authenticated proposal F. The ring-capacity check at [Inbox:592](../../../contracts/layer1/core/impl/Inbox.sol#L592) preserves every unfinalized proposal, while [Inbox:286](../../../contracts/layer1/core/impl/Inbox.sol#L286) stores its hash. A hash cannot recover its preimage: callers still need A-DATA, and a missing preimage is an explicit availability blocker, not authority to guess a source count.

Maintain `repairHead`, initially H. For a proposal with n forced sources, require `n <= repairHead`, match its ordered source BlobSlices exactly against retained queue entries `[repairHead-n,repairHead)`, set only those entries' already-paid fee fields to zero, then decrement `repairHead` by n and `scanPrev` by one. Complete source equality includes every blob hash, offset and timestamp; no separate accumulator-opening proof or stored proposal copy is needed. **The visible queue head stays H until every proposal and source is checked and repaired.** The final call moves it once to `repairHead = H-N`, records the abandoned id interval separately, and sets DRAINED; `finishDrain` authenticates the terminal installation before setting READY. It never writes an unproved id/hash into `_coreState.lastFinalizedProposalId`/`lastFinalizedBlockHash`; those remain the actual finalized boundary. The old proposal ring is frozen evidence until completion. No call after DRAINED repeats a repair or requeues an entry again.

**[proven conditional]** Forced sources were dequeued FIFO in proposal order; the unfinalized tail's N sources are exactly the suffix `[H-N,H)` of consumed requests. The existing code retains queue records and pays their fees before writing the new head ([Inbox:703](../../../contracts/layer1/core/impl/Inbox.sol#L703)). Scan authenticity, exact order, one phase lock and one final head write therefore exclude omitted sources, duplicated requeue and simultaneous legacy-finalized/Etna-requeued execution. **Adversary schedule:** duplicate chunk, reversed proposals, count-only lie, prove between chunks, head decrement before all fees are cleared, or reusing a ring cell after new landings. Every case fails the phase/range/commitment checks. Migration-call gas and source-preimage availability remain unmeasured/assumed; no “one call, 4 M gas” guarantee is claimed.

### C4-R06. Forced-request continuity and funding

**[assumed: proposed rule]** Preserve each legacy entry's full source identity: one original KZG versioned hash, blob offset, saved timestamp and original codec/revision, never just a hash with the offset discarded. C3's `fiEntry` normalizes it as a legacy blob entry without a requester or bond. A never-proposed entry retains its escrowed `feeInGwei * 10^9`; a requeued already-paid entry has fee zero, no refund entitlement and no second includer credit. Requests finalized before abandonment are not requeued. Old ordinary proposal transactions are not resurrected as forced requests; users may resubmit them with current nonce/fee validity. Historical preconfirmations outside the finalized boundary have no canonical or custody status.

The requeue does not claw back the original proposer's fee. It creates no token transfer, new bond or synthetic requester, and cannot use user custody, unrelated FI fees or TAIKO bond balances as a subsidy. C2/S3 fund ordinary Etna landing through the actual holder's reserve under their existing formulas; a certificate-free forced batch still needs an actor funding its two proofs and L1 inclusion under A-RECOVERY-FUNDING, and a zero-fee batch may pay that actor nothing. C3 owns the irreversible per-entry settlement rule adopted in D18; migration and later recovery consume it without defining another status machine. A requeued legacy id's already-paid fee is zero and legacy no-requester/no-bond classification persists; migration never clears a later Etna settlement marker or permits another credit/refund/burn. Old Inbox ETH balances, outstanding fees and already-paid amounts are reconciled in the manifest and C3/S3's liability ledger before activation.

**[open: C3 legacy-compatibility obligation]** A legacy source is not necessarily a valid new-entry shape. BASE's [Derivation:198](../../../docs/Derivation.md#L198) requires one forced block, overwrites its header metadata and inherits the parent's gas limit; [Derivation:373](../../../docs/Derivation.md#L373) gives 10 M through 45 M ordinary gas bounds, whereas C3 currently assigns FI_GAS_LIMIT 5 M. C3 must publish a versioned LEGACY_BLOB decoding/resource rule or an explicitly approved changed service promise before this requeue is specified as execution-compatible. New submission caps must not silently retroactively reject an authenticated old blob. An old request may already have state-invalid transactions, missing data, or the D12 stall/expiry outcome; those outcomes do not prove successful execution of the original request. C4 supplies exact source/version/accounting and does not privately override C3's content predicate.

**Adversary schedule and cost.** A prover cartel can force the deadline path; it loses no bond merely for nonservice, and the old proposer may keep up to ten original FI fees per abandoned proposal. At the historical 0.001 ETH floor that is 0.01 ETH per ten-source proposal, but queue-scaled fees may be larger. The ordinary tail is lost; authenticated FI liabilities survive with the stated zero-fee economic limitation. Repeating a proof or requeue cannot collect a second legacy fee. R1 has no whitelist veto on this path; it is not an unconditional economic guarantee that somebody will prove for free.

## 3. The authenticated first Etna parent

### C4-R07. Drain anchor and activation

**[assumed: proposed rule]** READY means the finalized boundary is fixed, all abandoned-request repair is complete, the exact terminal L2 root authenticates C4-R01/R02's required installations, and legacy write/proof/intake paths are closed. `activateEtna` is permissionless once READY and `now >= T0`. Its supplied L1 execution-header witness D must be the canonical **immediately preceding L1 block**, verified by `blockhash(block.number-1)` with canonical header decoding and `D.number == block.number-1`, and D's number must be at least `readyAtL1Block`. Derive its timestamp from that header; record `drainL1Number`, `drainL1Hash` and `drainedAt = D.timestamp`. Using an already-existing block avoids pretending the Inbox can read the hash of its current execution block.

Set the minimum starting term once as

```text
firstEtnaTerm = max(1, ceil((max(block.timestamp, drainedAt + C7.ANCHOR_MIN_AGE) - T0) / S1.TERM))
```

with checked widths. This absorbs the 48-second origin minimum before the first term; the explicit `max(1,...)` prevents `lastLandedTerm = firstEtnaTerm-1` underflow even if activation occurs exactly at T0 after a long L1 gap and `D.timestamp+48 <= T0`. No maximum L1 slot gap is assumed. Set `lastLanded.at = activation timestamp`, its anchor floor to D, and `fiClearTip = drainedAt`; its L2 height/hash/state root remain the actual finalized legacy boundary. Set the queue cursor to the restored head and reset only C3's **new** stall/escalation initialization, not legacy request data or monetary liabilities. The synthetic parent anchor floor does not rewrite the legacy execution header or historical Anchor storage.

Activation is one atomic L1 transition to ACTIVE. The same Inbox proxy remains the L1 SignalService's authorized syncer; legacy `prove` cannot coexist with `land`, so no second writer can choose a root between them. C2 governs every later checkpoint publication, including provisional status. No DAO action is required after arming under the named premises; migration API calls, including activation, are unbonded and permissionless. **Adversary schedule:** a caller chooses a higher unpublished genesis root, fabricates D, activates before repairs finish, or waits until the originally planned first term has elapsed. State-derived boundary checks, exact D and the activation-derived first term prevent those changes; normal transaction funding/inclusion is still assumed.

### C4-R08. Bootstrap identity and first-header obligations

**[assumed: proposed rule]** The genesis parent is the exact finalized legacy block `(height, hash, stateRoot, timestamp)`, not an EVM genesis allocation and not the merely highest caller-supplied checkpoint number. Define a distinct bootstrap lock identity with C8's canonical ABI convention:

```text
genesisLockHash = keccak256(abi.encode(
  bytes32("ETNA_GENESIS_V1"), uint256(l2ChainId), address(inbox), bytes32(manifestHash),
  uint48(height), bytes32(blockHash), bytes32(stateRoot), uint48(timestamp),
  uint48(drainL1Number), bytes32(drainL1Hash), uint48(drainedAt), uint32(firstEtnaTerm)
))
genesisOpening = keccak256(abi.encode(bytes32("ETNA_GENESIS_OPEN"), genesisLockHash))
```

These are bootstrap objects, not forged sequencer PHs or committee signatures. C2 initializes `lastLanded.phHash` and `lastVCHash` from them; C8 fixes their journal/ABI representation. The unique first Etna **height** is `height+1`; H3's GENESIS_CHILD exemption keys on that authenticated height and parent hash, never just “a child of some Shasta block.” Its origin number/hash is at or above D and it obeys C7's age window; it executes both C1 standard system operations before its ordinary transactions and has no Anchor transaction. No special receipt, first-block initializer or voluntary reveal is required.

**[proposed integration, C7/S2 review required]** D17's ordinary signer default is the first term's S1 leader, `leader(firstEtnaTerm,0)`, with any deterministic void-view skipping defined by S1. First production may instead follow S2's validated takeover chain or a valid S1 sentinel regime. GENESIS_CHILD is permitted at that one height with the **actual authorized view**, including 255 when S1 selects no-committee/open-empty/dead recovery; `(0,GENESIS_CHILD)` alone is insufficient. For the initial view use `genesisOpening` and the authenticated bootstrap lock in place of a preceding VC/certificate. If empty initial views/timeouts/terms precede production, S2's validated opening chain must root at that same bootstrap lock; D16 permits a verified L1 migration-parent record instead of a nonexistent certificate over a Shasta PH. The first two produced-block carried fields need a uniquely encoded bootstrap/opening object under S2, after which normal carried-object rules apply. Logical opening identities exclude quorum bitmap/aggregate-signature witnesses under D16. C7/S2 own that regime-complete table and first-view transition semantics; C4-T07 is not closed until they consume these facts. No launch claim presumes eight committee members always exist.

**Adversary schedule:** reuse the GENESIS_CHILD exemption at a later height, claim a synthetic genesis certificate, or select a different genesis state under the same block number. One authenticated height/hash/root, domain-separated bootstrap identity and the S2 opening chain reject the attempt; unresolved sentinel/header cells are named integration blockers rather than implementation choices.

## 4. Retained custody, selectors and storage

### C4-R09. Preserve authenticated custody and evidence

**[assumed: proposed rule]** Retain both SignalService, both Bridge and every Vault/wrapper proxy address and both chain IDs. Keep the ordinary one-hop proof/message ABI, signal-slot formula, remote service identities, message-hash/status encoding, transaction/receipt encoding, canonical-token keys, supply/balances/allowances/NFT ownership, ERC20 migration liabilities and permit domains/nonces. No asset or message is “migrated” by sweeping it to a new vault or clearing a status/cache/map. A valid legacy NEW/RETRIABLE/FAILED message follows the same authenticated processing/retry/recall rules after activation; DONE/RECALLED history continues preventing replay. Preserve `recallEnabled` and every dependency immutable unless a row below explicitly changes it.

Existing checkpoint epoch 1 and received-signal cache VERSION 1 retain their slots. C1 changes non-overwriting checkpoint-write/getter semantics on inherited records as well as new ones: partial/corrupt inherited tuples must be resolved in the preflight, not blessed as duplicates. L2 pins and new reveals do not authorize reminting or resetting Bridge reimbursement state. Example: an old 100-token deposit still resides in the same source vault; one destination processing mints to the same mapped wrapper, and the retained DONE status blocks a replay. This argument needs authenticated legacy custody/cache validity, not just matching proxy addresses.

**[proven: unchanged source encodings]** The sent-signal slot is `keccak256(abi.encodePacked("SIGNAL", uint64(chainId), address(app), bytes32(signal)))` ([SignalService:170](../../../contracts/shared/signal/SignalService.sol#L170)); it is written directly, not under a sequential mapping root. The Bridge identity is `keccak256(abi.encode("TAIKO_MESSAGE", Message))` ([Bridge:536](../../../contracts/shared/bridge/Bridge.sol#L536)); Message field order/types remain `uint64 id, uint64 fee, uint32 gasLimit, address from, uint64 srcChainId, address srcOwner, uint64 destChainId, address destOwner, address to, uint256 value, bytes data` ([IBridge:24](../../../contracts/shared/bridge/IBridge.sol#L24)). Status values remain NEW=0, RETRIABLE=1, DONE=2, FAILED=3, RECALLED=4. The old full proof remains ABI-encoded `HopProof[]` of exactly one element, with `uint64 chainId, uint64 blockId, bytes32 rootHash, CacheOption cacheOption, bytes[] accountProof, bytes[] storageProof`; blockId must fit uint48 and account/storage proofs remain nonempty. Empty proof follows the retained cache-bit path, not the checkpoint getter ([SignalService:265](../../../contracts/shared/signal/SignalService.sol#L265)). C1's checkpoint epoch change never changes that cache domain by implication.

**Adversary schedule:** erase DONE while keeping the proxy address, change the canonical token key, or change the signal chain-id width. One replay can then remint or lose authentication. The exact encoding/state preservation obligations reject such an upgrade; matching addresses alone provides no defense.

## 5. Forward rollback and custody limits

### C4-R12. C2 CONFLICT restart without undoing published custody

**[assumed: proposed rule]** C2-R13/R14 govern provisional status and CONFLICT. The ordinary recovery floor is the newest **published** checkpoint preceding the conflicting provisional suffix; it cannot be lower than the newest published checkpoint. All later provisional records and their descendants are void and had published no usable checkpoint under C2-R15. Authenticate this floor from the old Inbox/SignalService state, not caller input. Preserve C2's retained evidence and term/FI monetary disposition; D18's per-id irreversible settlement survives an execution rewind, so replay never repeats a fee credit/refund/burn. The forward upgrade appends C1-R10's next `(epoch, floorHeight)` only through that committed upgrade effect, then restores the canonical head and C2/C3 restart values.

C1-R06 alone defines epoch selection, equality and writes; C4 invokes it without a second lookup rule. Current permitted C2 recoveries have nondecreasing published floors; a proposed lower floor is rejected, regardless of the lookup algorithm's ability to describe a hypothetical future extension. No fallback to hidden old records, overwrite, deletion, pin clearing or cache-version bump is added. C4/C8 check the actual floor count and lookup gas before append; cost is unmeasured and grows with governance history.

**[proven conditional custody boundary]** This argument depends specifically on C2-R13 and C2-R15: neither a provisional record nor a later landing covered by an unfinalized provisional record publishes a checkpoint. Therefore no checkpoint above the recovery floor was published and no valid L1 proof/cache/retry could derive authorization from that suffix. Preserving valid pre-floor received-cache bits and Bridge retry state is then safe under A-LEGACY and those two publication rules. A revision allowing publication from that suffix invalidates this argument and requires renewed C4 review; an epoch-floor lookup alone cannot restore it. L2 execution rollback restores its state, code, pins, checkpoints and Bridge statuses together; a checkpoint-epoch change on L1 is not a substitute for that execution rollback.

| Effect / history | Disposition under this section |
|---|---|
| Authenticated pre-migration checkpoint, received cache, DONE/RETRIABLE message | Preserve in place and preserve ordinary proof/retry behavior; A-LEGACY is required. |
| Effects on an unlanded L2 fork, including a bad-origin reveal/cache/retry | Replace the entire L2 execution suffix under C2; its state effects roll back together. No claim that a pin or checkpoint epoch alone revokes them. |
| Provisional L1 suffix before C2 publication | No custody checkpoint exists for it under C2-R15; restore to the newest published floor, preserving earlier valid caches/status. |
| A false root already published under C2's finalization assumption | C2-R14/C6's accepted L-PF residual: completed transfers cannot be revoked by this migration, and cached/retriable effects are not silently cleared. Existing quota bounds release rate only for configured assets/paths; it is not compensation or restoration. |
| Proposed recovery below a published checkpoint | Out of scope and rejected by C4-R13; requires a separate explicit custody recovery design. |

**Adversary schedule:** select a lower old checkpoint to revive a spent/cached message or reset a settled FI status during CONFLICT recovery. The newest-published-floor gate and C3's D18 irreversible settlement reject the attempt; an epoch append grants neither custody revocation nor another payout.

### C4-R13. Guarded return to a legacy execution profile

**[assumed: proposed rule]** A return to Shasta-like execution is a new forward DAO upgrade and client fork, never an automatic liveness fallback. It fixes an authenticated retained parent, a client ROLLBACK_TIME/profile and exact proof/derivation revision. Before the first zero-root successor, keep the C1 guards installed and reset Anchor `ancestorsHash = 0` only inside that guarded upgrade; until clients successfully record a current zero root the public golden-touch path still fails. At the selected successor, builder/importer/guest all restore the old mandatory Anchor/fee/gas/ancestor semantics together; the first allowed call recomputes the **ancestorsHash field** from execution block hashes, not from a persisted ring requiring a bulk backfill. Authenticate and preserve/restore `anchorBlockNumber` at the retained boundary too: [Anchor:182](../../../contracts/layer2/core/Anchor.sol#L182) writes a checkpoint only when the supplied number exceeds that field. Resetting ancestorsHash alone cannot establish checkpoint progress. Both standard utilities and their verified history remain active as the reviewed profile requires. No failed oracle read is interpreted as permission to run legacy code.

The L1 upgrade reconstructs legacy CoreState and one authenticated starting proposal/ring record from the retained published Etna checkpoint/header, with exact new ids and codec commitments from the rollback manifest. It cannot simply reinterpret the aliased term ring as legacy proposals. Existing TAIKO deposits, exit/withdrawal liabilities, FI pending/refund/fee records, proof records and evidence windows must reconcile; seat records become inactive only with outstanding obligations preserved. The old whitelist/proposer-checker bytecode may remain deployed, but its reactivation is an explicit policy decision, not an implicit migration default.

**[open: exceptional rollback below published custody]** This draft authorizes **no** rollback below a published checkpoint. Such a fork can leave `_receivedSignals[1][slot] == true`, completed custody transfers or RETRIABLE/FAILED messages authorized by the old root. C1's epoch floors hide checkpoints but revoke none of those effects: an empty-proof cache hit or retry can still spend, while resetting statuses can double-spend a legitimate completed message. A proposal crossing that boundary must supply and separately review a complete asset/message/cache disposition and any compensation/irreversibility policy; otherwise the upgrade is inadmissible under this section. There is no generic “reset all caches,” “mark everything DONE,” or re-prove-only shortcut. C2's L-PF irreversibility residual remains explicit.

**Adversary schedule:** install an unguarded old Anchor, reset ancestorsHash while omitting its guard, retain an unauthenticated anchorBlockNumber that suppresses checkpoint writes, reuse hidden checkpoint epochs, or replay a cache-backed retry after a lower rollback. The guard and authenticated retained-field/floor checks exclude the first four; the last is the reason for the published-custody prohibition, not a problem solved by map versioning.

Forced requests consumed only by that tail are authenticated and requeued, but their original proposer fee has already been paid and is **not recovered or paid again**. The requeue creates no new bond or refund entitlement and may need a requester/prover to fund replay. Users may need to resubmit ordinary transactions with current nonces/fees; successful inclusion is not promised for unavailable, expired, state-invalid or subsequently voided requests. C6 indexes this cost; it must also remain in the eventual migration lesson and operator/user runbook.

## 8. Requeue versus full proof-backed drain

**[assumed: decision proposal under DL-3]** Adopt a finite, permissionless proof-backed proposal drain, with authenticated abandonment/requeue after the deadline. This chooses A's availability escape and paid-fee loss, with C4-R05's stronger phase/accounting boundary. It declines B's requirement that every frozen request execute under the legacy engine before activation: that requirement preserves old derivation most directly but can keep activation waiting on unavailable data or a legacy proving outage even after the whitelist is removed. The chosen requeue still needs authenticated proposal preimages and an exact legacy-entry adapter, and its fee-zero forced path needs funding; it is not unconditional recovery.

| Choice | Benefit | Cost / unresolved boundary |
|---|---|---|
| Full permissionless proof-backed legacy drain | Authenticates every legacy transition and serves old requests under original derivation; no abandoned ordinary tail or duplicate paid-fee problem. | Legacy proof/data outage can hold activation. B's candidate removes whitelist admission, so this is an availability/completeness limitation, not a privileged-prover veto. |
| Selected authenticated requeue after deadline | Existing paid source identities survive; no private actor's signature or proof required to abandon the unfinalized tail; atomic proof closure prevents races. | Ordinary unfinalized content lost; original fees not recovered; fee-zero recovery may be self-funded; old blob/profile compatibility and historic preimage access still required. D12 void/refund limitations apply after activation, not an assertion that every request executes. |
