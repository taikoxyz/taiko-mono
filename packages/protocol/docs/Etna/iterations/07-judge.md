## M01 — new pre-ACTIVE force escrow can remain permanently unprocessable

**Source:** A M-01; A T12. **Severity:** Medium. **Class:** normative intake/lifecycle risk, not a missing benchmark. **Exploitability:** conditional availability grief or user lock; no direct attacker payout or forged custody root.

The phase table explicitly permits `force` during DRAINING, while `getHead`, `submitSegment`, execution staging and canonical jobs are disabled. A new paid request therefore cannot be processed until a separate finite legacy drain produces READY and successful activation. The same candidate explicitly permits unavailable historical data or proving capability to block that transition forever and forbids voiding/refunding these new requests by timeout. The exact trace is:

1. Freeze the old proposal and force tails and disable legacy intake.
2. Accept a user's new Etna force request and fee in DRAINING.
3. A frozen legacy obligation remains unprovable or unavailable, so activation never occurs.
4. No Etna head, stage or accepted successor exists; the new request cannot reach either processing or an owner exit. Its fee remains a liability indefinitely.

Evidence is the rule itself at `design/migration.html:248`, `:330`, `:331`, `:337`, `:344`, and the no-timeout policy at `:506`. No implementation deviation is needed. The user's fee and its time value are locked; enqueue gas is spent. Direct attacker gain can be zero, while the attacker values disruption.

**Important qualification:** permanent delay in this trace requires failure of the named legacy-data/prover availability premise. It does not falsify the post-ACTIVE FIFO theorem while all its premises hold, and it is not an undisclosed claim that migration already guarantees activation. The reason for a corrective disposition is narrower: the interface voluntarily accepts *new* user escrow into a phase with no executable Etna head and an independent unresolved launch barrier. Faithful implementation reproduces that policy. Calling the blockage disclosed or a launch risk does not remove these newly admitted liabilities.

**Required disposition:** reject new Etna `force` calls, collecting no fee and creating no queue record or credit, in both PREPARED and DRAINING. Open intake only in ACTIVE. A view fee quote may remain available without creating a liability. Initialize the new queue once as empty and preserve that state through activation; retain all existing legacy forced requests, data, fees, proofs and bond obligations under their original finite drain. Do not erase old work, add a DAO refund, or introduce an owner-selected cancellation.

Keep certificate-derived H0 and its one empty force interval. Requests accepted in or after the activation block are included in the first real origin's ordinary exact end-of-block snapshot as applicable; a same-block request after `activateEtna` is already an ACTIVE request. Later due prefixes retain the existing FIFO rule. Update the phase table, queue initialization text, worked example, progress bounds, failure analysis and all references to DRAINING intake consistently. Clients should show that Etna intake is not yet open during the drain.

The coordinator has selected ACTIVE-only intake as the proposed next revision. **It has not been applied or verified by this immutable-snapshot adjudication.** An alternative pre-activation exit would need exact objective cancellation, cursor, escrow, snapshot and once-only accounting; it adds complexity without a stated need for pre-launch intake. ACTIVE-only admission is the smallest correction and leaves the user's strict standard-call choice intact.

## Attacks rejected on the proposed rules

- **Fabricated or substituted roots:** exact header-origin equality, full-header hashing, strict bounded parsing, explicit implementation mode, nonzero checkpoint fields and non-overwriting history reject the relevant A T1/T2 and C T1/T4 variants. A merely nonzero oracle word is never sufficient origin authentication.
- **First-Etna legacy writer reuse:** both writer guards are already installed in the certified terminal legacy root. Standard 4788 writes the exact nonzero origin before every ordinary transaction; both legacy paths read the current timestamp and fail closed. The old sender and first-successor ancestor coincidence therefore give no root-writing privilege. Missing code/read data cannot select legacy mode. No transaction-zero fix is required.
- **Ring expiry as permanent veto:** the candidate correctly identifies collisions by L2 timestamp modulo 8191, including a collision after one sufficiently large timestamp jump. A forced selector-only pin has no historical timestamp dependency; the later timestamp-zero reveal has no ring deadline. An expired fixed-timestamp reveal can fail and cost gas without refuting that separate recovery path.
- **Omitting old work or choosing H0:** READY, frozen-tail/counter checks, the installation proof and exact certificate-derived H0 reject the proposed alternative genesis. A public caller cannot amend the manifest, seal an unfinished drain, or repeat the sentinel interval. M01 concerns new intake *before* this boundary, not a bypass of it.
- **Staging/service artifacts as custody authority:** no stage, custody signature, optional job or publication receipt substitutes for the canonical proof relation or the L2 authenticated-header reveal. Local soft state remains provisional and rolls back if its ancestry loses.
- **Double payouts and self-dealing:** one-position reserves, one selected first-response reward, immutable historical receipt timing, asset-separated liabilities, caller-bound excess credits and irreversible sinks reject reward multiplication, donation-equality denial, proof-beneficiary substitution and self-slash minting. Front-running can select the actual first responder but does not multiply escrow.
- **Zero-rent/expired-origin lock:** old work may correctly expire, but a fresh origin/context can be staged and proved while an unchanged parent's rent remains zero. A stage or failed transaction cannot reset the rent clock; a competing successful head is progress.
- **Infinite overtaking of a fixed supported forced item:** exact parent-frozen work survives new arrivals, mandatory prefixes precede discretionary execution, and 900-second origin freshness eventually advances snapshots. Cheap empty-discretionary proofs still carry required work. Arbitrary prior backlog affects delay, as M02, rather than allowing later requests to jump the victim.

These conclusions use the actual rejecting predicates, not the number of reviewers who called an attack unsuccessful.
