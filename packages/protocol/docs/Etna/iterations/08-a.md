**Verdict.** This pass found no demonstrated Critical or High custody/accounting specification bypass. The core root-provenance, writer-retirement, initial FIFO and one-time liability predicates are stated with enough specificity to block the traces below, conditional on sound proofs and faithful implementation. The missing authenticated deployment manifest, actual circuit and runtime checks are launch blockers, not an assumption that an implementation will invent a rule.

## Symbolic traces

1. **False L2 withdrawal checkpoint — blocked; attempted Critical, residual low under the specified assumptions.** Prerequisites: an attacker controls an L1 submitter, stage, producer key and pays DA, proof gas and up to 0.05 ETH rent. Actions: stage a body whose claimed terminal root contains a fabricated Bridge signal; mature it 360 seconds; submit the same data with an execution proof; try to have Inbox publish that root to the existing L1 SignalService. Gain would be escrow release without a source signal (R2/R7). The final action checks current parent, actual DA, mandatory FIFO, exact proof and then publishes only the proven terminal checkpoint atomically (`index.html:122-125`; `migration.html:73-81`). The verifier input binds both chains, addresses, old head, complete execution and root; a bad proof rejects before checkpoint and payout (`index.html:123`, `index.html:141-159`). Feasible only if A-CRYPTO or implementation correctness fails, which the specification and `arguments.html:15-16` explicitly identify; I do not count that premise as a specification exploit.

2. **Forge an L1 checkpoint on L2 through an old Anchor or SignalService selector — blocked; attempted Critical.** Prerequisites: attacker can pay an ordinary L2 transaction from the former public legacy sender, and might match the old ancestors digest. Actions: invoke `anchorV4` or its `saveCheckpoint` path in the first Etna block, supply a fabricated L1 state root, then present a Bridge storage proof. Gain would be an unauthorized Vault release (R2). Both legacy entry paths require an exact current EIP-4788 read equal to zero; the first Etna block's standard pre-execution write records a nonzero authenticated origin before any ordinary transaction (`migration.html:461-483`; `checkpoints.html:52-74`). Wrong code, malformed read or missing return reverts rather than choosing legacy mode. The specified predicate blocks the action even if the old sender/ancestor checks alone would not (`migration.html:482`). Gas is lost on a reverted attempt.

3. **Invent a checkpoint via permissionless reveal — blocked; attempted Critical.** Prerequisites: attacker can call L2 `revealCheckpoint`, pay parsing/storage gas, and supply an RLP header with a chosen state root. Actions: submit the fake header against a live timestamp or a pinned hash, then prove a fabricated remote signal. Gain would be a false L1-to-L2 release (R2). A fresh reveal hashes the *complete* canonical header and requires equality with either the positive-timestamp 4788 result or a permanent pin; parser checks number/root widths and nonzero root, and a conflicting existing height cannot overwrite (`checkpoints.html:90-97`). The pin itself reads only the current authenticated origin and cannot accept a caller's hash (`checkpoints.html:52-72`, `checkpoints.html:76-86`). This fails barring hash collision, bad origin-proof binding or incorrect implementation. A previously stored identical checkpoint is returned idempotently, not reauthenticated against an expired ring entry (`checkpoints.html:93-94`), which is correct only under A-LEGACY for historical records (`migration.html:218-222`).

4. **Skip fresh forced escrow during activation — blocked; attempted High.** Prerequisites: an attacker enqueues after ACTIVE, potentially in the activation L1 block, paying at least 0.001 ETH per request plus gas. Actions: exploit H0's empty force cut by inducing the first accepted segment to omit the new request and descendants to retain cut zero. Gain would be permanent censorship and retention of paid fee liability (R1/R2/R7). Before ACTIVE, force reverts without escrow; activation verifies empty new-queue liabilities. H0 has cursor/cut/time zero once, the first child consumes no forced request but must write the uniquely checked tail after its real origin, including post-activation same-block enqueues; later children use the frozen FIFO prefix (`migration.html:321-343`, `index.html:185-190`). Repeating bootstrap requires the original stored initialHeadHash and segment zero, consumed once. The first-child deferral is specified, not deletion. Progress remains conditional on a capable funded prover and bounded successor spacing (`migration.html:344`).

5. **Drain a legacy force fee twice or abandon old bonds — blocked by normative accounting; attempted High.** Prerequisites: a participant can race legacy forced commits/proofs or invoke the exit adapter; old fee escrow and TAIKO bonds exist. Actions: prove the same pending forced proposal twice, collect two ETH credits, or route old bond units into new service collateral. Gain is duplicate payment or loss of user balances (R2/R3). The adapter permits only one pending deterministic proposal, checks its exact ID/hash/parent, advances old queue head and clears pending on the single successful proof, crediting the recorded fee once; fee claims clear the caller's credit before transfer (`migration.html:421-426`). Original bond ledger, unit conversion and objective mature withdrawal remain separate from the new registry (`migration.html:257`, `migration.html:433-456`). This is conditional on the manifest proving sufficient actual old escrow and the legacy proof program covering these transitions; those are explicit activation blockers (`migration.html:259`, `migration.html:433`, `migration.html:457-460`).

6. **Reuse a signed duty reserve for duplicate payouts — blocked; attempted Medium.** Prerequisites: attacker controls a bonded signer/reporter and funds a challenge Q (0.176 ETH at 20 gwei), or has two incompatible signatures on a 10-TAIKO position. Actions: self-challenge, answer, then submit default/equivocation again; or obtain multiple responder rewards from one fragment. Gain would be unbacked TAIKO/ETH credit (R3/R6). One position is reserved for one claim identity and slashed at most once; its 10 TAIKO allocates 1 reporter/9 sink, while a successful challenge transfers its own Q to one selected responder and other matching challenges refund individually (`roles.html:113-127`; `accountability.html:28-37`, `accountability.html:48-55`). The accounting invariant separates free, reserved, credit and sink claims, with held-asset coverage per escrow (`roles.html:114-125`; `accountability.html:61`). Self-reporting therefore loses 9 TAIKO plus gas, and self-answer merely moves owned ETH less gas. The original signature and first-publication time remain needed; a report after evidenceClose cannot slash, an explicit limit (`accountability.html:14`, `accountability.html:210`).

7. **Proof-worker default erased by a late competing head — blocked; attempted Medium.** Prerequisites: a worker accepts an exact staged job, locks 1,000 TAIKO, then fails its deadline; attacker later lands a different child. Actions: argue that the now-changed current head excuses the earlier miss and reclaim bond. Gain would be avoidance of the 100/900-TAIKO reporter/sink split (R3/R6). Settlement uses immutable `parentConsumption[oldHeadHash]` with acceptance time, not just today's head; a child after the deadline cannot cancel a default (`index.html:62`; `roles.html:96-107`; `accountability.html:56-60`). A timely competing child or timely revision retirement correctly cancels an impossible task. A sponsor's impossible task can still trap a voluntarily accepting worker; the design assigns task validation to the worker, a stated market limit, not an admin escape (`accountability.html:56-60`).

8. **Expire the transient origin before a bridge claim — feasible availability loss, Medium, explicitly stated.** Prerequisites: no one pays to pin or reveal a useful L1 origin before its 4788 timestamp ring entry collides; archives or new origin access may be scarce. Actions: wait until the ring slot is overwritten, then attempt a positive-timestamp reveal of the old header. That request fails and an L1-to-L2 message may wait for a newer checkpoint (R2/R3 availability, not false custody). A separately funded valid `pinCurrentOrigin()` forced transaction can pin the origin selected at processing time; a later timestamp-zero reveal has no ring deadline and can use a later state containing an append-only signal (`checkpoints.html:99-109`, `checkpoints.html:123-125`; `arguments.html:125-128`). Thus no designated relayer monopoly is specified. The recovery still needs a funded valid sender, an advancing proof chain, archived header/state witness and measured forced-call gas; the page acknowledges those conditions (`checkpoints.html:124-125`, `checkpoints.html:139-141`). No false root follows from the expiry itself.

9. **Cross-owner soft fork with no attributable slash — feasible bounded residual, Medium.** Prerequisites: attacker uses unbonded production or distinct collateral owners, stages a conflicting branch for 360 seconds, and has a valid proof and ETH for rent/DA/gas. Actions: publish a provisional X, then let mature Y consume the parent; choose Y's producer owner different from X's bucket owner or make the immediate parent context differ. Gain can be fees/MEV or user soft rollback without the same-owner conflict penalty (R6 and user-facing R4). The conflict predicate intentionally requires same owner, revision, immediate base and height; it cannot infer common economic control (`staging.html:175-181`; `accountability.html:39-47`, `accountability.html:209`; `roles.html:282-289`). Y still needs valid execution, prior actual DA, forced FIFO and mandatory rent; it cannot fabricate a Bridge root (`index.html:122-123`, `index.html:161-169`). The maximum gain is not bounded by 10-TAIKO collateral; rent deters repeated early capture only if a ready funded competitor lands by D<900 and external gain is below summed quotes (`roles.html:275-283`). This is openly accepted residual risk, not evidence of a missing identity oracle.

**Normative predicates versus premises.** I found no unfilled normative custody predicate in the examined interfaces: root publication, header provenance, nonoverwrite, legacy zero/nonzero writer retirement, bootstrap uniqueness, receipt history and asset-specific ledger conservation are stated. This judgment does not certify their implementation. Explicit residual risks are soft reorgs, finite duty evidence windows, ring-expiry funding/archival delay and high-MEV/zero-rent concentration (`accountability.html:199-214`; `checkpoints.html:112-141`; `roles.html:280-289`). Separate unverified launch premises are full verifier programs and KZG-to-body proof, canonical EIP-4788/2935 runtime and build/import/prover parity, live proxy/owner/storage/legacy-escrow manifest, retained historical witnesses, worst-case gas and one-second execution/proving economics (`index.html:216-220`; `migration.html:520-535`; `checkpoints.html:139-141`). The synthetic encoding fixtures specify hashes, not valid accepted blocks or migration proofs (`codec-vectors.md:1-3`, `codec-vectors.md:73-87`; `encoding-vectors.md:1-3`).
