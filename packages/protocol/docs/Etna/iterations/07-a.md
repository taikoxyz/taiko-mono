# Etna round 07-A — custody, checkpoint and accounting review

## Review identity and scope

Independent defensive specification review of immutable commit `575d41a5ad2aa1a276c9a491cd04dcd4d1f8d8c2`. I reviewed all eight `design/*.html` files, `design/encoding-vectors.md`, `design/codec-vectors.md`, and only the README requirement ledger. I did not read prior iteration reports, author analysis notes, or `notes/`. No implementation, deployment, live state, chain interaction, transaction, key, or third-party system was used.

Requested reviewer configuration was `gpt-5.6-sol/high`; the actual runtime model is unattested. Conclusions therefore rest on the cited immutable text, not model identity.

The review asks whether an adversarial trace can (a) authenticate a false checkpoint, (b) cross the migration boundary with omitted work or changed storage, (c) redirect or multiply payments, (d) withdraw more than escrow, or (e) turn an optional soft-service signature into custody authority. Severity is impact under the stated prerequisites: Critical permits broad custody loss; High permits substantial unauthorized asset movement; Medium causes bounded/conditional asset lock or material invariant failure; Low is bounded accountability or economic weakness without custody-root corruption.

## Verdict

No Critical or High custody flaw was found. The root-publication design keeps soft roles outside the custody trust boundary: L1 roots require the accepted proof path, L2 roots require a complete header whose hash was recorded or pinned from an authenticated Etna origin, and retained Bridge/Vault checks consume those roots rather than service signatures.

I found one specification-level Medium: the new force queue accepts ETH-backed requests during `DRAINING`, while the same specification permits legacy drain evidence to remain unavailable forever and provides no cancellation or refund. This can create new, indefinitely locked user liabilities before Etna has a usable head. I also record one disclosed Low economic limit: finite evidence windows and an uncalibrated reporter reward can make an objectively valid service penalty go unreported. Neither issue lets a claimant forge a checkpoint or withdraw Bridge/Vault custody.

Severity count: **Critical 0 · High 0 · Medium 1 · Low 1**.

## Findings

### M-01 — DRAINING accepts new force-fee escrow without a reachable processing or exit path

**Impact.** A user can place ETH into the new queue after the legacy cutover has disabled the old intake, yet before the legacy suffix is known to be provable. If one frozen legacy item cannot be proved, `ACTIVE` is unreachable, `submitSegment` remains disabled, the new queue cursor cannot advance, and the user has no cancellation/refund path. This is a bounded custody-availability failure, not an unauthorized withdrawal.

**Prerequisites.** The migration is in `DRAINING`; at least one frozen historical proposal/forced source lacks retrievable data, a supported proof, or a capable prover; a user pays force fee `F` into the new Inbox.

**Ordered counterexample.** (1) The cutover freezes old proposal/force tails and disables legacy intake. (2) A user calls the explicitly open new `force` path in `DRAINING`; the queue stores the request and its ETH escrow. (3) The missing legacy obligation prevents `READY` and therefore prevents `activateEtna`. (4) `getHead` and `submitSegment` continue to revert, so no accepted successor can create the first snapshot or consume any new request. (5) The request never expires, and the design forbids a timeout/void/refund. The escrow remains a liability indefinitely.

**Economics.** User loss/lock is `F + gas + timeValue(F)`. Direct adversary gain is `0`; griefing value is external, `G_grief`, and requires the adversary already to cause or exploit failure of the legacy-data/prover premise. The absence of attacker profit does not restore the user's exit.

**Invariant and requirements.** A newly accepted asset escrow should have a protocol-reachable processing outcome or owner exit under the lifecycle in which it is accepted. This trace fails that invariant and the forced-inclusion portion of R7 during migration; it weakens R1's no-operator liveness claim for newly accepted obligations.

**Evidence.** `design/migration.html:248-259` freezes legacy work, permits new requests, and makes missing data block activation; `design/migration.html:327-337` opens `force` in `DRAINING` while head access/submission revert and preserves the queue/fees; `design/migration.html:338-344` defers all new requests through the empty H0 interval and expressly says they remain unprocessed with fee liabilities if activation fails; `design/migration.html:506` specifies no migration timeout or force-void deadline; `design/migration.html:528-529` requires the rehearsal to demonstrate that unavailable old data blocks activation.

**Disposition.** This is a specification condition, not a launch-validation item: a faithful implementation has the trace. The simplest resolution is to accept new Etna force requests only in `ACTIVE`. That preserves old obligations without accepting new escrow into a chain state that has no usable head. If pre-activation intake is retained, the specification needs an objective, permissionless exit whose accounting cannot discard or double-spend a request.

### L-01 — objective service penalties can rationally expire unreported

**Impact.** A valid fragment/publication offense can escape its 10-TAIKO penalty if the signed evidence is hidden or the 1-TAIKO reporter share is worth less than evidence gas. The reserve is then released after the fixed horizon. This limits service-accountability deterrence but cannot publish a root, change a message status, or create a Bridge/Vault claim.

**Prerequisites.** A signer defaults; evidence cost is `C_e`; reporter value is `V_r = value(1 TAIKO)`; `C_e > V_r`; no subsidized/altruistic reporter submits before `evidenceClose`.

**Ordered counterexample.** (1) A position signs a valid v2 promise and misses its deadline. (2) The counterparty withholds the signature or rational reporters decline to pay `C_e`. (3) No evidence is admitted by `evidenceClose`. (4) Strictly later, release returns the unslashed reserve. (5) Later disclosure cannot revive liability.

**Economics.** The signer avoids loss `B = 10 TAIKO`; a rational reporter avoids negative payoff `C_e - V_r`; the service user can bear an external loss `L_s` not insured by `B`. Collusion may share part of `B`; the protocol itself mints nothing.

**Invariant and requirements.** A strong reading of R6 in which every objective offense is inevitably penalized does not hold. The narrower written invariant does hold: evidence is permissionless, predicates are objective, and payouts never exceed escrow. This is therefore Low and an accepted economic limit, rather than a custody-safety failure.

**Evidence.** `design/accountability.html:61-75` states that the reporter reward may not exceed evidence gas and that deterrence is uncalibrated; `design/accountability.html:199-214` states that hidden signatures, absent reporters, and post-close discovery can yield zero punishment; `design/roles.html:82-87` releases unknown/unreported liabilities after the horizon; `design/roles.html:203-218` fixes the one-hour window and 10% reporter share; `design/arguments.html:142-149` records the same worst-case detection limit.

**Disposition.** The limitation is disclosed and does not require a new custody guard. Before launch, calibrate `B`, reporter share, evidence gas, and any neutral subsidy against measured costs; user-facing bonded status must expire with the reserve.

## Symbolic counterexamples tested

Let `W` be value withdrawable from Bridge/Vault custody, `B=10 TAIKO` a duty reserve, `J=1,000 TAIKO` a worker reserve, `Q` a challenge deposit, `F` a force fee, `q(a)` canonical rent, `C_x` transaction/evidence cost, and `G` adversarial external gain.

### T1 — fabricated L1 state root through permissionless reveal: rejected

**Prerequisites/events.** An arbitrary caller chooses header bytes with attacker state root `R*`, calls `revealCheckpoint`, then attempts a signal proof for gain `W`. The contract hashes the complete canonical header and requires that exact hash in the timestamp ring or permanent pin; the parsed nonzero state root and number are inseparable from that authenticated hash. A fabricated header fails before checkpoint storage. Cost/gain: attacker loses `C_x`; `G=W` is unrealized. **Invariant/R:** only authenticated L1 execution state becomes an L2 checkpoint; R2/R7. **Evidence:** `design/checkpoints.html:8-11,52-74,90-97`; `design/migration.html:72-82`. **Result:** guard rejects under A-CRYPTO/A-IMPL.

### T2 — reuse a valid hash to overwrite a checkpoint number: rejected

**Prerequisites/events.** A caller reveals authenticated header `H1` for number `n`, then tries a different authenticated header/root `H2` for the same `n`. Existing `{blockHash,stateRoot}` is non-overwriting: only an identical tuple returns idempotently; partial/corrupt or conflicting tuples fail. Cost is two calls; gain `W` is unrealized. **Invariant/R:** checkpoint history is append-only by height; R2. **Evidence:** `design/checkpoints.html:90-96`; `design/migration.html:75-80`. **Result:** guard rejects.

### T3 — old Anchor/golden-touch writer publishes a forged first-Etna checkpoint: rejected

**Prerequisites/events.** The former public legacy sender submits the old Anchor selector in the first Etna block, hoping legacy caller/ancestor checks still pass. Standard EIP-4788 has already written the authenticated nonzero origin at the current timestamp. Both Anchor and L2 SignalService legacy writers require an exact successful current read equal to zero, so the call fails before its write. Delegation to the system address does not acquire system-caller identity. Cost `C_x`; hypothetical gain `W` is unrealized. **Invariant/R:** old/new root authorities are disjoint at the boundary; R1/R2/R7. **Evidence:** `design/checkpoints.html:13-20,52-74`; `design/migration.html:461-484`. **Result:** guard rejects, conditional on certified runtime/client parity.

### T4 — activate from an omitted legacy suffix or caller-selected genesis: rejected

**Prerequisites/events.** A caller supplies a convenient terminal checkpoint while historical proposals, a pending forced proposal, or the old queue remain. Activation recomputes the certificate/public input, verifies the pinned migration proof, compares exact frozen counters/checkpoint/timestamp, calls a READY-only seal, and deterministically derives H0. Pending work or a changed field prevents the same-transaction phase/head installation. Cost `C_x`; hypothetical gain is control of successor state and `W`, unrealized. **Invariant/R:** all accepted legacy work and custody state precede unique H0; R1/R2/R7. **Evidence:** `design/migration.html:240-282,283-337,348-434`. **Result:** guard rejects under proof soundness and A-IMPL.

### T5 — storage collision or VERSION bump substitutes bridge history: rejected by specification; launch validation required

**Prerequisites/events.** An upgrade attempts to reuse SignalService slot 254, reset Bridge status, remap a Vault token, or hide old caches behind a version bump. The normative layout keeps SignalService VERSION 1 and slots 253/254, Bridge status/counter, Vault maps, wrapper supply/approvals/nonces, and assigns pins to a separate ERC-7201 namespace. Such an implementation is nonconforming. Cost/gain depend on upgrade authority; a malicious DAO is outside A-UPGRADE. **Invariant/R:** addresses, escrow, replay status, and historical proof namespaces survive; R2. **Evidence:** `design/checkpoints.html:76-88`; `design/migration.html:137-159,163-223,488-515`. **Result:** rejected at specification level; exact deployed layouts/code hashes remain a launch blocker, not a proved fact.

### T6 — service signature or stage receipt becomes a withdrawal root: rejected

**Prerequisites/events.** A publisher/custodian signs a fragment, or a stager records a mature context, then presents that artifact as settlement authority. Staging never calls SignalService/Bridge/Vault; L1 checkpoint publication occurs only inside successful atomic `submitSegment` after parent, DA, FIFO, producer, proof, and rent checks. L2 publication requires the authenticated-header reveal path. Cost `C_x`; gain `W` unrealized. **Invariant/R:** optional roles have no custody authority; R1/R2/R3/R7. **Evidence:** `design/staging.html:117-121`; `design/index.html:122-126,165-170`; `design/migration.html:23-29,72-85`. **Result:** guard rejects.

### T7 — blob/stage receipt silently discharges a fragment duty: rejected

**Prerequisites/events.** A signer withholds the exact FR fragment but stages a blob or another manifest, then claims fulfillment to preserve `B`. Fragment fulfillment derives the tagged key from signed FR/index, verifies complete selected calldata bytes, exact lengths/digest and claim binding, and uses its immutable first receipt. A stage/body hash cannot create that receipt. Cost is publication/evidence gas; avoided `B` is unrealized. **Invariant/R:** payment/slash attribution attaches to the exact promised bytes; R6. **Evidence:** `design/accountability.html:16-29`; `design/codec.html:123-160`; `design/codec-vectors.md:62-71`. **Result:** guard rejects under collision resistance.

### T8 — multiply one publication into many responder rewards: rejected

**Prerequisites/events.** An actor opens compatible challenges for several claims sharing FR/index and publishes once, hoping to collect every `Q`. The immutable first receipt is shared, but only the selected challenge's actual first timely responder receives one `Q`; other timely satisfied challenges refund their own openers and are settled individually. Each position admits at most one challenge and pays at most one slash. Cost is deposits plus gas; maximum protocol publication reward is one selected `Q`, not `kQ`. **Invariant/R:** ETH credits do not exceed separately deposited ETH and rewards do not multiply by signer count; R6. **Evidence:** `design/accountability.html:30-37,61-75`; `design/roles.html:113-127`. **Result:** guard rejects.

### T9 — signer/reporting/responder self-dealing mints value: rejected

**Prerequisites/events.** One actor controls every identity, self-challenges, self-responds, or self-reports. A timely response only moves its deposited `Q` to its responder credit and costs gas. A default refunds `Q` but consumes `B`, returns at most `0.1B` as reporter credit, and locks `0.9B` in the sink. For a job, the analogous self-report loses `0.9J`. Net protocol gain is nonpositive before external value: `-C_x` when served, at most `-0.9B-C_x` or `-0.9J-C_x` on default. **Invariant/R:** no unbacked payout; R6. **Evidence:** `design/accountability.html:61-75`; `design/roles.html:113-127,285-289`. **Result:** guard rejects.

### T10 — direct donation blocks withdrawals or becomes owner surplus: rejected

**Prerequisites/events.** An attacker transfers unsolicited TAIKO/ETH to an escrow contract, then expects exact-equality accounting either to freeze claims or let an owner sweep the excess. The specified invariant is liabilities `<=` held assets; donations are uncredited surplus, create no claimant, and have no owner sweep. Legitimate credits remain withdrawable. Attacker cost is donation `D`; protocol-account gain is `0`. **Invariant/R:** external balance changes do not alter internal liabilities; R1/R3/R6. **Evidence:** `design/arguments.html:60-62`; `design/accountability.html:61`; `design/roles.html:113-125`. **Result:** guard rejects if implementations avoid raw-balance equality.

### T11 — copy a proof and redirect beneficiary, rent refund, or legacy force fee: rejected

**Prerequisites/events.** A copier reuses valid proof bytes but changes beneficiary, job worker, producer, stage, or `actualProver`; alternatively a fee payer claims the Inbox excess credit. The statement/proof and producer authorization bind beneficiary/job/stage/producer; legacy proof binds its commitment and `actualProver`; canonical rent excess belongs only to immediate `msg.sender`, not the separate fee payer or named beneficiary. A changed field changes the verified digest. Cost `C_x`; diverted reward `G` is unrealized. **Invariant/R:** each payment is attributed to the authenticated actor or actual funding account; R1/R3/R6/R7. **Evidence:** `design/index.html:122-145,161-180`; `design/staging.html:117-157`; `design/migration.html:418-433`; `design/roles.html:241-269`. **Result:** guard rejects.

### T12 — skip DRAINING requests through H0 forever: partly rejected; M-01 remains

**Prerequisites/events.** Requests exist in the new queue before activation. The first segment intentionally consumes zero, but its authenticated origin fixes the exact queue tail and H1 stores it; later children must process the due FIFO prefix and later arrivals cannot overtake. If activation and canonical progress occur, the one-time empty cut cannot repeat. Costs include proof/DA/rent; censorship gain is bounded by the conditional FIFO argument. If activation never occurs, however, no H1 exists and M-01 applies. **Invariant/R:** atomic data+proof plus frozen FIFO; R7. **Evidence:** `design/migration.html:323-344`; `design/index.html:182-189`; `design/arguments.html:85-96`. **Result:** post-activation bypass rejected; pre-activation escrow liveness fails as found.

## Conditions versus launch validation

The following are **specification conditions**. Violating them is a nonconforming implementation: proof/public-input completeness; full-header hash authentication; current-root legacy-writer guard; non-overwriting checkpoints; one-time certificate-derived H0; immutable parent-consumption/revision-retirement receipts; VERSION 1 and preserved Bridge/Vault/wrapper storage; per-asset liabilities `<=` assets; state-first pull credits; once-only reserves/sinks; exact FR/context separation; producer authorization; and atomic head/checkpoint/payment updates. M-01 is also a specification issue because the documented phase table itself admits the unsafe escrow lifecycle.

The following are **launch-validation conditions**, not findings that documentation can close: authenticate every live proxy, implementation, owner/pending owner, immutable, resolver, wrapper and treasury recipient; generate exact old/new layouts; prove old message/cache/checkpoint compatibility; establish complete legacy DA and the audited RISC0+SP1 drain relation; verify canonical EIP-4788/EIP-2935 runtime hashes and builder/importer/guest parity; reproduce both proof backends' full Etna relation; test first/last legacy and first Etna blocks plus reorgs; benchmark maximum FR publication, proof verification, pin/reveal, forced-prefix and migration gas; validate blob retention; and calibrate rent, reporter incentives and collateral.

Subject to M-01 remediation and those launch gates, I did not find a symbolic path from a soft role, staged candidate, copied proof, migration caller, duplicate evidence, donation, or self-dealing identity to an unauthenticated custody root or an unbacked payout.
