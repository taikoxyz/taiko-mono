# Round 07 C — censorship and concentration review

**Reviewer/model:** Codex subagent, requested `gpt-6-sol` with high reasoning and `fork_turns=none`; actual runtime SKU is unattested. **Scope:** research-only, adversarial review of immutable commit `575d41a5ad2aa1a276c9a491cd04dcd4d1f8d8c2`. I read its eight `design/*.html` reference pages (`index`, `staging`, `codec`, `roles`, `accountability`, `checkpoints`, `migration`, `arguments`), both `design/*-vectors.md` fixtures, and only the R1–R7 requirement table in `Etna/README.md`, through `git show`. Line citations below refer to that immutable commit. I did not use author verdicts as evidence, inspect earlier iterations or notes, execute an exploit, deploy, or alter production code.

**Verdict:** No demonstrated Critical/High break of the proposed transition relation. R1–R7 have conditional design-level mechanisms, but none has launch-level implementation evidence. The censorship escape is eventual and funded, with no bound on the work already ahead of a user. Soft-service economics and mandatory rent leave profitable concentration possible. The first bridge checkpoint now needs an ordinary paid transaction; the forced pin route removes an expiring hash dependency, subject to canonical proof progress, transaction validity, and retained source state. These are material Medium risks rather than evidence of a forged checkpoint or a permissioned gate.

## Adversarial traces

**T1 — censor a positive-timestamp checkpoint, then force a pin (attack fails under assumptions).** Preconditions: an L1-to-L2 signal is stored before L1 block `e`; the L2 header at timestamp `t` records its authenticated origin hash `h`, but no checkpoint or pin exists. The adversary controls soft publication and omits ordinary `revealCheckpoint(t, header)` until a later L2 timestamp collides modulo 8191. A positive-timestamp reveal then fails exactly as specified (`checkpoints.html:19,90-108`). The user pays an L1 force fee starting at 0.001 ETH plus enqueue gas and funds a correctly nonce/fee/balance/gas-valid L2 `pinCurrentOrigin()` transaction. The next qualifying forced prefix pins its **processing-block** origin `h2`, not expired `h`; after obtaining that header, the user pays an ordinary or forced `revealCheckpoint(0, headerH2)` and then pays for the Bridge claim (`index.html:184-189`; `checkpoints.html:109,121-129`; `arguments.html:125-128`). The attacker can gain bridge delay and impose user gas/fee cost; it cannot select a false state root or make the positive timestamp ring a permanent veto if proofs keep advancing. The later state must still contain the signal and its archival proof must be available. This trace is not a deadline guarantee.

**T2 — prefill FIFO before the victim pin (finite delay succeeds; overtaking fails).** Preconditions: the adversary can pay for `N` L1 forced enqueues before the victim's pin request and can keep new enqueues arriving. It submits `N` well-formed or deterministically rejectable records, then the victim enqueues the funded pin. Each accepted successor processes at most four due requests from its parent's frozen prefix. Later attacker requests remain behind the victim by index; they cannot replace its bytes, and a fresh origin after 900 seconds must eventually expose its queue position (`index.html:145-158,184-189`; `codec.html:116-121`). At least `ceil(N/4)` accepted segments of prior work stand ahead, plus snapshot/maturity latency. For 1,000 prefilled requests, the documented no-intermediate-processing example pays 10.5 ETH in fees, with at least 5.25 ETH sunk even if the attacker collects all beneficiary credits, plus L1 gas and proof/DA cost (`roles.html:285-288`). Gain: an arbitrarily large *finite* bridge delay for finite but scalable expenditure. The later-arrival censorship step fails; an unconditional maximum queue latency is not established. If proving stops, both victim and attacker halt under A-EXEC.

**T3 — keep soft issuance while using the checkpoint ring as a choke point (soft service succeeds; bridge availability degrades).** Preconditions: canonical blocks continue with EIP-4788's standard write, and an adversary controls the popular builder/relayer but not all capable provers. It omits the optional, unpaid pin/reveal calls from its soft blocks. A user waiting for the latest L1-to-L2 checkpoint sees only transient roots; after a timestamp collision, the old positive-timestamp route cannot write a new checkpoint (`checkpoints.html:9,19,49-50,99-109`). The user can bypass the relayer with direct paid pin/reveal or T1's force path, but pays fresh state SSTORE, header calldata/RLP parsing, potential forced fee and a separate claim transaction with no automatic Bridge reimbursement (`checkpoints.html:112-129`). The attacker gains a degraded bridge experience without signing a slashable duty; the chain's one-second soft blocks do not imply checkpoint service. The spec explicitly accepts this optional-service boundary, but it should be evaluated against the product's expected bridge latency.

**T4 — exploit permanent pin state as a paid state-growth externality (growth succeeds; forgery fails).** Preconditions: an attacker can put ordinary pin calls into many accepted L2 blocks with distinct authenticated origin hashes and can pay the L2 transaction envelope; it may also be the block coinbase. It calls `pinCurrentOrigin()` once for each distinct current hash. Each successful new hash stores one permanent bool in the existing SignalService proxy's new namespace; duplicate calls write nothing, no ordinary method clears entries (`checkpoints.html:76-88,119`). Under the specified 100% coinbase basefee allocation, a producer paying its own L2 gas can recapture that fee at its coinbase, although L1 staging/proof/DA/rent and actual execution resources remain costs (`codec.html:103-105`; `roles.html:277-283`). Gain: durable state and archive burden imposed on all L2 nodes, potentially cheaper for an integrated producer than for an external user. There is no arbitrary-hash pin or checkpoint forgery: the call reads only the authenticated current root (`checkpoints.html:52-74,86,90-97`). This is an uncapped lifetime storage choice, not an unbounded single-call gas bug.

**T5 — frame a publisher through beneficiary or producer naming (attack fails), then use a different owner (conflict slash evaded).** Preconditions: Alice holds a live 10-TAIKO publisher position for block X. Mallory stages a different public valid Y and submits its proof, naming Alice as beneficiary and attempting to name her as producer without her authorization. Beneficiary naming cannot establish Alice's assent; the accepted statement requires an exact EIP-712 producer signature or self-registered immutable key, so the forged-producer step fails (`staging.html:123-157`). Mallory instead self-authorizes Y under another economic identity; if Y wins, Alice's X is a provisional loser, but the owner-linked conflict rule cannot slash either owner merely for competing (`staging.html:159-181`; `accountability.html:39-55`). Mallory pays proof/gas/DA and the current rent, potentially 0.013333333333333334 ETH at parent age 660 seconds (`codec-vectors.md:89-102`). Gain: fees/MEV/censorship value if greater than costs; loss is a soft rollback for X users. This is a successful scope escape from *same-owner conflict attribution*, not a forgery or a bypass of staging/rent.

**T6 — buy repeated canonical wins while independent entrants lack funding (monopoly remains possible).** Preconditions: incumbent controls a fast prover, order flow, and coinbase; no independent party can both fund the current rent and get a fresh proof included by age `D<900`. It stages each complete context, waits 360 seconds, republishes exact data plus proof, and repeats. If no one consumes a parent until age 900, rent is zero; if a competitor can win by age 660, each preemptive capture sinks at least 0.013333333333333334 ETH (`roles.html:239-283`; `codec-vectors.md:89-102`). With `Gnet=0.02 ETH` of external value per contested capture before rent, that 660-second capture can still net ~0.006667 ETH before any additional uncounted cost; 100 such rent payments total 1.3333333333333334 ETH. Same-owner fees from its own L2 transfers are internal and do not count as external gain. The attacker can profit and remain dominant where value or asymmetry exceeds the quote; otherwise repeated capture loses money under the named competitor assumption. No service bucket or producer collateral is mandatory for raw submission (`roles.html:54,275-283`). This refutes any unconditional anti-monopoly guarantee, which the design itself does not claim.

**T7 — promise one-second bonded data near the body cap, then ration L1 publication (default succeeds; R4 capacity unproven).** Preconditions: a publisher advertises a complete ~120,000-byte bonded block record each second, split into four ≤32,768-byte fragments within the 122,880-byte *whole-segment* body cap, and has the required live 10-TAIKO positions. It or its custodians must post each exact fragment and ordered FR preimage as calldata by `issuedAt+240`, even if blob staging follows (`codec.html:21-45,123-165`; `accountability.html:7-29`). This schedule implies ~120,000 bytes/s of early calldata. At 16 gas per nonzero byte, the byte-charge component alone is ~1.92 million gas/s; at a 64-gas-per-nonzero-byte calldata floor, it is ~7.68 million gas/s. Neither figure includes manifests, transaction overhead, duplicated stage/acceptance DA, or proof verification, and the exact launch-fork gas schedule needs measurement. The four-position-per-second exposure example needs 147,000 TAIKO peak for one publisher and the same again for an independent custodian (`roles.html:289`). If L1 inclusion capacity or ETH budget cannot sustain it, some honest promises objectively default. Each missed position loses 10 TAIKO, with 1 to the first reporter and 9 sunk; a user gets no guaranteed damages for the soft rollback (`accountability.html:25-29,201-214`). The attacker may instead issue unbonded blocks, avoiding service penalties but losing the bonded label. Result: the one-second header/soft issuance rule can coexist with an unavailable bonded publication market; full-load sustained performance is an open measurement, not a demonstrated failure at lower realistic body sizes.

**T8 — retain an operational migration path (attack succeeds only if the stated launch gate is skipped).** Preconditions: live Bridge, Vault, wrapper or ForkRouter implementations still expose an inherited owner pause, `init3`, resolver mutation, owner mint, quota dependency or generic legacy fallback after the DAO installs Etna. A former operator uses that selector to block processing or alter custody; the new Inbox being permissionless does not remove an old shared-contract gate (`migration.html:143-155,191-213`). The specified migration instead requires exact proxy/code/layout/wiring manifest, full selector audit, committed guarded implementations and a terminal-root certificate before ACTIVE (`migration.html:226-259,521-531`). The attack fails *under that verified installation*, but those facts are not established by this documentation. Cost/gain depend on the retained authority; asset loss or indefinite censorship would be High if an operational selector survives. This is a launch blocker and a concrete audit target, not a demonstrated exploit of the proposed final design.

**T9 — suppress checkpoint revelation across a ring expiry with no archives (recovery fails under an explicit environmental assumption).** Preconditions: no checkpoint or pin for an older L1 origin; the transient timestamp was overwritten; current canonical L2 blocks can still advance. The user forces a successful current pin, then tries to construct the complete corresponding L1 header and an account/storage proof for an old signal. If archival header/state data or the old signal's persistent storage is unavailable, the pin's bool is insufficient to reconstruct the header/root/proof, and the bridge claim waits (`checkpoints.html:90-109,124-129`; `migration.html:216-223`; `arguments.html:125-128`). The adversary need only withhold archival service; it cannot invent a different root, and any independent archive can break the withholding. Its gain is claim delay; its direct protocol cost can be zero if it was the only off-protocol archive. R2's address preservation does not itself guarantee archival data availability.

## Findings and disposition

| ID / severity / exploitability | Finding and evidence | Disposition |
|---|---|---|
| **C-07-1 / Medium / practical economic censorship** | A forced pin is FIFO but can be delayed by an arbitrary finite backlog already in front of it. Every old request costs a fee and bounded proof work; no maximum recovery latency is given (`index.html:184-189`; `roles.html:285-288`). T2. | Accept only as an **eventual** censorship escape under bounded L1 inclusion/proving assumptions. Do not present it as prompt bridge recovery. Measure backlog clearance and user fee budget; reconsider per-segment forced capacity only with proof/gas evidence. |
| **C-07-2 / Medium / practical service degradation** | L2 checkpoint persistence has no mandatory duty, reward or fee reimbursement. A dominant builder can omit it while continuing valid blocks, shifting pin/reveal and claim funding to users (`checkpoints.html:49-50,127-137`). T1/T3/T9. | The force route prevents a protocol relayer monopoly if archives and funded actors exist. Specify bridge-latency/user-cost expectations and test the complete forced pin → reveal → proof path before launch. |
| **C-07-3 / Medium / conditional profit** | The Dutch rent proves a cost only against a timely funded competitor; raw producers need no service collateral, and `Gnet > q` permits rational repeated capture. Same-owner slash does not reach cross-owner economic control (`roles.html:275-289`; `staging.html:180-181`). T5/T6. | Keep the guarantee explicitly bounded; measure entrant funding, inclusion and actual net value before claiming that `Pmax=0.05 ETH` deters a monopoly. Sybil address counts are not evidence of diversity. |
| **C-07-4 / Medium / resource and capital concentration** | Permanent origin pins create caller-paid lifetime state, while a one-second high-data bonded service requires large upfront TAIKO plus actual L1 calldata. L2 fees may recycle to an integrated coinbase (`checkpoints.html:76-88,119`; `codec.html:103-105`; `roles.html:289`). T4/T7. | Benchmark realistic and maximum schedules, SSTORE/gas, L1 calldata/blob capacity and independent entrant capital. Do not infer one-second useful bonded throughput from one-second header issuance. |
| **C-07-5 / Medium now; High if gate skipped / launch-dependent** | R1/R2 depend on verified removal of old admin/custody paths and exact storage compatibility at the retained proxy addresses. The manifest and rehearsal are still open (`migration.html:191-213,521-531`). T8. | Treat verified selector/layout/state inventory and old-message replay as activation prerequisites. No operational-operator bypass is demonstrated under the specified final rules. |

The adverse outcomes above preserve the requested standard EIP-4788 pre-execution call: none proposes a mandatory anchor transaction, custom system hook, replacement custody address, operational admin, or privileged checkpoint writer. The numerical traces are scenario calculations under the page's proposed constants, not measurements or production exploit results.
