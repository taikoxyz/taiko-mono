## Finding C1 — contradictory publication-claim signature domain (High, R6 hard gate)

**Preconditions and trace.** A bonded publisher opens a 600-TAIKO bucket, reserves a 10-TAIKO position, seals context C, and signs the six-field publication promise under the `EtnaDuty` domain. A client following `staging.html` signs the EIP-712 type `PublicationClaim(...)`; a registry implementing `accountability.html` verifies `EtnaPublication(...)`. The type hashes differ even with identical fields, values, domain, and ECDSA key. The publisher misses `issuedAt+240` and first stages C later. At `now>publishBy`, a reporter calls `provePublicationDefault` with the client's original signature. Signature recovery fails, so the direct default proof and the 1/9-TAIKO reporter/sink split never run. Reversing which page client and registry follow produces the same interoperability failure. The data-age gate still prevents first disclosure *at acceptance*, but the claimed objective penalty for the signed publication deadline disappears.

**Cost/gain.** The signer locks 10 TAIKO until release but loses none for this missed covenant, assuming no independent offense. It pays the ordinary late stage/landing DA and proof costs. It gains an unpunished 240-second service miss and may still land after the 360-second maturity wait. A reporter pays failed-transaction gas if it tries the incompatible signature. This is a document-level conflict, so no particular deployed verifier behavior is asserted.

**Exact evidence.** `staging.html:200–210` declares the type name `PublicationClaim` and hashes the literal `PublicationClaim(uint256 bucketId,...)`; `accountability.html:10,95–103` and `roles.html:85` declare `EtnaPublication` for that same six-field claim; `accountability.html:19,114–118` makes authenticated signature recovery the default-evidence gate. `README.md:25` requires L1-verifiable punishment and permissionless reporting. **Minimal repair:** make one literal EIP-712 type string normative in every page and interface; publish its domain separator, structure hash, signed digest and recovery test vector. Use that exact type for publication default and both publication/mixed equivocation evidence. This is a **High specification defect**, not a request for implementation testing.

## Finding C2 — same-owner pipelined contradiction escapes the stated conflict proof (Medium, R6 disposition required)

**Preconditions and trace.** A publisher reserves X against accepted head H and signs a valid soft block at height k on a speculative descendant of H. The same collateral owner later authorizes a conflicting canonical segment Y containing height k, but Y's immediate `oldHeadHash` is H′, an accepted child of H. The reporter has X, Y's exact accepted statement, producer authorization receipt, and Y's six-sibling block-membership proof. `proveCanonicalConflict` still rejects: it obtains `getAcceptedReceipt(X.baseHeadHash)` and requires `Y.oldHeadHash == X.baseHeadHash`. The attacker did not need a Sybil key or hidden data; Y can be staged with its complete context for 360 seconds and then land lawfully. A different producer-owner address gives an additional, explicitly acknowledged identity false negative.

**Cost/gain.** X needs one 10-TAIKO reserve in a 600-TAIKO bucket, normally refundable after its evidence horizon. Y needs staging and landing DA, proving, and L1 gas. The owner can profit from a conflicting soft branch or avoid a promise to customers without paying this 10-TAIKO consistency slash. The exact profit is workload/MEV dependent; it is not claimed that every such conflict is profitable. The public stage gives observers a chance to notice Y, which limits surprise but does not turn X's authenticated contradiction into punishable evidence.

**Exact evidence.** `accountability.html:20` defines the receipt lookup and strict immediate-parent predicate and expressly names the pipeline false negative; `staging.html:180–181` repeats it; `roles.html:81,84` gives the owner-linked promise and bounded evidence scope; `index.html:62–63,144` permits descendant contexts to be precomputed and soft work to continue while earlier segments prove. `README.md:25` is the R6 objective-punishment gate. **Minimal repair:** either specify a bounded authenticated accepted-receipt ancestry/membership proof that can connect X's claimed base through the accepted pipeline to Y at height k, preserving a strict same-owner check, or narrow the advertised consistency duty to only the exact immediate parent and explicitly accept that customer-facing pipelined soft blocks have no canonical-conflict penalty. The latter is a **risk acceptance**, not evidence that the broader R6 punishment claim passes. Do not penalize a different economic owner merely because it won a valid race.
