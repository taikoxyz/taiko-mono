## D92 follow-ups, assumptions and alternatives

**[assumed: proposed D92-L1 disclosure]** A reorg orphaning recovery N can affect every active key that consumed N, rather than independent isolated signers. Rotating a key needs its owner’s accepted on-chain action and the existing DELAY_REG (7,200 seconds), plus remaining admission/enrolment/term/history work, which can overlap. No certification from those held keys returns before valid replacement admission. Certificate-free hatch/dead mode remains subject to its own conditions; no total liveness bound follows. The hold waives no existing MISS or stale/tenure rule. A waiver, if desired, requires a separate S1/S3/C6 disposition. V50/V52 state this correlation; they do not assume that other already eligible keys also lost records.

**[assumed: proposed D92-L2 policy]** A used key with unprovably complete cursor, applied journal or signing protection remains held even for later openings; ordinary owner-initiated fresh-key admission/exit is its route. This is stronger than R09’s original per-old-opening minimum. Re-baselining that key is rejected because an L1 replay cannot reconstruct private signatures it may have broadcast. Restorable intact records are not declared lost merely because external RPC data is absent. No new timeout or administrative reset is added.

**[assumed: proposed D92-L3 prerequisite]** A-S2-REPLAY names retained/reconstructible full execution state and authenticated intermediate call/state inputs in addition to C7’s canonical L1 view. A logs-only feed is insufficient. Missing required current-prefix inputs pauses all protocol signing by the affected key until the prefix can be classified. Availability, archive dependence, replay speed and local retention/pruning cost remain unmeasured and conditional.

**[proven: conservative no-landing filter, conditional on A-KECCAK and the supported fixed writer profile]** If consecutive authenticated Inbox account storage roots match, no committed landing/restart occurred: ordinary landings and C4 restarts write `.at = timestamp(N)`, strictly newer than the pre-block value; hatches preserve `.at` but increase height and leave fresh marker state. These writers cannot restore the whole old storage state. Reverted calls correctly leave no effects. If the profile is uncertain or an arbitrary A-UPGRADE rewrite is involved, this proof is inapplicable and the shortcut is not used. Equal L2 height/hash/state-root fields alone are insufficient: a provisional recovery followed by CONFLICT restart can restore a published floor while preserving new timestamps/markers. The design therefore selects whole-account-root equality, not that tempting partial comparison. A changed root only requests full classification; it does not prove recovery.

**[assumed: proposed D92-L4 failure behavior]** Request/horizon limits do not make an archive exist. If the key cannot authenticate a requested older scope’s pruned recovery provenance, refusal/wait is the expected result and can be indefinite. It cannot interpret TTL expiry as “no displacement”. A later independent scope needs its own complete inputs. A blanket claim that FB_SIGNER_HORIZON or R22 bounds this archive wait is rejected. No new storage service, role or forced publication duty is adopted.
