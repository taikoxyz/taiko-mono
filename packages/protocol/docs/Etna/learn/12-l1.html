Lesson 12: the L1 environment

Prerequisite: lesson 6. Design pages: L1 dependencies, Frame transactions.

Goal

Know which upcoming L1 changes matter, which do not, and how to check any Etna rule against a change of slot time.

The idea

Nothing in Glamsterdam or Hegotá is a hard dependency. Etna needs only what is live today: blobs with blobhash, the transaction gas cap as a constraint, ecrecover and the BLS precompiles, block.timestamp, prevrandao, and blockhash with EIP-2935. It must tolerate ePBS (payloads canonical one slot later, Empty slots), state-gas repricing (97,920 gas per fresh slot), and shorter slots. It may use Frame Transactions for zero-cost races and FOCIL for calldata legs.

The slot-time test

Every Etna constant is in seconds, TAIKO, wei, gas or a count. To check a rule at a new slot time, ask: does it count L1 blocks? Only three do, and all are L1-given: blockhash (256 blocks), EIP-2935 (8,191 blocks) and the attester's anchor-lag policy (20 blocks, 40 s to 4 min). Windows in seconds cover more blocks as slots shrink, so finality margins grow; windows in blocks shrink in wall time, so the design keeps its worst-case anchor age (about 96 minutes) under the 2935 window at 2-second slots (4.55 hours). Blob capacity per second is roughly constant, so batch sizes are per second; gas per block shrinks, so a landing stays under 10 M gas.

Frame Transactions in two shapes

  • Direct to builder: the lander's own nonce with an expiry frame in front and a status-VERIFY frame behind. Any revert makes the whole transaction invalid: no gas, no blob fee. This is the primary landing path and needs no builder trust for safety.
  • Public mempool: a shared gate contract whose nonce is the lock; of all transactions sharing one nonce at most one can ever be included and the rest are invalid and free. It is the only censorship-resistant race that propagates through the public mempool, and it is deployed only once the EIP is Final because its pins (frame count, selector, expiry address) are still moving.
  • Without EIP-8141: plain transactions with a deadline field; a losing lander pays about 25k gas plus one blob fee; nothing else changes.

Self-check

Why does Etna never read the EIP-4788 beacon root?

Reading it "at time T" means probing by slot timestamp (R5), it has gaps at ePBS Empty slots, and its window is 4.5 hours at 2-second slots. The prevrandao accumulator gives the same entropy without any of that.

What is the one property Frame Transactions do not give?

That the L2 slot is used. They fix who pays for a lost race, never whether a landing happens; an ePBS builder can still reveal an invalid payload.

At 2-second slots, why does the inbox use the EIP-2935 path for almost every landing?

blockhash then covers only 8.5 minutes, less than the happy-path landing latency after a 48-second anchor age plus proving.

Challenge this

Pick any parameter on the parameters page and try to break it at 2-second slots with ePBS Empty slots. The design claims every one survives; find the weakest.
