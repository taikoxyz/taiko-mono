Your dependency map

Start with Ethereum headers, storage proofs and transactions. Learn authenticated context before migration. The transaction-race lesson explains submission costs. Landing supplies the proof and publication concepts used by the hatch. The hatch explains queue progress before migration considers inherited requests and custody continuity. C8 explains how the message identities used by these mechanisms get exact bytes. Then study permissionless registration, local block validity, how limitations are recorded, and how to read a conditional argument. The arrows show teaching prerequisites; the owning integration tables define protocol dependencies.

How to read the evidence

Assumed means a selected rule or a named premise. Proven conditionally means an argument under those premises, not machine verification. Open names the missing decision, integration or evidence.

Diagrams scroll horizontally on narrow screens. Example arithmetic is not a benchmark. Follow numerical citations to the source register or fixture. If a lesson and its owner disagree, the owner controls; report the discrepancy on the convergence PR.
