The problem: arrival order must not choose the verdict

Read a fixed reference

One node has received the parent's data and an L1 record. Another is still waiting. If the second node rejects merely because those inputs are missing, the same block gets different verdicts depending on delivery order.

Assumed, C7-R07. A block's own L1 reference, R_b, is the later of its anchor and its opening's nonzero l1Ref. The block's own anchor must be at least ANCHOR_MIN_AGE old at the block's timestamp (C7-R09). The opening is the signed context the block names. The parent check accepts a parent that passes gossip validation, or whose landing is recorded at that reference. It never substitutes the node's latest L1 head or a future descendant's reference. Owning definition; no descendant input; anchor age at the block timestamp.

Proven conditionally: nodes with the same inputs and canonical L1 view agree. A later landing cannot rewrite an older reference's record. C7 states this argument under A-L1VIEW, C2-R13 and C2-R14, alongside its execution and registry premises. Agreement argument; named premises.

The mechanism: missing, false or passed

A hold is unfinished evaluation

Assumed, C7-R01/R14. An evaluable failure makes the block invalid even when something else is missing. If nothing evaluable fails but required context is missing, the node holds it. Only passing every required check makes it valid. V6 execution is the only rule deferred past a hold. Steps 11 (anchor) and 12 (request queue) still run while the parent check is unresolved, whenever their own inputs are complete; either can reject the block. Execution runs only after the preceding checks pass. Results; evaluation order and re-entry.

Assumed, key boundary. If the parent is known invalid and the held canonical state at the child's reference records no landing of it, the child is invalid. A hold is appropriate only while that parent verdict or reference state is unresolved, provided no other evaluable rule fails. Expiring a hold drops the block without deciding validity; later context resumes the earliest unfinished check. Parent rule; finality and re-entry.

Proven conditionally: the reference contains the parent's landing, so the parent check passes. The remaining checks must still pass. A node that lacks the reference holds the child if no other evaluable rule has failed; obtaining it resolves that missing input.

Assumed producer rule; conditional timing. For a child that is a later block under its parent's opening, where the parent is accepted only by landing at L1 timestamp T_L, an honest producer uses an anchor at or after that landing and a timestamp no earlier than T_L + ANCHOR_MIN_AGE. This lower bound alone does not guarantee a child in the same opening: the term window and parent-timestamp rule must also hold. C7 derives the condition under V2, V4, V5 and S2-R11; construction also assumes A-L1LIVE, A-L1VIEW and the required certificate for a parent at the landing tip, or the opening object when the child is second under that opening. A late landing can force a pause until a permitted later opening, whose lock S2 owns, or recovery through C2 landing or the hatch. C7-R07's timing rule and premises.

Countercase from the same vector: when the parent is invalid and complete context shows no landing at the child's fixed reference, the child is invalid. A later parent landing or a descendant with a newer reference cannot repair this child's gossip verdict. C7-T06 (iv), fully informed case.

The limit: gossip validation and landed acceptance differ

Know which result you are reading

Assumed, C7-R01/R15. VALID_GOSSIP is the node's pre-landing predicate. VALID_LANDED is the combination of the guest's assertions and the Inbox's checks, accepted through the L1 landing record. An importer follows an accepted landed range even if its earlier gossip verdict rejected a block; that does not rewrite the earlier gossip verdict. The exact landed-rule listing and inherited parent consequence remain owner work under D62. Definitions and differences; separate landing acceptance; carried obligations.

Assumed, contiguity limits. T11 names the honest-quorum premise. Outside it, a cartel can land a request block that fails gossip queue order while remaining inside C3's landing accounting. C7 supplies no evidence object for either form below. C7-R15.

Check your understanding

The parent is invalid and the fixed reference records no landing. Keep waiting?

No. Once both inputs are held, the parent check fails and the child is invalid. Later L1 progress does not change that old reference. C7-R07.

A context hold expires. Is that an invalid verdict?

No. The block is dropped without a verdict. Missing context arriving later resumes the earliest unfinished check. A different evaluable failure would already have justified rejection. Hold transitions.

A block rejected by gossip later lands. Must the importer keep rejecting that chain?

No. It accepts the landed range under VALID_LANDED. The earlier VALID_GOSSIP verdict stays distinct, and evidence exists only where the specified evidence rules provide it. C7-R15; landing transition.

Challenge the assumptions

  • Do both nodes hold the same authenticated L1 record and the same signed inputs, or is one still missing context?
  • Does a proposed repair change this block's actual inputs, or quietly rely on a later descendant?
  • Does the claimed failure belong to gossip validation, landing acceptance or an evidence rule?
