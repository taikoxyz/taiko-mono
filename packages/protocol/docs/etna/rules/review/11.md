## Q11-1

**U = 151,200 is stated as a target, a reference and an imperative**

**Text.** §10: "Use U=151,200"; §11 row U: "the target deployment selects U=151,200 (about 7 days), subject to validation"; PARAM-11-2: "Values in the table are references only".

**Why it matters.** A deployment with U = 10,000 satisfies PARAM-11-8's bounds and every other numbered rule, yet arguably violates "Use U=151,200". Conversely a target deployment at U = 151,200 needs no exception. The three sentences give the same number three different statuses, and the answer is observable at acceptance: either U is a launch requirement or it is a suggestion.

**Would close it.** state one status for U = 151,200 — a launch requirement for the target deployment, or a reference value with no obligation — and align §10's imperative with it.

## Q11-3

**The leaf-calldata bound names no gas limit and no conversion**

**Text.** "maxBatchBlocks ≥ 1, and small enough that its leaf calldata ((maxBatchBlocks − 1) × 32 bytes) fits within the per-transaction gas limit".

**Why it matters.** The formula produces bytes, while the constraint is a gas limit, and no calldata gas price or margin is given. "The per-transaction gas limit" could be the L1 block gas limit, an L1 transaction cap the spec does not otherwise define, or the L2 block gas limit. The bound is not checkable until the limit and the conversion are named, and a deployment could satisfy it under one reading and fail under another.

**Would close it.** name the limit and the worst-case gas price/margin (for example "fits within 30,000,000 L1 gas at 16 gas per non-zero byte"), or express the bound directly in bytes.

## Q11-5

**"This response budget" has no antecedent, owner or acceptance**

**Text.** "Publish and exercise this response budget; no guaranteed reaction time is implied."

**Why it matters.** "This" points at the preceding analysis of detection, DAO decision/authorization, L1 inclusion and L2 delivery, but there is no budget format, no publisher, no threshold and no place to publish. "Exercise" is untestable. Yet this is the only rule that addresses the emergency-execution risk the paragraph itself raises ("forfeiture needs timely emergency execution or may be lost"). A deployment that writes "no guaranteed reaction time" and nothing else conforms.

**Would close it.** make the budget a deployment-manifest field with its components (detection, DAO authorization, L1 inclusion) and a tested drill, or state that it is guidance.

## Q11-9

**missLimit's margin has no measurable bound**

**Text.** "1 ≤ missLimit ≤ 65,535 (STAKE-4.2-6); it should exceed the number of consecutive blocks an honest validator can miss: by failing to sign under this spec's own rules (its L1 view lagging, checkpoint trust not yet passed, a restart) ... and through precommits that reach proposers too late (section 12, item 33). A value worth hours of blocks leaves the penalty to a validator that has been absent from LastCommit for that long". The reference value is "3,600, about 4 hours at 4 s blocks; pin before launch".

**Why it matters.** The spec bounds none of these causes in blocks: a validator's L1 view can lag for as long as its L1 node does (RECOV-8-5), checkpoint trust stays closed until the local chain catches up with the target (SYNC-9-6a), a restart takes as long as the operator's recovery, and precommits can reach proposers too late for as long as the validator's network path stays slow (section 12, item 33). "Should exceed" therefore names no number a deployment can check, the reference value binds nothing (PARAM-11-2), and missLimit is an immutable of the staking contract, so a value chosen too low changes only with an upgrade (STAKE-4.1-40). An honest validator that misses more than missLimit consecutive blocks for one of these reasons is penalized like any other (section 12, item 31), while a high value delays the penalty for a member that really is offline.

**Would close it.** state whether the margin is a launch requirement, and if so the measurement it rests on (for example the longest expected L1-lag or restart gap in L2 blocks, with headroom) and where ACCEPTANCE records it; or state that it is guidance only.
