## Q3.2-1

**The floor and unit of "BFT time" are undefined**

**Text.** "`timestamp` | max(parent.timestamp + 1, ⌊BFT time⌋, anchor.timestamp)".

**Why it matters.** Ethereum timestamps are integer Unix seconds. CometBFT's BFT time is a `time.Time` with sub-second precision, and "⌊BFT time⌋" does not say whether it is floored to seconds, truncated toward zero, or converted to a Unix timestamp first. Two nodes with the same BFT time but different conversion can compute different header timestamps at a second boundary, and the header is compared "field by field" by other nodes.

**Would close it.** define the representation (for example "BFT time as Unix seconds, floored, i.e. `uint64(t.Unix())`") and state whether a proposal whose timestamp differs by one second is invalid.

## Q3.2-6

**The block-start call's proving cost is unmetered**

**Text.** "the EL makes one message call to `onBlockStart` on the staking contract (STAKE-4.2-4), at the `EtnaStaking` proxy address built into it (PARAM-11-10b), from the system caller `0xfffffffffffffffffffffffffffffffffffffffe`, with exactly 30,000,000 gas available to the call's frame" … "it is not counted in the block's gasUsed or in its zk gas (`difficulty`), and it pays no fee." FI-7.2-8's singleton build "makes the block-start staking call (CONS-3.2-13) exactly as the block does".

**Why it matters.** zk gas exists to bound what a block costs to prove, and the call runs outside it, with up to 30,000,000 gas, in every block and again in every 7.2 singleton trial. STAKE-4.2-8 bounds only the EVM gas of the contract's own worst case, and the contract is upgradeable (STAKE-4.1-40). An implementation, faulty or upgraded, that spends its gas on the work most expensive to prove keeps every block valid for nodes but can make the blocks unprovable (MODEL-1-2): settlement stops, production pauses at U, a governance recovery from a c whose L2 state holds that code restarts with it, and the block that would carry the repair makes the call first (LIMIT-12-29). MODEL-1-2 now counts both calls in each block's worst case and acceptance section 1 measures them, but only for the implementations measured.

**Would close it.** decide whether to meter the call's zk gas against a fixed per-call budget, a call that exceeds it being treated as a call failure under CONS-3.2-13 (state unchanged, block valid, the fallback key set signs two heights later), and if so state the budget and its place in MODEL-1-2's worst case; or state that the unmetered proving cost is accepted, bounded only by acceptance and by the DAO's review of each staking contract upgrade.
