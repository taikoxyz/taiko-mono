## Q5.4-1

**Which app bootstrap implementation and store layout implement the metadata scan and offline installation?**

**Text.** DATA-5.4-3 through DATA-5.4-5 require metadata reconstruction, a precise post-s state and durable offline bootstrap of stock v0.40.0 stores.

**Why it matters.** Beyond the public EL verifier tracked in [Q5.3-1](5.3.md#q53-1), app bootstrap needs a concrete metadata scanner and pinned app/Comet/evidence-store layouts, with EL canonical indexes, historical state, contradiction handling and durable cross-store installation. These are separate from verifying a public EL snapshot or syncing finalized execution blocks.

**Would close it.** Name the implementation and versions, publish verification/import commands and demonstrate ACCEPTANCE.md section 6, including H+2, evidence, interrupted installation and full-prefix import resource measurements against declared deployment budgets.

## Q5.4-2

**Which operators and endpoints provide the complete app-import path?**

**Text.** DATA-5.4-8 requires an available authenticated current-generation package and all data needed to reach the latest finalized checkpoint; 9.1 retains the consensus archive separately from public blobs.

**Why it matters.** A joining app node needs discoverable archive access and a rotation/outage runbook, including full current-generation consensus history. Public EL snapshots alone do not satisfy this dependency.

**Would close it.** Publish supported packages, consensus archive endpoints/access, responsible operators and the tested rotation/repair procedure.
