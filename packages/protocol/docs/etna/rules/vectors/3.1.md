# 3.1 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). This file asserts only what the text says: each vector follows from the cited statement, or reports that the statement is contradicted. Where the text states a requirement but **not the consequence of violating it**, the row says "violates <ID>" and names no outcome; enforcement is a separate question. Anything undetermined has no vector and is listed under "Not covered" and in [review/3.1.md](../review/3.1.md).

`accept` means the described configuration satisfies the cited statement. `reject` means the statement is contradicted, not necessarily that a block was rejected. Several statements here are implementation constraints, so their enforcement point is not stated at all.

| Vector     | Setup                                                                                                     | Expected                                         |
