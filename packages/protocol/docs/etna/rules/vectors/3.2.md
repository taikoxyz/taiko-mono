# 3.2 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). This file asserts only what the text says: each vector follows from the cited header rule, or reports that it is contradicted. Where the text states a requirement but **not the consequence of violating it**, the row says "violates <ID>" and names no outcome. Undetermined items are under "Not covered" and in [review/3.2.md](../review/3.2.md).

`accept` means the described header satisfies the cited rule. `reject` means it does not. Rules 1–9 of 3.4 are applied by ProcessProposal and FinalizeBlock, and rule 7 requires the header to match 3.2 field by field, so a row whose header violates a field rule states "block invalid" with the 3.4 rule; rows about node or EL behaviour rather than the header's values state no outcome.

## CONS-3.2-1

| Vector     | Setup                                                                                                                                                                | Expected                                                                                                 |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 1.a accept | every non-beneficiary field recomputed from the committed parent, the block's anchor, its LastCommit, BFT time and chain constants matches the header field by field | conforms                                                                                                 |
| 1.b accept | the beneficiary differs from any value a recomputation would produce, and the header is accepted                                                                     | conforms: beneficiary is the stated exception                                                            |

| 1.d reject | the proposer builds a header using values other than those listed, and no node recomputes them                                                                       | violates "The proposer builds with these values; other nodes recompute them"; block invalid (3.4 rule 7) |

## CONS-3.2-13

The text states these consequences of its own: the call fails exactly when it reverts or halts exceptionally, out of gas included; a failed call leaves the state as it was before the call and does not make the block invalid; a call to an address without code succeeds and changes nothing; and a fault of the node's own storage or environment is not a failure of the call. For the other requirements it states none, so those rows say "violates CONS-3.2-13". The calldata bytes are under [ENC-A-10d](A.md#enc-a-10d), and what the call does is under [STAKE-4.2-4](4.2.md#stake-42-4).
