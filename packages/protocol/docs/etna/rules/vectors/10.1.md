# 10.1 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). `accept` means the setup satisfies the cited requirement; `reject` identifies its violation, without inventing an unstated runtime consequence. These are written vectors, not executed client, contract or guest tests.

The height-only rules START-10.1-1, -4, -7, -8, -11 and -12 are retired in [INDEX.md](../INDEX.md); their suffix replacements below govern timestamp activation.

## START-10.1-1a

| Vector      | Setup                                                                                                        | Expected                                                      |
| ----------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| 1a.a accept | A compatible upgrade satisfies the plan/preparation deadline and production and settlement continue across T | permitted; no mandatory stop                                  |
| 1a.b accept | Operators voluntarily wait for settlement or choose downtime while preserving the plan                       | permitted; no zero-downtime guarantee                         |
| 1a.c accept | The first valid V2 block is produced while the pre-T prefix is still unsettled, within all ordinary bounds   | permitted; pre-T settlement is not an activation prerequisite |
