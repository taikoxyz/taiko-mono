# 8 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). This file states only what the text states: each vector either follows from an enumerated condition, or reports that a requirement was violated. Where the text states a requirement but **not the consequence of violating it**, the vector says "violates <ID>" and does not name an outcome. Anything undetermined has no vector; it is listed under "Not covered" and raised in [review/8.md](../review/8.md).

`accept` means the described node behaviour, decided block or recovery call satisfies the rules cited. `reject` means a stated requirement is violated; the consequence, where the text does not name one, is the review question cited.

## RECOV-8-1

| Vector     | Setup                                                                                    | Expected                                                     |
| ---------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 1.a accept | no finalized anchor is available; the node waits and retries; a finalized anchor appears | production pauses and then resumes; no decided block is lost |
| 1.b accept | the cause persists across many rounds                                                    | process keeps running; every retry is lossless               |
| 1.c reject | a liveness pause causes a decided block to be discarded                                  | violates RECOV-8-1                                           |
