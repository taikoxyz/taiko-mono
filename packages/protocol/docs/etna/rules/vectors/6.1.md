# 6.1 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). This file states only what the text states: each vector either follows directly from an enumerated condition, or reports that a requirement was violated together with the outcome the text gives for it. Where the text states a requirement but **not the consequence of violating it**, the vector says "violates <ID>" and does not name an outcome — inventing one would lock in an interpretation nobody decided. Anything you cannot determine has no vector; it is listed under "Not covered" and raised in [review/6.1.md](../review/6.1.md).

`accept` means the described landing satisfies the rules cited. `reject` means a stated requirement is violated. LAND-6.1-10 incorporates the complete reference Solidity block and states "checks are normative". That listing rejects an already settled target "without mutation" and states "any failure reverts everything"; so a landing that fails a check reads `violates <ID>; land reverts (LAND-6.1-10)`, and it changes no state (LAND-6.1-11). A reject that describes an implementation departing from the rules (omitting or reordering a check, gating the call, writing partial state) has no landing to reject and reads only "violates <ID>". Notation used throughout: `K` is the grid interval, `p` the proof origin, `c` the latest checkpoint height at execution and `h` the terminal height of the landing, and `G=lcm(oldK,newK)` the pending plan's common-grid interval.

## LAND-6.1-8

The incorporated reference Solidity compares height, EL hash, Comet hash and FI cursor against `c`'s slot 285 record; it also requires that record's FI cursor to equal the current FI head (LAND-6.1-10).

| Vector              | Setup                                                                                 | Expected                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 8.a accept          | `c=306`; the supplied leaf at `c` equals the leaf computed from `c`'s slot 285 record | accepted                                                                                 |
| 8.b reject          | `c`'s height matches but the EL hash in the leaf differs from `c`'s record            | violates LAND-6.1-8; land reverts (LAND-6.1-10), before proof verification (LAND-6.1-12) |
| 8.c reject          | `c`'s height and EL hash match but the Comet hash differs                             | violates LAND-6.1-8; land reverts (LAND-6.1-10), before proof verification (LAND-6.1-12) |
| 8.d reject          | `c`'s height, EL and Comet hashes match but the FI cursor differs                     | violates LAND-6.1-8; land reverts (LAND-6.1-10), before proof verification (LAND-6.1-12) |
| 8.e accept boundary | `c = p`; there is no leaf at `c` in the leaf list                                     | the check does not apply; origin `p` is bound by the origin-record check                 |

## LAND-6.1-10

This rule incorporates the complete reference Solidity block, including its checks and interface definitions. Its vectors check implementations against that scope; local helper spelling remains illustrative under LAND-6.1-13.

| Vector      | Setup                                                                                                | Expected                                                               |
| ----------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 10.a accept | the implementation performs every check in the toggle, with the same outcomes                        | conforms                                                               |
| 10.b reject | the implementation omits a check that appears only in the toggle (for example the `h < 2**48` bound) | violates LAND-6.1-10 ("checks are normative")                          |
| 10.d reject | the implementation omits the first-seal pauseHeight==0 or h+1<2\*\*48 precondition                   | violates LAND-6.1-10; the incorporated first-seal checks are normative |

_Retired vector `LAND-6.1-10.c`: "the implementation performs a check that the toggle does not list". LAND-6.1-10 requires the incorporated reference checks but states no outcome for this additional check. This case has no active accept/reject assertion; its label remains reserved._
