# 12 — limitation map

**Non-normative.** Section 12 is a limitations register, and in [../README.md](../README.md) its IDs have type `limitation`: they are precise and citable, but they **bind nothing**. There is therefore no accept/reject vector for them — an implementation cannot conform to or fail a limit, and inventing a reject case would turn a disclosed limitation into an obligation nobody wrote. The one exception is LIMIT-12-10a, a requirement stated inside item 10; it is typed `rule` and has accept/reject rows.

What this file does instead: for each numbered item, the rule or measurement the limitation depends on, and what would retire it. A limitation is retired by a change to the rule it describes or by the measurement it asks for; it is never "satisfied" by an implementation. Items that no rule covers are questions, raised in [review/12.md](../review/12.md).
