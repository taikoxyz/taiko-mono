# 5.3 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). Vectors cover public EL snapshots and the additional validator/full-node import path in 5.4. A stated rejection uses the rule's rejection consequence; other failures say "violates <ID>". Deployment questions remain in [review/5.3.md](../review/5.3.md).

Operational labels `retry`, `reject candidate` and `safety halt` name the expected failure-handling outcome. The other `accept`/`reject` labels identify positive/negative conformance cases; they do not by themselves mean that an import succeeds or a candidate is rejected. The Expected column states the required behavior.

## DATA-5.3-1

**Retired.** The fixed-origin-only restriction on app snapshots is replaced by DATA-5.3-1a.
