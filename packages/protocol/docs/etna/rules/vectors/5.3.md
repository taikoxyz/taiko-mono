# 5.3 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). Each vector follows from a stated snapshot/sync or optional reconstruction requirement. Where a requirement has no stated rejection consequence, the vector says "violates <ID>". Gaps are in [review/5.3.md](../review/5.3.md).

`accept` means the described EL startup or replay satisfies the cited rule. `reject` means a stated input or check is contradicted.

## DATA-5.3-1

| Vector     | Setup                                                                                                           | Expected                                                    |
| ---------- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 1.a accept | a new EL starts from a public snapshot of an L1-authenticated settled checkpoint                                | conforms to DATA-5.3-1                                      |
| 1.b accept | a new EL uses the same verified-snapshot path long after launch                                                 | conforms; the option remains available throughout operation |
| 1.c accept | an EL instead starts from genesis using public material                                                         | conforms to DATA-5.3-1                                      |
| 1.d reject | snapshot authentication requires a validator-private database, private witnesses/signatures or a running L2 RPC | violates DATA-5.3-1                                         |
| 1.e reject | later EL nodes are refused snapshot startup solely because the launch period ended                              | violates the continuing startup option                      |

## DATA-5.3-2

| Vector     | Setup                                                                                                     | Expected                                          |
| ---------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| 2.a accept | source-available snapshot-verification/checkpoint-sync tooling and the listed public inputs are provided  | conforms to DATA-5.3-2                            |
| 2.b accept | verified snapshot startup is supported but no independent genesis-to-head blob replay program is supplied | conforms; full replay is optional                 |
| 2.c reject | only a closed-source snapshot verifier is provided                                                        | violates the source-available tooling requirement |
| 2.d reject | launch or later EL admission requires the optional full replay mode                                       | violates DATA-5.3-2                               |

_Which program, version and licence satisfy the tooling requirement: no vector — [Q5.3-1](../review/5.3.md#q53-1)._

## DATA-5.3-4

| Vector     | Setup                                                                                                                                                                                                                                   | Expected                                            |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| 4.a accept | the own finalized L1 view authenticates s; the header hash matches its checkpoint, required ancestors link to that header, actual account/storage/code verify against the header stateRoot, and derived indexes are verified or rebuilt | conforms to DATA-5.3-4                              |
| 4.b accept | proof-checked state sync establishes the same complete state/code commitment as local recomputation                                                                                                                                     | conforms to the equivalent verification option      |
| 4.c reject | a copied correct header or matching snapshot metadata is accepted without verifying downloaded state                                                                                                                                    | violates DATA-5.3-4                                 |
| 4.d reject | a changed balance, nonce, storage slot or code is accompanied by a newly computed matching file checksum                                                                                                                                | reject the stateRoot/code mismatch under DATA-5.3-8 |
| 4.e reject | derived database indexes are used without verification or rebuilding                                                                                                                                                                    | violates DATA-5.3-4                                 |
| 4.f reject | the checkpoint is accepted solely from the snapshot publisher's L1 claim                                                                                                                                                                | violates own-finalized-L1 authentication            |
| 4.g reject | a required ancestor header/hash is tampered with and no longer links to the authenticated starting header                                                                                                                               | reject the hash mismatch under DATA-5.3-8           |
| 4.h accept | the first post-s block computes its base fee and BLOCKHASH results from the bounded authenticated ancestor context without pre-s state replay                                                                                           | conforms to DATA-5.3-3/4                            |

## DATA-5.3-5

| Vector     | Setup                                                                                                                                       | Expected                                                                    |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 5.a accept | blob replay verifies versioned hashes and complete (p,h] blobs in canonical L1 landing order; p and actual c come from authenticated inputs | conforms to DATA-5.3-5                                                      |
| 5.b accept | a post-s landing has p < s; its full blobs are checked without executing state before s                                                     | conforms to DATA-5.3-5                                                      |
| 5.c reject | blob replay uses unauthenticated p/c, a noncanonical landing order or a missing required blob                                               | violates DATA-5.3-5; missing required material is rejected under DATA-5.3-8 |

## DATA-5.3-6

| Vector     | Setup                                                                                                                                                        | Expected                             |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------ |
| 6.a accept | for p < s <= c < h, prefix EL hashes/links match authenticated checkpoint hashes, only (c,h] executes from c's state, and h's hash/stateRoot/FI cursor match | conforms to DATA-5.3-6               |
| 6.b reject | an overlapping prefix is executed twice                                                                                                                      | violates DATA-5.3-6                  |
| 6.c reject | the terminal hash, stateRoot or FI cursor is unchecked                                                                                                       | violates DATA-5.3-6                  |
| 6.d reject | post-s replay starts a landing from c < s without its authenticated state                                                                                    | violates the stated c >= s condition |

## DATA-5.3-7

| Vector     | Setup                                                                                                                                                           | Expected                                                   |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 7.a accept | a retained snapshot and subsequent history are selected with authenticated generations/origins and latest-checkpoint matching precedes the section 9 trust gate | conforms to DATA-5.3-7                                     |
| 7.b reject | a snapshot or subsequent blocks belong to discarded history                                                                                                     | reject the authenticated-history mismatch under DATA-5.3-8 |
| 7.c reject | a correct older snapshot is enough to grant trust before the latest L1 checkpoint is reached and matched                                                        | violates DATA-5.3-7                                        |
| 7.d reject | selecting a snapshot silently creates a new same-domain Comet genesis at that checkpoint                                                                        | violates the unchanged section 9 fixed-genesis requirement |

## DATA-5.3-8

| ---------- | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |

## DATA-5.3-9

| Vector     | Setup                                                                                                                                    | Expected                                                   |

| 9.a accept | published snapshots and needed subsequent-sync data are available; archive inputs actually used are authenticated against L1 commitments | conforms to DATA-5.3-9                                     |
