# 5.4 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). These vectors specify authenticated app checkpoint import without pre-s EL execution, followed by stock CometBFT continuation. Deployment details are in [review/5.4.md](../review/5.4.md).

## DATA-5.4-1

| Vector     | Setup                                                                                                  | Expected                             |
| ---------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------ |
| 1.a accept | s > current origin; own finalized L1 authenticates generation, EL state and same-generation Comet hash | conforms to DATA-5.4-1               |
| 1.b accept | s equals recovery origin; existing fixed-genesis path uses its old Comet hash only as proving boundary | conforms to DATA-5.4-1               |
| 1.c reject | checkpoint from another generation is used as this generation’s Comet state                            | violates DATA-5.4-1                  |
| 1.d reject | same-domain InitialHeight is reset to s+1                                                              | violates DATA-5.4-1 and RECOV-8.4-15 |

## DATA-5.4-2

| Vector     | Setup                                                                                                                 | Expected                                                 |
| ---------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 2.a accept | complete original prefix archive authenticates both hash chains, block bytes, commit links and all committee switches | conforms to DATA-5.4-2                                   |
| 2.b reject | EL stateRoot/checksums or publisher validator weights substitute for authenticated archive/registry proofs            | violates DATA-5.4-2                                      |
| 2.c reject | rotation uses D(t)’s proof root instead of S(t)’s own anchor root, or omits R floor                                   | violates DATA-5.4-2                                      |
| 2.d reject | an envelope, block part set, commit link or EL header is changed                                                      | violates DATA-5.4-2; candidate rejected under DATA-5.4-5 |

## DATA-5.4-3

| Vector     | Setup                                                                                                                                         | Expected               |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| 3.a accept | metadata scan matches a normal replay’s current/pending sets, priority state, FI cursor, historical validators and committed-evidence markers | conforms to DATA-5.4-3 |
| 3.b reject | validator hashes match but imported proposer priorities or pending H+2 updates come directly from an unverified database                      | violates DATA-5.4-3    |
| 3.c reject | missing pre-s validator/parameter history makes an otherwise valid post-s evidence item unverifiable                                          | violates DATA-5.4-3    |
| 3.d reject | previously committed evidence is accepted again because committed-evidence markers were not rebuilt                                           | violates DATA-5.4-3    |
| 3.e accept | prefix scan derives metadata without any pre-s EVM execution, FI trial or normal FinalizeBlock                                                | conforms to DATA-5.4-3 |

## DATA-5.4-4

| Vector     | Setup                                                                                                                                                                                                     | Expected                               |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| 4.a accept | snapshot is at S(t), S(t)+1 or H(t); post-s last/current/next sets match stock H+2 semantics without needing successor blocks                                                                             | conforms to DATA-5.4-4                 |
| 4.b reject | post-s AppHash is copied from header(s) as ELHash(s-1)                                                                                                                                                    | violates DATA-5.4-4                    |
| 4.c reject | only 256 EL headers remain and a required older anchor checkpoint cannot be compared                                                                                                                      | violates DATA-5.4-4                    |
| 4.d reject | LastResultsHash, full BlockID, InitialHeight, app version or consensus params differ from the derived stock post-s state                                                                                  | violates DATA-5.4-4                    |
| 4.e accept | first post-s anchor proves checkpoint s; authenticated reconstructed EL headers supply the ancestry equality without claiming independent pre-s execution                                                 | conforms to DATA-5.4-4 and CONS-3.4-16 |
| 4.f accept | first post-s block at s+1 has an anchor proving a retained checkpoint q with max(o,s-U+1)<=q<s, U>256 and s-q>255; EL canonical indexes o..s resolve q and forkchoice accepts it after import and restart | conforms to DATA-5.4-4 and SYNC-9-3    |
| 4.g reject | app-side headers cover o..s but EL canonical/hash indexes contain only s-255..s and cannot resolve a required older finalized hash                                                                        | violates DATA-5.4-4                    |

## DATA-5.4-5

| Vector     | Setup                                                                                                                                                                        | Expected                                                                                                                      |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 5.a accept | all verified stores are durably staged while signer is disconnected; one completion boundary is published before start                                                       | conforms to DATA-5.4-5                                                                                                        |
| 5.b reject | crash leaves EL at s but app/Comet/evidence at an earlier height and node starts from that mixed state                                                                       | violates DATA-5.4-5                                                                                                           |
| 5.c accept | peer sends unverifiable data; that candidate is rejected while node stays untrusted                                                                                          | candidate rejected under DATA-5.4-5                                                                                           |
| 5.d accept | archive data is temporarily missing                                                                                                                                          | synchronization stays incomplete and the node untrusted while it obtains material and retries under DATA-5.4-5 and DATA-5.3-8 |
| 5.e reject | import depends on a forked engine or claims the empty ABCI snapshot methods perform the import                                                                               | violates DATA-5.4-5                                                                                                           |
| 5.f accept | Comet header(s) matches finalized L1 and its original envelope passes DataHash authentication, but the envelope execution-header hash differs from the same slot 285 EL hash | safety halt and alert under DATA-5.4-5                                                                                        |
| 5.g accept | an envelope paired with an authenticated Comet header fails DataHash authentication                                                                                          | candidate rejected under DATA-5.4-5; node stays untrusted                                                                     |
| 5.h reject | required archive material is missing, but the node publishes a completed import boundary or starts from partially aligned stores                                             | violates DATA-5.4-5                                                                                                           |

## DATA-5.4-6

| Vector     | Setup                                                                                                               | Expected                                                                       |
| ---------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 6.a accept | import latest checkpoint, pass both-hash session trust, process s+1 by normal P2P/FinalizeBlock and enter consensus | conforms to DATA-5.4-6                                                         |
| 6.b accept | import older current-generation checkpoint, execute P2P suffix and match latest target before trust/signing         | conforms to DATA-5.4-6                                                         |
| 6.c reject | trust is granted at older s without reaching the latest session target                                              | violates DATA-5.4-6 and SYNC-9-5                                               |
| 6.d reject | a later FI skip needs a previously executed parent state that was pruned and EL refuses non-retryably               | violates DATA-5.4-6; safety halt under RECOV-8-13                              |
| 6.e reject | generation changes during import but old-generation node is admitted                                                | violates DATA-5.4-6; startup generation mismatch safety-halts under RECOV-8-16 |

## DATA-5.4-7

| Vector     | Setup                                                                          | Expected                            |
| ---------- | ------------------------------------------------------------------------------ | ----------------------------------- |
| 7.a accept | existing signer HRS remains separate and is checked before any signing session | conforms to DATA-5.4-7              |
| 7.b reject | Comet snapshot import replaces or lowers persisted signer HRS                  | violates DATA-5.4-7 and RECOV-8.2-1 |
| 7.c reject | lost/uncertain signer state is restored from snapshot to resume signing        | violates DATA-5.4-7 and RECOV-8.2-3 |
| 7.d reject | import grants an old-generation key signing authority in the superseded domain | violates DATA-5.4-7                 |

## DATA-5.4-8

| Vector     | Setup                                                                                                              | Expected                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| 8.a accept | one supported app package and all suffix dependencies remain available; old path is retired only after replacement | conforms to DATA-5.4-8                                                            |
| 8.b reject | EL-only public path works but joining app nodes lack every complete authenticated consensus-import path            | violates DATA-5.4-8                                                               |
| 8.c accept | consensus archive is shared off L1 while public EL-only snapshot/data path remains available                       | conforms to DATA-5.4-8                                                            |
| 8.d reject | prefix metadata scan or copied state is claimed as independent EL execution evidence before recovery               | violates RECOV-8.1-7; DATA-5.4-8 requires independently executed retained history |
