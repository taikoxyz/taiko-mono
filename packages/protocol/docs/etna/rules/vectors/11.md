# 11 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). This file states only what the text states. Where the text states a requirement but **not the consequence of violating it**, the vector says "violates <ID>" and does not name an outcome. Anything undetermined has no vector; it is listed under "Not covered" and raised in [review/11.md](../review/11.md).

`accept` means the described deployment or node satisfies the statement cited. `reject` means a stated requirement is violated.

## Row types

Every parameter row is either a **rule** (it imposes an invariant or a bound) or a **definition** (it says what a parameter is or where it lives, and imposes nothing). Only rules carry IDs. No reference value in the last column is binding: PARAM-11-2 makes the table references only.

| Row                                                                                 | Type                                                                            | ID                                                              |
| ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| L, genesisCutoff                                                                    | rule — L is chosen independently of U                                           | PARAM-11-4                                                      |
| `forcedInclusionDelay`, `maxAnchorAge`                                              | rule — bounds                                                                   | PARAM-11-5                                                      |
| `maxBatchBlocks`, FI fee and doubling threshold, verifier, `protocolFeeRecipient`   | rule — bounds                                                                   | PARAM-11-6                                                      |
| vp_unit, s_min, n_max                                                               | rule — bound on vp_unit; power follows 4.3                                      | PARAM-11-7                                                      |
| U                                                                                   | rule — bounds                                                                   | PARAM-11-8                                                      |
| K (grid interval)                                                                   | rule — bounds and provability                                                   | PARAM-11-9                                                      |
| `L2_BLOCK_GAS_LIMIT`, `L2_BLOCK_ZK_GAS_LIMIT`, metering, multiplier table           | rule — a change is a rule upgrade (10.1); the limit's meaning is defined in 3.1 | PARAM-11-10a                                                    |
| `minStake`, delays, `slashBountyBps`, `slashSink`, `l2ChainId`, Inbox proxy address | rule — bounds and equality checks                                               | PARAM-11-11                                                     |
| `forfeitBps`                                                                        | rule — bound and destination                                                    | PARAM-11-12                                                     |
| `C_CAP_MIN`, `P_REF`, `S_MIN_TOTAL`                                                 | definition — "Launch manifest, not consensus"; no bound                         | none — see [review/11.md](../review/11.md#normativity-boundary) |
| `timeout_commit`                                                                    | definition — "Block cadence only"; the ~4 s value is a target                   | none — see [review/11.md](../review/11.md#normativity-boundary) |

## PARAM-11-1

| Vector     | Setup                                                                                                                                                            | Expected                                                            |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
