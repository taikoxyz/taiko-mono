# 6.2 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). This file states only what the text states: each vector either follows directly from an enumerated condition, or reports that a requirement was violated. Where the text states a requirement but **not the consequence of violating it**, the vector says "violates <ID>" and does not name an outcome. Anything you cannot determine has no vector; it is listed under "Not covered" and raised in [review/6.2.md](../review/6.2.md).

Unless a row states S, the Etna start S is 0.

The nine numbered items are assertions the guest must prove; a proof that does not establish one fails the requirement, so `reject` below means "violates <ID>" rather than a named on-chain outcome. The verifier is opaque to `land` (PROOF-6.2-2), so the nine items are enforced by the pinned guest image, not by a contract check — [Q6.2-1](../review/6.2.md#q62-1). `p` is the proof origin, `h` the terminal height, `c` the checkpoint at execution and `o` the generation's start height; "the set that signs x" is the validator set, keys and powers, that 4.3 gives for height x.
