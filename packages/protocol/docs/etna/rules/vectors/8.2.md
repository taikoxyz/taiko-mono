# 8.2 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). This file states only what the text states: each vector either follows from an enumerated condition, or reports that a requirement was violated. Where the text states a requirement but **not the consequence of violating it**, the vector says "violates <ID>" and does not name an outcome. Anything undetermined has no vector; it is listed under "Not covered" and raised in [review/8.2.md](../review/8.2.md).

`accept` means the described signer configuration or signing decision satisfies the rules cited. These rules bind the signer, not the chain, so most violations have no on-chain rejection; the consequence is the review question cited.

## RECOV-8.2-1

| Vector     | Setup                                                                                                                           | Expected             |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| 1.a accept | separate HRS state per full `chain_id`; each signature persisted before it is returned; the state is never reset or rolled back | conforms             |
| 1.b reject | one HRS state shared across chain ids                                                                                           | violates RECOV-8.2-1 |
| 1.c reject | a signature is returned before it is persisted                                                                                  | violates RECOV-8.2-1 |
| 1.d reject | the HRS state is rolled back after a restart                                                                                    | violates RECOV-8.2-1 |

## RECOV-8.2-2

| Vector     | Setup                                                                                                                                                                                                    | Expected                                                                                                                                  |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 2.a accept | the key exists only in the signer that owns the HRS state                                                                                                                                                | conforms                                                                                                                                  |
| 2.c accept | a rebuilt home lacks the signer's WAL for its last signed height H; its own latest finalized-L1 target is below H                                                                                        | keep a durable floor of at least H + 1; refuse all votes and proposals until a verified committed chain covers H and session trust passes |
| 2.d reject | a replacement signer or restart accepts a nil vote at a later round of H despite that floor                                                                                                              | violates RECOV-8.2-2                                                                                                                      |
| 2.e accept | the old signer process is fenced; on the bound stores, predecessor and durable WAL prefix match, stock replays through the last signing decision without block/state sync, and HRS and trust are certain | stock replay may resume at H subject to the saved HRS                                                                                     |
| 2.f accept | peers claim H is committed but provide no verifiable commit or authenticated landed descendant                                                                                                           | remain fenced                                                                                                                             |
| 2.b reject | a copy of the key signs outside that state                                                                                                                                                               | violates RECOV-8.2-2                                                                                                                      |
| 2.g accept | manual rebuild changes the instance ID, or the ID survives but WAL continuity cannot be established                                                                                                      | signer automatically persists the floor before admitting signatures                                                                       |
| 2.h reject | startup block-syncs one block to the predecessor and is admitted to sign at H based on the WAL being present                                                                                             | violates RECOV-8.2-2; stock skips WAL catch-up                                                                                            |
| 2.i reject | a validator imported the settled tip s above the generation origin, signed at undecided H = s + 1 and restarted on the bound stores without block or state sync; its WAL lacks `#ENDHEIGHT s`            | stock can start, but the signer durably fences H and rejects a request to sign there                                                      |
| 2.j reject | a live request repeats the saved HRS and bytes after stock fell through on a replay error                                                                                                                | the request cannot confirm replay; the signer enforces the durable floor                                                                  |
| 2.k accept | the confirmed replay repeats the saved HRS and canonical bytes while handling a record before the end of the signer-bound prefix                                                                         | return the saved signature; strictly higher HRS can be signed in the same trusted attempt                                                 |
| 2.l accept | a torn record follows all signer-bound input; stock repairs the tail and the preserved binding is verified                                                                                               | a clean replay from the predecessor must confirm again; the tail repair alone does not fence H                                            |
| 2.m accept | no ValidBlock; rebuilt proposal conflicts at the saved HRS; the authenticated replay applies the original signed proposal and restores the round and lock                                                | reject the conflicting proposal; the independently confirmed vote can receive its first signature during replay                           |
| 2.n reject | a proposal HRS match alone opens voting despite a different POLRound or unknown lock                                                                                                                     | fresh signing remains closed                                                                                                              |
| 2.o accept | H stays undecided until the stock 1 GiB WAL limit has deleted the files holding `#ENDHEIGHT H−1`; the validator restarts at H                                                                            | no eligible replay exists, and the signer persists a floor of at least H + 1 before any fresh signature                                   |

## RECOV-8.2-3

| Vector     | Setup                                                             | Expected                                                       |
| ---------- | ----------------------------------------------------------------- | -------------------------------------------------------------- |
| 3.a accept | the HRS state is lost, or its latest value is uncertain           | stop signing                                                   |
| 3.b reject | the state is deleted and signing resumes                          | violates RECOV-8.2-3 ("deleting state cannot restore service") |
| 3.c accept | an operator restores service by a means other than deleting state | consistent with the stated prohibition                         |

## RECOV-8.2-4

| Vector     | Setup                                                                                                                                                            | Expected             |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| 4.a accept | signing for a new generation starts only after the own finalized L1 view authenticates the recovery, both 8.4 checks pass, and section 9 checkpoint trust passes | conforms             |
| 4.b reject | a new-generation signature is produced before the L1 view authenticates the recovery                                                                             | violates RECOV-8.2-4 |
| 4.c reject | signing starts while the 8.4 origin-record or genesis check fails                                                                                                | violates RECOV-8.2-4 |

## RECOV-8.2-5

| Vector     | Setup                                                                                                             | Expected             |
| ---------- | ----------------------------------------------------------------------------------------------------------------- | -------------------- |
| 5.a accept | the new generation's HRS state starts at c + 1; after authentication, old-generation signing requests are refused | conforms             |
| 5.b reject | old-generation signing continues after authentication                                                             | violates RECOV-8.2-5 |
| 5.c reject | the new generation's HRS state starts at a height other than c + 1                                                | violates RECOV-8.2-5 |

## RECOV-8.2-6

| Vector     | Setup                                                        | Expected             |
| ---------- | ------------------------------------------------------------ | -------------------- |
| 6.a accept | the same height is signed in two different generations       | not a double sign    |
| 6.b reject | cross-generation votes are submitted as double-sign evidence | violates RECOV-8.2-6 |
