# 4.3 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). Each vector follows from the stated committee rule, or reports that a requirement was violated. Where the text states a requirement but not the consequence of violating it, the vector says "violates <ID>"; the consequence is a separate question. Gaps are in [review/4.3.md](../review/4.3.md).

`accept` means the described set or call satisfies the rule cited. `reject` means a stated condition is violated; where the text says a candidate is not usable, that the fallback key set signs, or that a call reverts, the vector says so. o is the generation's start height, H a block from o + 1 on, and M the `minTotalStake` that H's anchor proves.

## COMM-4.3-1

| Vector     | Setup                                                                 | Expected                                                                                |
| ---------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 1.a accept | generation 0 with S = 1000                                            | the origin record's keys sign 1001 and 1002; the set that signs 1003 is decided at 1001 |
| 1.b accept | a governance recovery with c = 5000                                   | the same rules with o = 5000: the origin keys sign 5001 and 5002, and 5001 decides 5003 |
| 1.c reject | a recovered generation starts from the old generation's set or powers | violates COMM-4.3-1                                                                     |
