# 4.2 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). Each vector follows from the stated steps of the block-start call, or reports that a requirement was violated. Where the text states a requirement but not the consequence of violating it, the vector says "violates <ID>"; any consequence is a separate question. Gaps are in [review/4.2.md](../review/4.2.md).

`accept` means the described call or contract state satisfies the rule cited. `reject` means a stated step, order or deployment requirement is contradicted; where the text says the call reverts, the vector says so. Which bits of `missBitmap` are set is 3.4's rule and is tested there; the vectors below take the bitmap as given.

## STAKE-4.2-4

| Vector     | Setup                                                                                               | Expected                                                           |
| ---------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 4.a accept | the system caller calls `onBlockStart(g, b)` with `g` and `b` taken from the block's `extraData`    | the contract stores `g` and takes the three steps                  |
| 4.b reject | an ordinary transaction calls `onBlockStart`                                                        | the call reverts (stated: "reverts a call from any other address") |
| 4.c accept | `onBlockStart` stored generation 3; double-sign evidence for generation 3 arrives in the same block | the generation condition of STAKE-4.1-32 holds                     |
| 4.d reject | the snapshot is stored before the penalties, so a bond penalized below `minStake` is still a member | violates STAKE-4.2-4 ("the following three steps, in order")       |

## STAKE-4.2-5

| Vector     | Setup                                                                                                                  | Expected                                                                                                    |
| ---------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 5.a accept | seat 3 is occupied with miss count 2; bit 3 of `missBitmap` is 1                                                       | the count becomes 3                                                                                         |
| 5.b accept | seat 3 is occupied with miss count 2; bit 3 is 0                                                                       | the count becomes 0                                                                                         |
| 5.c accept | seat 9 is empty; bit 9 is 1                                                                                            | nothing changes ("Bits of empty seats ... change nothing")                                                  |
| 5.d accept | `missBitmap == 0`                                                                                                      | the miss count of every occupied seat is 0 after the call                                                   |
| 5.e accept | `missBitmap == 4`                                                                                                      | only bit 2 is 1: `(4 >> 2) & 1 == 1`, so only seat 2 counts a miss                                          |
| 5.f reject | a 0 bit lowers the count by one, or leaves it unchanged, instead of resetting it                                       | violates STAKE-4.2-5 ("the count resets to 0")                                                              |
| 5.g accept | `n_max = 64`; bit 100 is 1                                                                                             | nothing changes ("bits at or above n_max change nothing")                                                   |
| 5.h accept | in block P's transactions bond A vacates seat 4 and bond B takes it; A gave no precommit for P; the call runs in P + 1 | P's post-state maps A's key to no seat, so seat 4 carries none of A's misses; B's count is not raised for A |
| 5.i reject | that call raises seat 4's count, charging A's miss to B                                                                | violates STAKE-4.2-5 ("a seat that a bond vacated in the parent block carries none of that bond's misses")  |

## STAKE-4.2-6

| Vector     | Setup                                                                                  | Expected                                                                                      |
| ---------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 6.a accept | `missLimit = 10`; a seat's count reaches 10; effStake = 100,000; `missSlashBps = 1000` | 10,000 is deducted and sent to `slashSink`; the count resets to 0                             |
| 6.b accept | the same, with effStake = 100,001                                                      | `ceil(100,001 × 1000 / 10000)` = 10,001 is deducted                                           |
| 6.c accept | `missLimit = 10`; a seat's count reaches 9                                             | no deduction                                                                                  |
| 6.d accept | the deduction leaves the bond below `minStake`                                         | the bond releases its seat (STAKE-4.1-14c) and is not in this call's snapshot (STAKE-4.2-7)   |
| 6.e accept | `missLimit = 1`; a seat's bit is 1                                                     | the deduction applies in that call                                                            |
| 6.f reject | the deduction is floored                                                               | violates STAKE-4.2-6 ("ceil")                                                                 |
| 6.g reject | part of the deduction is paid to anyone other than `slashSink`                         | violates STAKE-4.2-6 ("all of it to `slashSink` with no bounty")                              |
| 6.h reject | the count stays at `missLimit` after the deduction                                     | violates STAKE-4.2-6 ("reset the count to 0")                                                 |
| 6.i reject | a deployment with `missLimit = 0` or `missLimit = 65,536`                              | violates STAKE-4.2-6 ("`1 ≤ missLimit ≤ 65,535`")                                             |
| 6.j reject | a deployment with `missSlashBps = 0` or `missSlashBps = 10001`                         | violates STAKE-4.2-6 ("`0 < missSlashBps ≤ 10000`")                                           |
| 6.k accept | `missSlashBps = 10000`; a seat's count reaches `missLimit`                             | the whole effStake is deducted; the bond releases its seat and no exit is set (STAKE-4.1-14c) |

## STAKE-4.2-7

| Vector     | Setup                                                                                  | Expected                                                                                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 7.a accept | after step 2 of block H, seats 0, 2 and 5 are occupied                                 | records 0, 2 and 5 hold those bonds' keys and powers and the other 125 records are zero; `snapshotTotalStake` is the sum of the three bonds' effStake; `snapshotHeight == H` |
| 7.b accept | no seat is occupied after step 2 of block H                                            | all 128 records are zero, `snapshotTotalStake == 0` and `snapshotHeight == H`                                                                                                |
| 7.c accept | a member's effStake is `2.5 * vp_unit`                                                 | its `power` is 2 (STAKE-4.1-14e)                                                                                                                                             |
| 7.d accept | a top-up or an exit executes in block X's transactions                                 | X's snapshot does not reflect it; X + 1's snapshot does                                                                                                                      |
| 7.e reject | a transaction changes `snapshotHeight`, `snapshotTotalStake` or a snapshot seat record | violates STAKE-4.2-7 ("Only this call writes these values")                                                                                                                  |
| 7.f reject | record s holds the key of a bond other than the one in seat s                          | violates STAKE-4.2-7 ("record s holds the key ... of the bond in seat s")                                                                                                    |
| 7.g reject | `snapshotTotalStake` sums the powers instead of the bonds' effStake                    | violates STAKE-4.2-7 ("the sum of the effStake of the bonds in those records")                                                                                               |
| 7.h accept | `snapshot()` is called after the block-start call of H                                 | it returns `H`, `snapshotTotalStake` and the occupied records as `SeatMember` entries in ascending seat order                                                                |
| 7.i accept | `n_max = 64`                                                                           | records 64 to 127 are zero                                                                                                                                                   |
| 7.j reject | `n_max = 64` and record 70 is nonzero                                                  | violates STAKE-4.2-7 ("records at or above n_max stay zero")                                                                                                                 |
| 7.k accept | a seat is released by a transaction in block X                                         | the key-to-seat mapping changes in X; the records change only at X + 1's call                                                                                                |

## STAKE-4.2-8

| Vector     | Setup                                                                                                     | Expected                                                          |
| ---------- | --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 8.a accept | `n_max = 128`; every seat occupied; every bit set; every seated bond reaches `missLimit` in the same call | the call fits the 30,000,000 gas limit                            |
| 8.b reject | that worst case needs more than 30,000,000 gas                                                            | violates STAKE-4.2-8 ("must fit the call's 30,000,000 gas limit") |
