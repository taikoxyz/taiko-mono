# 4.2 — accept/reject vectors

**Non-normative.** Rule text lives in [SPEC.md](../../SPEC.md). Each vector follows from what the block-start call stores, or reports that a requirement was violated. Where the text states a requirement but not the consequence of violating it, the vector says "violates <ID>"; any consequence is a separate question. Gaps are in [review/4.2.md](../review/4.2.md).

`accept` means the described call or contract state satisfies the rule cited. `reject` means a stated step, order or deployment requirement is contradicted; where the text says the call reverts, the vector says so.

## STAKE-4.2-4

| Vector     | Setup                                                                                               | Expected                                                              |
| ---------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 4.a accept | the system caller calls `onBlockStart(g)` with `g` taken from the block's `extraData`               | the contract stores `g` and then the candidate snapshot (STAKE-4.2-7) |
| 4.b reject | an ordinary transaction calls `onBlockStart`                                                        | the call reverts (stated: "reverts a call from any other address")    |
| 4.c accept | `onBlockStart` stored generation 3; double-sign evidence for generation 3 arrives in the same block | the generation condition of STAKE-4.1-32 holds                        |
| 4.d reject | the call stores the candidate snapshot but leaves the stored generation unchanged                   | violates STAKE-4.2-4 ("It stores `generation`")                       |
| 4.e accept | the call's calldata is the 36 bytes `0xaa28c32e ‖ abi.encode(uint48(g))`                            | conforms; the bytes are under [ENC-A-10d](A.md#enc-a-10d)             |

## STAKE-4.2-5

**Retired.** The block-start call no longer counts missed signatures, because a precommit missing from a LastCommit is not evidence against its member (4.2); this old ID has no conformance vectors.

## STAKE-4.2-6

**Retired.** The missed-signature penalty was removed with the miss count it acted on (4.2); this old ID has no conformance vectors.

## STAKE-4.2-7

| Vector     | Setup                                                                                            | Expected                                                                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 7.a accept | when block H's call runs, seats 0, 2 and 5 are occupied                                          | records 0, 2 and 5 hold those bonds' keys and powers and the other 125 records are zero; `snapshotTotalStake` is the sum of the three bonds' effStake; `snapshotHeight == H` |
| 7.b accept | no seat is occupied when block H's call runs                                                     | all 128 records are zero, `snapshotTotalStake == 0` and `snapshotHeight == H`                                                                                                |
| 7.c accept | a member's effStake is `2.5 * vp_unit`                                                           | its `power` is 2 (STAKE-4.1-14e)                                                                                                                                             |
| 7.d accept | a top-up or an exit executes in block X's transactions                                           | X's snapshot does not reflect it; X + 1's snapshot does                                                                                                                      |
| 7.e reject | a transaction changes `snapshotHeight`, `snapshotTotalStake` or a snapshot seat record           | violates STAKE-4.2-7 ("Only this call writes these values")                                                                                                                  |
| 7.f reject | record s holds the key of a bond other than the one in seat s                                    | violates STAKE-4.2-7 ("record s holds the key ... of the bond in seat s")                                                                                                    |
| 7.g reject | `snapshotTotalStake` sums the powers instead of the bonds' effStake                              | violates STAKE-4.2-7 ("the sum of the effStake of the bonds in those records")                                                                                               |
| 7.h accept | `snapshot()` is called after the block-start call of H                                           | it returns `H`, `snapshotTotalStake` and the occupied records as `SeatMember` entries in ascending seat order                                                                |
| 7.i accept | `n_max = 64`                                                                                     | records 64 to 127 are zero                                                                                                                                                   |
| 7.j reject | `n_max = 64` and record 70 is nonzero                                                            | violates STAKE-4.2-7 ("records at or above n_max stay zero")                                                                                                                 |
| 7.k accept | a seat is released by a transaction in block X                                                   | `seatOfBond` and `bondInSeat` change in X (STAKE-4.1-14d); the records change only at X + 1's call                                                                           |
| 7.l accept | blocks are produced while the key of the bond in seat 4 signs none of them; nothing else changes | record 4 keeps that bond's key and power in every snapshot those blocks store                                                                                                |

## STAKE-4.2-8

| Vector     | Setup                                                                                               | Expected                                                                           |
| ---------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 8.a accept | `n_max = 128`; every seat occupied                                                                  | the call fits the 30,000,000 gas available to its frame                            |
| 8.b reject | that worst case needs more than 30,000,000 gas                                                      | violates STAKE-4.2-8 ("must fit the 30,000,000 gas available to the call's frame") |
| 8.c reject | the call's work grows with the number of issued bonds or with what earlier blocks' transactions did | violates STAKE-4.2-8 ("bounded by n_max seats")                                    |
