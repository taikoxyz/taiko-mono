# Etna verification worklist

This is the current remaining-work index for the existing Etna verification
project. [Tracking issue #22355](https://github.com/taikoxyz/taiko-mono/issues/22355)
is its GitHub entry point. Historical batch plans and reports retain their
original measurements; they are not current completion checklists.

## Baseline and completion rules

Baseline: published draft [PR #22387](https://github.com/taikoxyz/taiko-mono/pull/22387),
head `6057aee347f4865830593f1775e99b4f4822f96c`. The preceding five-increment
batch is complete: 369 exact TLC outcomes, 65 assessed fault obligations,
171 Python tests and five separate controller tests. See the
[final retrospective](REPORT.md#five-increment-batch-final-gate-and-retrospective).
These numbers describe selected finite evidence, not whole-module completion.

Normative baseline: SPEC commit `d18357214fab30ea512ae9858a11699806d72ba1`,
blob `649548c58d6629dd85143b33efd3644a3bb71509`. Actual contract and stock
CometBFT pins remain those in the conformance manifests. A changed specification
or executable input requires a correspondence review before reusing evidence.

Every row below names a remaining obligation, its owning module, the acceptance
evidence, and its dependencies. **OPEN** is actionable verification work;
**ACTIVE** is selected in the current authorized batch; **WAITING** needs a
concrete implementation or measurement environment. **COMPLETE** retains a linked
closed selected obligation for traceability. A task leaves this list
only with linked scope, raw results, negative/progress controls and independent
review. A bounded subtask does not close its larger obligation. Cryptographic
assumptions and canonical-L1 finality are recorded premises, not promises to
prove a cryptosystem or Ethereum itself in TLC.

For each result, record model checking, actual implementation replay, and
deployment/measurement separately. A source mutation is detected only for the
intended named property/error with successful original and restored execution.
Setup failure, skipped work, empty output and timeout never count as a pass.
