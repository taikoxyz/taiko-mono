## Exact-artifact and default-coverage obligations

The instruction path really is bytecode decode → EVM X → EVM step → shared opcode semantics, with calls intercepted by EVM step. `EVM/Semantics.lean:84-97,435-436,496` and `EVM/Instr.lean:427-587` supply this path. Unknown opcode bytes are parsed as **INVALID** at`Instr.lean:587`; INVALID is rejected through δ=None (`Instr.lean:424`, `Semantics.lean:453-454`). Therefore the inventory's UNKNOWN_21 atPC12513 is **not evidence of a STOP-default bug or a land execution bug**. It is a code/data/reachability classification obligation; no land reachability proof was performed here. Out-of-bounds decode → STOP is a separate case.

Shared `Semantics.lean:570-572` still has generic default branches. EVM system operations are handled before that fallback; merely observing a fallback does not prove land reaches it. The actual proof must establish that every reachable operation/callee uses its intended semantic case, or supply and prove any missing case. Removing bytes or excluding failing paths without justification is unacceptable.

The inventory records immutable placeholders, storage layout and link references. It does not identify a specific deployed proxy, its runtime/code hash, EIP1967 implementation slot contents, constructor immutable values, or the actual verifier/SignalService account states. A proof over the template or over a fresh viaIR/Yul compilation cannot substitute for those identities. No deployment-address binding is fabricated in this note.

## Minimum concrete next plan

1. Preserve the exact solc settings/runtime hash. Bind the actual proxy runtime, implementation storage slot, implementation code hash, immutable values and external code/state identities. Extract the real land entry selector/CFG with a checked relation to these bytes, classifying embedded data and proving reachability rather than deleting opcodes. Record source/artifact digests at each mapping.
2. Prefer EVMYulLean's **bytecode EVM** path for the feasibility spike. A Clear or Yul-only route would first require substantial missing call/gas/modern-op semantics plus a proved compiler/bytecode bridge. Port only the inspected EVM dependency closure from its exact pin to Lean4.35.0-rc4/locked Mathlib, recording source changes; do not claim old oleans are compatible. Before any future build, pin or replace executable build extras: EVMYulLean `lakefile.lean:12-19` clones C hash repositories without immutable revisions. Separate these executable helpers from proof obligations.
3. Establish kernel meanings for the required hashing/crypto operations and relevant precompiles, or retain explicitly stated concrete input/output relations as visible assumptions without upgrading proof level. Do not use the `implemented_by` IO result as a theorem about its kernel default. Complete a small Osaka semantic coverage matrix for reachable instructions and nested callees, including gas exhaustion, cold/warm accesses, transient/static restrictions, revert data and account/substate rollback. Prove fuel sufficiency instead of identifying model OutOfFuel with EVM OOG.
4. Prove a simulation/refinement from the exact runtime/proxy/external execution to the Task5 LAND operation model. Prove the business-state journal/frame relation (including nested reentrancy guard and SignalService/verifier behavior); distinguish it from transaction nonce/fee effects. Only then reuse LAND theorems, run the transitive axiom/type audit and relevant execution conformance/mutation checks, and consider changing the ledger level.

## Honest boundary and unresolved uncertainty

**Solidity implementation-proved=pending.** This is independent Task8 preparation, allowed alongside the first-phase protocol proofs; it is neither an implementation proof nor an unsupported-semantics impossibility result. The EVM backend is meaningfully more complete than the Yul limitations suggest and is a feasible candidate for a dedicated stage.

Unresolved: actual land/callee reachability and code/data separation; precise deployed proxy/immutable/external identities; every applicable Osaka gas/precompile/fork rule and its correspondence to this library; attainable kernel crypto trust closure; Lean4.35 port/build effort and fuel bounds; full runtime-to-LAND simulation.
