# Paired CI acceptance and remaining release boundaries

The workflow is implemented for every PR (including Draft), main push, manual dispatch, schedule and release. Internal path detection covers formal sources, manifests/policies, tools, all client/protocol code/config, shared vectors and this workflow. `Etna formal gate` always aggregates actual job results. Related skipped/cancelled/failed/timed-out jobs fail. Unrelated changes emit the stable successful not-applicable check. Both dependency PR heads and the current verification event head are checked again at completion; a moved head requires a reviewed refresh and rerun.

The two dependency revisions are client base `2af0f30485b9990eae87074037bede11c59e8883` and protocol `27777e9d7147e7b1d3543711f4d7370a0377fa53`. The verification SHA is the current event head containing the new core/wrapper/proof overlay. Pair preparation retains the protocol's own immutable checkout and creates a digest ownership manifest over F/C/I plus protocol P and build context. Shared paths must have equal bytes. This avoids relabelling the upstream client base as the proved runtime revision.

## Event protocol ownership and adoption order

The only CI premerge exception is a PR/review whose base is exactly `feat/taiko-client-rs-abci` at the immutable client pin `2af0f30485b9990eae87074037bede11c59e8883`. Its event protocol projection must be byte/path/mode-identical to that client baseline. This explicitly permits the original stacked follow-up to test the separate protocol feature, while rejecting any unreviewed protocol/compiler/dependency edit in that follow-up. Local runs without GitHub event context use the same premerge comparison and label it as such; this fallback is forbidden inside GitHub Actions.

Main/push, schedule, release, manual dispatch and every other PR base use adopted ownership. The event protocol projection must exactly equal the tested pinned protocol projection; an event revision containing different contract, compiler or dependency inputs fails. Equality is computed from actual Git blob bytes, modes and paths, not commit presence/ancestry. A squash-equivalent tree passes even without either upstream revision as an ancestor. The projection includes all `packages/protocol`, shared Etna vectors, root package/pnpm manifests, Foundry/remapping configuration, npm/pnpm/tool/git attributes configuration and dependency patches. Reports distinguish the event projection, comparison revision/projection and separately tested protocol revision/projection. The current event SHA still identifies the actual client/formal overlay; neither dependency pin is a self-reference to that SHA.

Adoption order: merge the reviewed protocol feature (or a byte-equivalent squash), reconcile any other projected inputs through a deliberate reviewed pin/artifact refresh, then integrate the client/formal follow-up and validate the actual default-branch event projection. A changed adopted protocol cannot get green by reusing old pinned contract evidence; update the tested dependency pin, compiler/artifact provenance and reviewed obligations first. Enable the global required check only after the workflow exists on default and the hosted run passes. Manual dispatch requires an adopted-compatible projection; arbitrary premerge feature dispatch is deliberately unsupported. Initial premerge acceptance is through its declared stacked PR or explicitly labelled local validation.

## Execution and review

Independent Lean, extraction/Rust, paired-conformance and coverage jobs use fresh pinned sources and controlled compiler environments. Every Lean bootstrap builds the local Etna package after fetching Mathlib cache, so direct conformance consumers never rely on another runner’s oleans. Each individually selected receipt uses flat extraction (`merge-multiple: true`) in its own consumer directory. Changed-path detection disables rename detection so moving a proof outside watched paths still triggers both verification and proof review. Fresh production extraction compares the entire generated output file set and exact Lean/provenance bytes; it never normalizes unexplained Linux differences. LLBC and logs remain diagnostic artifacts. All 204 full-type/transitive-axiom checks and 17 actual extracted-function refinements remain mandatory. The coverage policy independently pins theorem contracts; coordinated `True` and `False -> goal` weakening is rejected. Statement/premise/policy/checker changes require an exact-head approval from another repository writer containing `Etna proof contract reviewed`. Updating a digest alone never supplies that approval.

Nightly executes three extra seeds, longer actual Prepare/Process/Finalize/Commit/reopen traces (12, 24 and 48 epochs, versus ordinary 3), all five FI mutants, all five committee mutants and four actual Solidity mutants. Domain jobs are isolated; mutation scripts restore production/generated/staging bytes in finally. Solidity permits only four closed exact pinned-source patches, preserves authentication of every other compilation input, requires an actual targeted assertion and restores canonical compiled artifacts. Baseline and restored runs retain 56 actual cases, 30 actual proxy preimages, 56 Rust statement rows, four cuts and 12 intervals.

The release job consumes this run's report for the exact release SHA and exact fixture/compiler artifact digest record. It fails while genuine guest soundness, execution header/time rules and exact Solidity bytecode/proxy refinement are pending. Spec/conformance green cannot satisfy these obligations.
