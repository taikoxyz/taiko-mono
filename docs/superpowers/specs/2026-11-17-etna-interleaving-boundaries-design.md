# Etna interleaving boundaries design

The user authorized another group under the established five-increment cadence
after accepting that discriminating checks improve later code correspondence.
This group strengthens finite model histories and independent observers. It
does not claim that missing client, EL, guest or corrective-upgrade interfaces
have become available, or that a green check proves whole-protocol correctness.

## Intent and approaches

The previous H group demonstrated that equal final scalar states can hide a
missing discarded suffix or missing first payment. The next group targets
dimensions that were separate or absent in previous bounds: a second recovery,
asymmetric node knowledge, two occupied staking slots, signer payload/salt/crash
composition and dynamic overlapping proof completion.

Root considered three approaches. Merely enlarging old exhaustive bounds risks
repeating archived inconclusive searches without identifying the missing
property. Immediate concrete runtime correspondence would need unavailable
interfaces and would move ahead of the user's intended later code comparison.
Root selects thin additive companions over unchanged original actions, with
complete raw histories and bounded reduced products where those add genuine
interleavings. This choice is delegated engineering judgment, not a separately
approved user mechanism. Its cost is that broader concrete acceptance remains
OPEN/WAITING and poorly chosen reductions would require rework.

## Components

J01 adds a two-recovery checkpoint-identity companion. It lands through an
intermediate generation's overlap, retains old public origins, then executes
and settles in generation2. The old identity configurations all stop at
MaxGeneration1 and cannot distinguish a recovered-generation hard-coded to1.

J02 adds two-node asymmetric finalized-generation knowledge. Both nodes first
serve an old authenticated view; only one observes recovery and revokes, while
the lagging node remains available. Subsequent refusals, sessions and mismatch
halts must preserve local knowledge and other-node state. This is modeled
service followed by containment, not invented generation1 restart liveness.

J03 targets a six-permutation two-slot registry lifecycle: pending-funded balances
affect minimum/tie admission, replacement identity survives later activation
and retirement, and withdrawal/history/custody observations remain independent.

J04 targets an eight-profile reduced signer product with two slots, Nil and two signature
salts, retries, crash/restart and delayed delivery. Signature records remain
symbolic; no concrete cryptographic keys or signatures are produced.

J05 targets a twelve-program product of dynamic two-job resource arrival and overlapping landing while
backend results remain incomplete, including suffix-only publication refusal,
same-block landings and actual block-end finality. Real prover/DA throughput
and resource fairness remain separate premises.

Task-specific exact bounds/programs/expected raw terminals and source faults
are frozen in the accompanying five-task implementation plan. Source/API
feasibility review precedes implementation; each task also receives an independent
literal-oracle readback before its first engine execution.

## Validation and remaining boundaries

For each task, require normal original-model invariants, complete positive raw
witnesses, discriminating actual-source faults with restoration, structural
missing-action controls and a different independently selected challenge.
Before/after each task and after tasks2/4, reconsider omitted valid inputs,
shared oracles, action suppression and overly strong premises. No finding quota.

The final gate freshly discovers/runs all default configurations and ordinary
Python suites, the new shared TLC obligations and mandatory controller checks.
Prepare its source snapshot with the complete packages/protocol/docs directory,
including external Derivation.md, rather than repeating H's incomplete-docs
preparation failure. Existing unchanged native/Forge obligations remain historical
unless separately rerun and explicitly attributed; inventory is not freshness.
Final nonauthor whole-batch source review and independent raw artifact audit
remain separate from CI success. Closing prose and post-hook hashes receive
their own narrow readback before normal draft-branch push and PR/issue readback.

R01/K02/P01/F01/Q01/Q02 and related full runtime obligations are not closed by a
bounded subtask. Authenticated L1, sound symbolic identities/proofs and atomic
original model actions remain premises. Moving-target import is not added:
there is no original target-replacement/generation2-install action to reuse.
The observed ability to detect selected injected defects cannot establish
coverage of all unknown protocol failures.
