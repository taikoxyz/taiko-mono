## Consensus compatibility

Heartbeat/FI semantics change consensus. Bump ABCI APP_VERSION from3 to4 and the committee-config domain from ETNA_PARENT_ANCHOR_V3 to ETNA_PARENT_ANCHOR_V4, retaining its eleven ABI words. This is a fresh-genesis configuration; older genesis/state/config must fail closed. Do not rewrite old signed journals, transactions or nonces. Envelope6, payload6, V10 statement, record encoding2 and reward V1 remain byte-structurally unchanged. Update both copies of independent vectors and all active pins/documentation; generated artifacts must reproduce.

## Seat retention

Derive base candidates from activation/exit interval and minimum stake. Deduplicate pubkeys by lowest eligible bond id. Rank by stake descending/set key ascending and take at most n_max seats. Only then apply the existing heartbeat rule (epochs0/1/2 exempt). Failed holders contribute no member or voting power, and no lower-ranked candidate fills their seat. Preserve set-key output ordering, floor formula, power/cap checks and empty-set halt. ABCI and lander share this pure derivation, which remains suitable for a future guest. Test n_max1 with a high-stake missing-heartbeat holder and lower valid-heartbeat candidate, partial holes, equal-stake boundaries, exemptions, roots/power and no fallthrough/backfill.

## Forced transaction fee eligibility

Add protocol constant FI_MIN_EXEC_FEE_CAP=1_000_000_000 wei, the current hard base-fee cap. Keep canonical decoding generic; inclusion at transaction0 remains possible for a canonical matching low-cap transaction. Before due, nothing may be skipped just for low cap. After due, with an authenticated exact preimage: malformed bytes OR canonical transaction with maxFeePerGas (gasPrice for legacy/type1) below the constant become directly skippable; canonical transactions at/above it require the existing successful empty singleton build. Do not classify RPC timeout/build error as skip. Use one pure classification shared by proposer, Process/Finalize and lander; future guest must use it. The threshold is a protocol constant, not a node-local flag. This change is genesis-only; later threshold upgrades must preserve the submission-time threshold for queued entries.

## Exact active stake for churn

Active means activeFromL1 <= current L1 block < exitEffectiveL1, independent of heartbeat/top-N. Keep the public bondedStake getter's existing meaning and R+7 position. Append two uint256 Fenwick trees at namespace R+13 and R+14, for activation and effective-exit amounts. A block b maps to uint256(b)+1 in a domain ending at2^64; updates visit at most65 nodes and each prefix query at most64. activeStake() is the current activation prefix minus exit prefix; no arbitrary historical API is offered.

Register computes its schedule using the current active sum before adding its own activation event. requestExit computes its schedule from current block+exitDelay using the pre-request active sum, then records the FINAL max(queued,activeFromL1+exitDelay) event; preserve the existing non-stranding queue order. A requested but not effective exit remains active. Both trees are maintained even when churn is disabled. After withdrawal gates pass, remove the matured activation and exit events before freeing the slot/transferring: both have entered every current/future prefix, so their net removal is zero and lifetime accounting remains bounded by outstanding bonds. Same-block zero-delay reuse must work. Existing Entry/Checkpoint encodings, node-facing namespace offsets, roots and withdrawal gates stay unchanged.

Use full-width unsigned amounts, checked uint256-to-uint64 coordinates and explicit no-exit sentinel handling; no silent int256/uint128 stake cap. activeStake returns0 at/after the max-u64 no-exit boundary. Reject reserved/unrepresentable scheduled coordinates atomically. Preserve mathematical churn scheduling while avoiding full-width intermediate overflow with mulDiv and remainder arithmetic where needed. Existing opened-window remaining capacity is not retroactively repriced; current active stake sets newly opened capacity. This is a new-genesis registry; append-only slots do NOT constitute a populated-proxy migration.

Use a naive entry-sum model independent of Fenwick in invariants, retain 256 runs/depth50 and near4096-slot coverage, and measure cold register/exit/withdraw/getter gas. Initial acceptance budgets: register/exit<3M, withdrawal<1.2M, getter<350K, subject to actual-token external calls. No unbounded sweep or keeper dependency.

## Latest-checkpoint trust and signing gate

Keep ordinary block validity deterministic. A process starts untrusted after startup/restart and authenticates the latest Inbox checkpoint at one pinned own-L1 finalized block using its header/state root and exact Inbox storage proof. Bind Inbox identity, generation, height and hash. Failure/unavailability never opens trust. Retry transient I/O without altering committed application state; malformed or contradictory authenticated facts halt safely.

Allow Info, InitChain and deterministic Finalize/Commit historical replay while behind the target. At the target height the replayed committed EL hash must match; a mismatch is a safety halt before trusting it. When persisted state is already beyond the target, prove ancestry by walking authenticated EL parentHash links from the stored committed head; an unrelated header_by_number result is insufficient. Refresh the finalized checkpoint before opening trust; if it moved ahead, continue catch-up. Trust is node-local and never enters app_hash, committee roots or block bytes. Once live, do not expire accepted proposals merely because finalized L1 advances. Expose explicit syncing/trust-ready/target fields, a null-or-trusted committed head and chain_id through the app status; raw Comet /status is not a substitute for this app trust signal. While untrusted, forkchoice must not mark the candidate head safe; retain an authenticated checkpoint/genesis safe/finalized boundary instead. Existing L1-authenticated checkpoints remain valid; the untrusted replay suffix must not be advertised as trusted consensus finality. Raw stock Comet/EL progress endpoints are not rewritten or claimed to be app trust signals, and operational readiness must consume the app signal.

ABCI-only rejection cannot stop stock Comet locked-block, retained-proposal or nil-vote signing. Add a small guarded external signer based on CometBFT v0.40.0's existing FilePV and SignerServer, not a new cryptographic or double-sign implementation. PubKey/Ping remain available during bootstrap. Every vote/proposal signing request must query the app directly over a permission-restricted local Unix control socket for bounded, current trust readiness bound to the configured/requested chain id and signer connection session; unavailable/malformed/untrusted/superseded/mismatched status denies without advancing FilePV signing state. Never cache an open decision across app restarts. Preserve existing FilePV key and anti-double-sign state; never synthesize missing state for an existing key. The actual consensus key must be supplied only to this signer; Comet uses priv_validator_laddr and cannot fall back to the same local FilePV.

The private control protocol supports BeginSession (close readiness immediately, allocate a new session id and request target reacquisition) and CheckSession (read-only readiness). Each successful Comet signer transport connection begins a new session before PubKey/Ping handling, so Comet-only restarts/reconnects rearm trust. The control socket has filesystem access restrictions and is not routed through public Comet ABCI Query; no public unauthenticated readiness-reset API is added. The app observes a session reset at a request boundary; publication uses a session-id check so an in-flight old verification cannot reopen a newer session. BeginSession does not wait for replay or L1 I/O. One signature whose fresh authorization read completed before a concurrent crash may finish; do not claim atomic cross-process revocation.

Package the helper and update normal validator startup/test-harness so the gate is exercised, not just an optional unused tool. Full nodes need no signing key. Prefer a small standalone Go tool module under packages/taiko-client-rs/tools/etna-signer, reusing the official Comet signer example and durable FilePV. Harness uses ephemeral test keys outside the Comet-mounted home, host signer subprocesses and scoped cleanup. Test historical catch-up for >=1/3 and single-validator voting power because Comet may switch early from block sync into consensus catch-up. No fork/reset/delete of Comet WAL/state, no trusted-target bypass flag and no signing through ProcessProposal-only checks.
